# T7.1 — Artist panels: regrouped render settings, the per-light ghost override, material and world panels, a panel-registry test
Milestone: M7 · Depends on: T5.4 (all of M4 and M5) · Parallel-safe: no

## Goal
After this card:
- The Render properties show five top-level Painterly panels in the order **Sampling, Brush, Lights, Path, Film**, one per
  SocketInfo group. Each draws its group's generated socket properties in socket order, with labels and tooltips taken
  only from the socket UI info (`ui_name`, `description`). Three default-closed subpanels hold the expert controls:
  Sampling > Performance, Brush > Advanced, Path > Advanced.
- Every socket has an artist-readable `ui_name` and `description` (table below), written once in the core's UI info. The
  jitter description carries the two cautions that experiment 006 (Decision 2) requires.
- A property that the render currently ignores is greyed out (`active = False`), by exact rules from SPEC §1, §3, §8 and
  T4.3's `apply_reference_knobs()`. Nothing is hidden, so every property is always drawn exactly once.
- The Light properties show a Painterly **Light** panel that draws exactly the light inputs T5.3 reads, plus the per-light
  override `light.painterly.ghost` for point and spot lights. T5.3 honours it as
  `settings.ghost_lights and light.painterly.ghost`. The built-in `DATA_PT_light`, which draws only the light type for
  engines that join through `BLENDER_RENDER`, is excluded from `get_panels()`, as Cycles excludes it.
- The Material and World properties show what Painterly reads: a material-slot panel and a **Surface** node view for
  materials, and a **Surface** node view for the world. Without them, the Material tab has no slot list and no surface
  panel for PAINTERLY, because Blender's own panels are EEVEE-only.
- A panel-registry dump runs inside `blender -b` against the installed extension, and also against the `bpy` module. It is
  checked by one shared, deterministic checker.

**No `material.painterly` or `world.painterly` property groups exist after M5, and this card creates none.** SPEC §6 and §8
define no per-material or per-world knob. The plan's M7 row mentions a "painterly emission" override, but the SPEC does not
define one, so it needs an Opus SPEC decision first ("Not in this card").

## Interface

### Panels (bl_idname = class name; `bl_space_type = "PROPERTIES"`, `bl_region_type = "WINDOW"`, `COMPAT_ENGINES = {"PAINTERLY"}`)
| bl_idname | bl_label | bl_context | bl_parent_id | bl_options | bl_order | draws |
|---|---|---|---|---|---|---|
| `RENDER_PT_painterly_sampling` | Sampling | render | – | – | 0 | Sampling sockets, then `reference_scene`; header: the presets popover |
| `RENDER_PT_painterly_sampling_performance` | Performance | render | `RENDER_PT_painterly_sampling` | DEFAULT_CLOSED | – | `threads`, `batch` |
| `RENDER_PT_painterly_brush` | Brush | render | – | – | 1 | Brush sockets except Advanced, then `spiral_object` |
| `RENDER_PT_painterly_brush_advanced` | Advanced | render | `RENDER_PT_painterly_brush` | DEFAULT_CLOSED | – | `u2_mode`, `k0_phase_lock_bits` |
| `RENDER_PT_painterly_lights` | Lights | render | – | – | 2 | Lights sockets, then `area_light_segments` |
| `RENDER_PT_painterly_path` | Path | render | – | – | 3 | Path sockets except Advanced |
| `RENDER_PT_painterly_path_advanced` | Advanced | render | `RENDER_PT_painterly_path` | DEFAULT_CLOSED | – | `ray_epsilon`, `two_sided` |
| `RENDER_PT_painterly_film` | Film | render | – | – | 4 | Film sockets, then the `PAINTERLY_OT_apply_display_settings` button |
| `PAINTERLY_LIGHT_PT_light` | Light | data | – | – | – | the light inputs T5.3 reads, and `light.painterly.ghost` |
| `PAINTERLY_LIGHT_PT_beam_shape` | Beam Shape | data | `PAINTERLY_LIGHT_PT_light` | – | – | `spot_size`, `spot_blend`, `show_cone` (spot only) |
| `PAINTERLY_MATERIAL_PT_context_material` | "" | material | – | HIDE_HEADER | – | slot list and material selector (Cycles' panel) |
| `PAINTERLY_MATERIAL_PT_surface` | Surface | material | – | – | – | node view of the Surface input |
| `PAINTERLY_WORLD_PT_surface` | Surface | world | – | – | – | node view of the Surface input |

- The five top-level `bl_order` values are `GROUP_ORDER.index(group)`: ranks in the display order, below the 10 and 100 of the
  built-in render panels, so Painterly's panels come first. "–" means the attribute is not set (Blender's default).
- `get_panels()` exclude set: `RENDER_PT_simplify` (T4.2), plus `DATA_PT_light`, `DATA_PT_spot` and `DATA_PT_preview`, each
  with its one-line reason from "Read first" as a comment.

Activity rules (the only conditions; everything else is always active, enabled and not alert):
- `property_active(settings, name)` is False iff `settings.reference_scene` and `name in REFERENCE_KNOBS` (T4.3 pins it),
  or `name in ACTIVE_WHEN` and `effective_value(settings, controlling socket)` is not in the used values.
- `RENDER_PT_painterly_lights` sets its whole layout inactive iff `settings.reference_scene`: in reference mode the scene is
  built by `build_smallpaint_scene`, and no Blender light is synced (T4.3).
- `property_alert(settings, name)` is True iff `name == "spiral_object"`, `effective_value(settings, "spiral_frame") == "object"`
  and `settings.spiral_object is None`. That is the configuration T5.1 refuses to render.
- The light panel's ghost row is active iff `settings.ghost_lights and not settings.reference_scene`, with
  `settings = context.scene.painterly`.

Rule for later cards:
- A new socket needs no UI change. It lands in its group's main panel, and the checks cover it.
- A new activity rule goes into `ACTIVE_WHEN` and into `panel_registry.expected_active`.
- A new hand-written property goes into `HAND_WRITTEN_PANEL`. Until it does, the "drawn exactly once" check fails.
- A new panel goes into `panel_registry.EXPECTED_PANELS`.
