# T6.4 — Vendored shader graph and constant folding, the core shader nodes from fragments, and `cycles_scene`
Milestone: M6a · Depends on: T2.11, T3.1, T3.2, T3.3, T6.1, T6.2, T6.3 · Parallel-safe: no

## Goal
After this card:
- Cycles' host-side shader graph compiles from verbatim upstream text in the `painterly` namespace, as a static library
  `cycles_scene`:
  - whole files: `scene/shader_graph.{h,cpp}`, `scene/constant_fold.{h,cpp}`, `scene/shader_nodes.h`, `scene/svm.h`, plus
    the headers they need: 11 files that this card vendors, beside 3 kernel headers that T6.3 vendored ("Vendored files");
  - fragments (T6.2) of `scene/shader_nodes.cpp`: the **core node set**, the 15 node classes that vendored code creates or
    names, each with all of its out-of-line members;
  - fragments of `scene/svm.cpp`: the `SVMCompiler` stack, input/output and emit members (`svm.cpp:172-550`), which the
    node `compile(SVMCompiler &)` bodies call.
- Five shims, `src/cycles/shim/scene/{scene,shader,attribute,image,osl}.h`, plus `scene/{attribute,shader}.cpp`, provide
  exactly the members that this vendored code uses.
- `tools/gen_fragment_units.py` assembles one translation unit per fragmented upstream file, from the manifest
  `src/cycles/fragment_units.toml` and the `[[fragment]]` entries of `third_party/cycles/VENDORED.toml`. It also generates
  the node type registry `painterly_cycles_shader_node_types()`, which references every `X::get_node_type()`, so that no
  `NODE_DEFINE` registration is lost in the static library.
- Doctests create nodes by Cycles type name, set sockets by name, connect them, and simplify and constant-fold small graphs,
  e.g. Value 2 + Math 3 folded into an Emission strength of exactly 5.

Nothing in the painterly engine uses `cycles_scene` yet. T6.5 compiles graphs to SVM byte code; M6b wires both into
`PainterlyScene` and the Blender sync.

## Decisions (Opus, 2026-10-09)
1. **Core node set, and the `SVMCompiler` members that link it.** Vendored code creates or names 13 node classes:
   `OutputNode` (`shader_graph.cpp:225`), `EmissionNode` and `ConvertNode` (`connect`, `:272, 286`), `ColorNode` (`:584`),
   `TextureCoordinateNode`, `GeometryNode`, `VectorTransformNode` (`default_inputs`, `:880-904`), `BumpNode`, `SetNormalNode`,
   `VectorMathNode` (`bump_from_displacement`, `:1031-1080`), `MixClosureWeightNode`, `MathNode` (`transform_multi_closure`,
   `:1117, 1159`) and `AttributeNode` (`:703, 728`). `MathNode::expand` creates `ClampNode` (`shader_nodes.cpp:6929`), and the
   doctests use `ValueNode`. These 15 classes are the core set. (`OSLNode` is only named, `shader_graph.cpp:793`; it needs no
   definition.)
   - Each class needs **all** its out-of-line members. `SHADER_NODE_CLASS` declares `compile(SVMCompiler &)` as the first
     non-inline virtual function, so the vtable is emitted with it. Without that body, `create_node<X>()` does not link.
   - The `compile(SVMCompiler &)` bodies call `SVMCompiler`. So this card also vendors `scene/svm.h` and extracts the
     contiguous `SVMCompiler` members `svm.cpp:172-550` (stack, inputs/outputs, `add_node`, `add_value_node`, `attribute`).
     That is their link closure: compiled to objects, the core set plus these members leave undefined only symbols that
     T3.2 and T3.3 define.
   - The rest of `SVMCompiler`, its constructor (`svm.cpp:157-170`) and the graph compiler (`:552-1279`), is left to T6.5
     ("What this card leaves to later cards").
2. **The bare token `ccl`.** Upstream names its namespace with the `CCL_NAMESPACE_*` macros and, once in this card's files,
   with the bare token: `scene/shader_nodes.h:992` (`ccl::BsdfBaseNode::get_feature()`). T3.2 maps the macros to
   `painterly`. `cycles_scene` adds the PUBLIC compile definition `ccl=painterly`, so that token means `painterly` too.
   - No patch is needed. No symbol is emitted under `ccl::`.
   - Upstream defines the namespace only on the compiler command line (`intern/cycles/CMakeLists.txt:208-209`). The token
     `ccl` appears in no system or doctest header.
3. **Socket naming** (the contract for M6b's Python export; see "Interface"). Linkable sockets are found by UI name,
   parameters by member name.
4. **One generated translation unit per fragmented upstream file.** It holds every fragment of that file, in upstream order,
   so fragments keep upstream's definition order (macros and `static` helpers before their users). Its static
   initializers, which include `ConvertNode::register_on_init`, are linked whenever the registry function, which it
   defines, is referenced. A node port adds fragments and, if its code needs a further header, one `includes` entry.
5. **Build-glue headers of the `cycles_*` libraries live in `src/cycles/`.** `src/cycles/` may hold headers that belong to
   the build of a `cycles_*` library without shadowing an upstream path, included as `"cycles/<name>.h"` through the `src`
   include directory. Upstream has no `cycles/` directory (and `third_party/cycles/cycles/` does not exist), so such a header
   can never shadow an upstream path. The first is `src/cycles/shader_node_registry.h`: its function is defined in a
   generated `cycles_scene` unit, so putting it under `src/painterly/` would make vendored code include a painterly layer.
   Its function keeps the `painterly_` prefix (`docs/architecture.md`, "Source layout and naming").
   - `docs/architecture.md` does not list this location yet. A later docs card adds it; this card does not touch `docs/`.
6. **`NOMINMAX` on Windows comes from T2.11; this card adds none.** The `util/thread.h` shim includes `<windows.h>` on
   Windows (through vendored `util/windows.h`), and without `NOMINMAX` it defines `min` and `max` as macros. These would
   break vendored `util/simd.h:110` (`std::numeric_limits<int>::min()`) and `util/math_base.h:124`
   (`int max(const int a, const int b)`), which `scene/shader_graph.cpp`, the generated units and the doctest include after
   it. Blender defines `NOMINMAX` for every Windows source (v5.2.2 `build_files/cmake/platform/platform_win32.cmake:133-142`,
   `add_definitions(… -DWIN32_LEAN_AND_MEAN -DNOMINMAX)`; the file is not in the T3.1 checkout).
   - T2.11 restored it as `if(WIN32)` `target_compile_definitions(cycles_util PUBLIC NOMINMAX)` `endif()` in
     `src/cycles/CMakeLists.txt`. `cycles_scene` links `cycles_graph`, which links `cycles_util`, so every `cycles_scene`
     source and every consumer of `cycles_scene` gets it.
   - A second copy in this card's block would duplicate T2.11's on merge. Step 2 checks that the branch has T2.11's line;
     without it, stop.
   - The `windows` job of `ci.yml` (T2.10, T2.11) and the Windows wheel build compile this card's code with MSVC on the
     next push of the M6a branch. Those results are not part of this card's acceptance.

### `tools/gen_fragment_units.py`
`gen_fragment_units.py --manifest PATH --vendored PATH --unit NAME (--output PATH | --check PATH)`
- Reads the manifest and the `[[fragment]]` entries of `--vendored` whose `upstream` is `"cycles"` and whose
  `upstream_path` is the unit's. Fragment files are `<directory of --vendored>/fragments/<name>.inc`. Before using a file,
  it checks the file's sha256 against its entry.
- `--output` writes the result as bytes and creates missing parent directories. `--check` compares the result with an
  existing file, byte for byte; it never writes.
- Exit status:
  - 0 on success;
  - 1, with `gen_fragment_units: <message>` on stderr, when:
    - the manifest breaks a rule above, or the unit is unknown;
    - the unit has no fragment;
    - a fragment file is missing or its sha256 differs (the message contains `sha256`);
    - `node_registry` is true but the unit has no `node_define` fragment;
    - `--check` names a file that does not exist, or finds a difference.
- Read and write files as bytes. Decode the TOML files as UTF-8.
- Python API, which the tests use: `class GenError(Exception)`, `generate(manifest: Path, vendored: Path, unit: str) -> str`
  (raises `GenError`) and `main(argv: list[str] | None = None) -> int`.
- The CLI runs only under `if __name__ == "__main__":` `sys.exit(main())`. Importing the module runs nothing, because
  `tests/core/test_gen_fragment_units.py` loads it with `importlib`; test 5 also runs it as a script.

The output is exactly the concatenation of:
1. the header below, with `<upstream_path>` replaced by the unit's; it ends with a newline;
2. `"\n"`;
3. for each entry of `includes`, in manifest order: `#include <x>` if it starts with `<`, else `#include "x"`, then `"\n"`;
4. if `node_registry` is true: `'#include "cycles/shader_node_registry.h"\n'`;
5. `"\nCCL_NAMESPACE_BEGIN\n\n"`;
6. for each fragment, in increasing `upstream_lines[0]`: `/* <upstream_path>:<first>-<last> */` and `"\n"`, then the
   fragment's text, then `"\n"`. `first` and `last` come from `upstream_lines`. The order of the entries in `VENDORED.toml`
   does not matter;

### Socket naming (contract for T6.5 and M6b)
Cycles has two name spaces for sockets, and each operation uses one of them:

| What | Name | API | Example |
|---|---|---|---|
| node type | Cycles type name (`NodeType::name`) | `graph->create_node(NodeType::find(ustring(name)))` | `"math"`, `"emission"`, `"convert_float_to_color"` |
| linkable input or output: link it, or set an unlinked input's value | UI name (`SocketType::ui_name`) | `ShaderNode::input(name)`, `ShaderNode::output(name)` (`shader_graph.cpp:93-135`), `ShaderGraph::connect`, `ShaderInput::set` | MathNode `"Value1"`, output `"Value"`; Emission `"Strength"` |
| parameter (a socket without `IN`/`OUT` in its macro: `SOCKET_ENUM`, `SOCKET_BOOLEAN`, `SOCKET_FLOAT`, …) | member name (`SocketType::name`) | `node->type->find_input(ustring(name))` (`graph/node_type.cpp:186-196`), then `Node::set(socket, value)`; an enum by its `NodeEnum` name | MathNode `"math_type"` = `"multiply"`, `"use_clamp"`; ValueNode `"value"`; ColorNode `"value"` |

- A parameter has no `ShaderInput`, so `input("Type")` is `nullptr`. `find_input` never matches a UI name.
- Blender's own sync matches `socket.identifier` (after its renames) to the UI name (`blender/shader.cpp:1212-1323`,
  `node_find_input_by_name`/`node_find_output_by_name`), and sets parameters with typed setters in `add_node` (e.g.
  `set_math_type`, `blender/shader.cpp:540, 546`). M6b's Python export sends UI names for links and linkable defaults, and
  member names, with enum names, for parameters.
