## Goal
After this card:
- `tools/vendor_sync.py` vendors **fragments**: verbatim extracts of the upstream files that M6a does not vendor whole
  (`scene/shader_nodes.cpp`, `scene/svm.cpp`, and the `SVM_CASE` blocks of `kernel/svm/svm.h`; M6a design, Opus decision
  2026-10-09).
  - An *anchor* locates each fragment: a `NODE_DEFINE`, a member function, a free function, a macro, an `SVM_CASE` block, or
    an exact-text span. Line numbers are recorded but never used to find code.
  - Each fragment is a `[[fragment]]` entry in `third_party/cycles/VENDORED.toml` with its sha256. `sync` writes it to
    `third_party/cycles/fragments/<name>.inc`, and `check` verifies it as it verifies vendored files.
- `tools/gen_svm_switch.py` builds Cycles' `svm_eval_nodes()` from fragments alone. The upstream frame (signature, loop,
  `default:`) surrounds the `SVM_CASE` blocks of the nodes listed in the new manifest `src/cycles/svm_nodes.toml`. Its
  output is deterministic.
- The manifest lists the four control-flow cases `NODE_END`, `NODE_SHADER_JUMP`, `NODE_JUMP_IF_ZERO` and
  `NODE_JUMP_IF_ONE`. Their fragments and the three frame spans are committed.
- Later cards port a node by adding fragments (`add-fragment`) and manifest entries only. Nothing in this card compiles
  C++: T6.3 compiles the generated header into `cycles_svm`.

## Interface

### Changes to T3.1's code
Every later `sync`, `add` and `remove` rewrites `VENDORED.toml` through `render_manifest` (T6.3 and later cards run `add`
after this card). These changes make all three keep every `[[fragment]]` entry byte for byte.
- `class FragmentError(VendorError)`. The fragment code raises only `FragmentError`: when a T3.1 helper it calls
  (`load_manifest`, `_rel_path`, `check_structure`, …) raises `VendorError`, it re-raises it as `FragmentError` with the
  same message. T3.1's handler in `main` reports both as `vendor_sync: error: <message>` on stderr and returns 1. Dispatch
  the new subcommands inside its `try`.
- `Manifest` gains a third field, `fragments: list[dict[str, object]]`: the `[[fragment]]` tables in file order, each the
  dict that `tomllib` reads. It has no default, so every `Manifest(...)` call must pass it:
  - `load_manifest` passes `data.get("fragment", [])`;
  - `sync_manifest` (its `result`), `cmd_add` and `cmd_remove` pass `manifest.fragments` through unchanged.
- `check_structure` also enforces rules 1-3 ("`[[fragment]]` entries") and raises `FragmentError` at the first violation.
  `load_manifest` and `sync_manifest` already call it. So `add` refuses a `[[file]]` whose (`upstream`, `upstream_path`) a
  fragment uses (rule 3) before it writes anything.
- After the `[[file]]` tables, `render_manifest` emits one block per fragment, in list order: a blank line,
  `[[fragment]]`, then one `key = value` line for each key the entry has, in the order of `FRAGMENT_KEYS`.
  - String values are written by T3.1's `_toml`. `upstream_lines` is written as `[FIRST, LAST]`, e.g.
    `upstream_lines = [118, 119]`.
  - `MANIFEST_HEADER` stays unchanged.
- `add_fragments` and `remove_fragments` write `VENDORED.toml` only as `render_manifest(...)` encoded as UTF-8. So one
  serializer writes every byte of the file, and nothing appends to it.
- `offline_problems` skips files whose first path component is `fragments`, as it skips `patches/`. `check_fragments`
  reports unlisted files under `fragments/` instead.

### Lexing (shared by every anchor kind)
Read the upstream file as bytes and decode it as UTF-8. A `\r` anywhere is an error. The lines are the pieces of
`text.split("\n")`, without the empty piece after the final `\n`. Do not use `str.splitlines()`, which also splits on other
characters. Lines are numbered from 1. For each line:
- **preprocessor**: outside a block comment, its first non-blank character is `#`; or the previous line is a preprocessor
  line that ends in `\`. The first line of such a run is a **directive line**. Preprocessor lines are not lexed further.
- **code**: empty for preprocessor lines. Otherwise, the line with each of these constructs replaced by one space:
  - a block comment `/* … */`, which may span lines;
  - a line comment `// …`;
  - a string literal `"…"` or a character literal `'…'`, where a backslash escapes the next character. A literal that does
    not close on its line is an error.

  Find the constructs in one left-to-right scan of each non-preprocessor line, carrying the in-block-comment state
  across lines. At each position, the first of `/*`, `//`, `"` and `'` opens its construct. Inside a literal, `//` and
  `/*` are ordinary characters; inside a comment, quotes are ordinary characters. Each construct, or its part on this
  line, becomes one space. Never replace literals and comments in separate passes: upstream comments contain apostrophes
  (`svm.h:11` "uint4's", `shader_nodes.cpp:322` "there's"), and a literals-first pass reports them as unterminated.
- **depth**: the number of `{` minus the number of `}` in the code of all earlier lines. The depth *after* line n is the
  depth of line n + 1, or the count over all lines when n is the last line.
- **open conditionals**: the number of earlier directive lines matching `#\s*(if|ifdef|ifndef)\b` (after leading blanks),
  minus those matching `#\s*endif\b`. "After line n" means at the start of line n + 1, or at the end of the file.
- **top-level**: depth 0, not preprocessor, not starting inside a block comment, not empty, and its first character is not
  a space or a tab.
- **declarator** of a top-level line: group 1 of the first match, in its code, of
  `(~?[A-Za-z_][A-Za-z0-9_]*(?:::~?[A-Za-z_][A-Za-z0-9_]*)*)\s*(\(|=(?!=))`. A line whose text, without trailing blanks, is
  `NODE_DEFINE(<identifier>)` has no declarator.
- **parameter text** of a declarator followed by `(`: the code between that `(` and its matching `)`, which may span lines
  (a line break counts as a space). Every whitespace run becomes one space, and the ends are stripped. Comments are already
  spaces, so `void BsdfNode::compile(SVMCompiler & /*compiler*/)` has the parameter text `SVMCompiler &`. A declarator
  followed by `=` has no parameter text.

**Definition extent** from a header line h. Scan the code from the start of line h, counting parentheses and braces.
- The first `{` met at parenthesis depth 0 and brace depth 0 opens the body. The extent ends at the line where the brace
  depth returns to 0 after that.
- If a `;` comes at parenthesis depth 0 and brace depth 0 before any body opens, the extent ends at that line. Examples:
  `TextureMapping::TextureMapping() = default;` (`shader_nodes.cpp:79`), and
  `bool ConvertNode::register_on_init = NodeType::register_on_init([] { … });` (`:1974-1977`), whose `{` is inside
  parentheses.
- The extent starts at h, or at h − 1 when line h − 1 is top-level and its code starts with `template`.

### Anchor kinds
| `kind` | anchor | header | extent |
|---|---|---|---|
| `svm_case` | `NODE_X` | the non-preprocessor line whose stripped text is `SVM_CASE(NODE_X)` | "`svm_case` extent" below |
| `node_define` | class name `X` | the top-level line `NODE_DEFINE(X)` (trailing blanks ignored) | definition extent |
| `member` | qualified name: `X::f`, `X::X`, `X::~X`, `A::B::f` | top-level lines whose declarator equals the anchor | definition extent |
| `function` | unqualified name `f` | top-level lines whose declarator equals the anchor | definition extent |
| `define` | macro name `M` | the directive line at depth 0 that matches `#\s*define\s+M\b` after leading blanks | through the first line that does not end in `\` |
| `span` | none; `id`, `begin`, `end` instead | the line whose whole text equals `begin` | through the first line, at or after the header, whose whole text equals `end` |

- `svm_case`, `node_define`, `define` and `span` need exactly one header. Zero or several is an error.
- **`svm_case` extent.** Let d be the header's depth. The extent ends at the line before the first later line that either
  - has depth < d, or
  - has depth d and is a non-preprocessor line whose stripped text starts with `SVM_CASE(` or `default:`, or
  - has depth d and is a directive line `#if`, `#ifdef`, `#ifndef`, `#elif`, `#else` or `#endif`.

  Trailing blank lines are dropped. Let h be the header and e the last line left. The case must then end in one of two
  forms. Anything else is an error ("falls through"): the generator omits the unlisted cases, so a fall-through would
  run whichever listed case follows.
  - Line e, stripped, is `break;` or `return;`.
  - The `NODE_SHADER_JUMP` form (`svm.h:120-136`), where all four hold:
    - line h + 1, stripped, is `{`;
    - every line from h + 2 to e has depth ≥ d + 1, so that this `{` stays open through line e;
    - line e, stripped, is `}`, and the depth after line e is d, so line e closes the `{` of line h + 1;
    - line e − 1, stripped, is `break;` or `return;`.

    `SVM_CASE(NODE_X)` / `if (c) {` / `return;` / `}` is refused: line h + 1 is not `{`, and it falls through when c is
    false.

  **Wrapped case.** After that check, if line h − 1 is a directive line that matches `#\s*(if|ifdef|ifndef)\b` after
  leading blanks, and line e + 1 is a directive line at depth d that matches `#\s*endif\b` after leading blanks, the
  extent becomes h − 1 to e + 1. The case is then the only content of its conditional, and the fragment keeps both
  directive lines. This is the form of `NODE_HAIR_INFO` (`svm.h:406-410`) and `NODE_POINT_INFO` (`:411-415`). The M6a
  design excludes only the `__SHADER_RAYTRACE__` cases, and T6.1 defines `__HAIR__` and `__POINTCLOUD__` as upstream
  CPU builds do, so a later card ports either node by adding a manifest entry alone.
- **`member` and `function` selection.** Without `params`, exactly one header must carry the declarator. With `params`:
  - if any candidate's parameter text equals `params`, exactly one must, and it is chosen;
  - otherwise `params` must be non-empty, and exactly one candidate's parameter text must start with `params`, followed by
    its end or by a character outside `[A-Za-z0-9_]`;
  - a candidate without parameter text (declarator followed by `=`) never matches `params`.

  Checked on upstream: `MathNode::compile` with `SVMCompiler` selects `shader_nodes.cpp:6970-6981`. `BsdfNode::compile`
  with `SVMCompiler` is ambiguous (`:2184` has `SVMCompiler &`, and the template at `:2189` has
  `SVMCompiler &compiler, const T &data`); with `SVMCompiler &` it selects `:2184-2187`.
  `ScatterVolumeNode::ScatterVolumeNode` with the empty `params` selects `:3387-3390`.
  - Convention for later cards: pass the shortest `params` that selects the definition. For node bodies that is
    `SVMCompiler` or `OSLCompiler`; for `BsdfNode::compile` it is `SVMCompiler &`.
- **Conditionals.** For every kind, the open-conditional count must be 0 both at the extent's first line and after its last
  line. Otherwise the error says the anchor "lies inside a preprocessor conditional".
  - This refuses the `__SHADER_RAYTRACE__` cases `NODE_BEVEL`, `NODE_AMBIENT_OCCLUSION` and `NODE_RAYCAST`
    (`svm.h:566-581`). The three share one conditional, so none of them is a wrapped case, and no generated switch can
    contain them, as the M6a design requires. The wrapped cases `NODE_HAIR_INFO` and `NODE_POINT_INFO` pass: their
    extents start and end outside the conditional.
  - Conditionals wholly inside an extent are kept: `NODE_ATTR` (`svm.h:242-252`), `ImageTextureNode::attributes`
    (`shader_nodes.cpp:383-396`).
- **Fragment text**: the extent's lines, each followed by `\n`, as UTF-8 bytes. `sha256` is computed over these bytes, and
  the `.inc` file holds exactly them.
- Every failure raises `FragmentError`, with a message that names the anchor. For an ambiguous or unmatched member or
  function, the message lists each candidate's parameter text and header line.
- Not covered: top-level `struct` and `class` definitions. Upstream's only one in these files is `struct SunSky`
  (`shader_nodes.cpp:683-690`), used by the sky texture, which is outside M6a.
- Lex each source once per command. `list-anchors` resolves several hundred anchors in `shader_nodes.cpp`.

### Names and files
- `name` is `<upstream_path with every "." replaced by "_">/<kind>/<id>`, where `<id>` is:
  - for `svm_case`, `node_define`, `define` and `function`: the anchor;
  - for `member`: the anchor with each `::` replaced by `.`;
  - for `member` and `function` selected with `params`: the above, then `-`, then `params` with every run of characters
    outside `[A-Za-z0-9_]` replaced by `_` and leading and trailing `_` stripped, or `void` if nothing is left;
  - for `span`: the `id`.
- Valid anchors: `[A-Za-z_][A-Za-z0-9_]*` for `svm_case`, `node_define`, `define` and `function`;
  `[A-Za-z_][A-Za-z0-9_]*(::~?[A-Za-z_][A-Za-z0-9_]*)+` for `member`. Valid ids: `[A-Za-z0-9_]+`.
- The file is `third_party/cycles/fragments/<name>.inc`. C++ includes it as `#include "fragments/<name>.inc"` through the
  `third_party/cycles` include directory.
  - The repository-relative path `third_party/cycles/fragments/<name>.inc` has at most `FRAGMENT_PATH_MAX` (190)
    characters. Otherwise `fragment_name` raises `FragmentError`, naming the path, its length and the limit 190, and
    saying to pass a shorter `--params` or `--id`. Example: the full parameter text of `sky_texture_precompute_nishita`
    (`shader_nodes.cpp:805-815`) gives a 345-character path.
    - The limit is the one the project depends on: CI checks out and compiles these files on Windows, under the
      69-character `WINDOWS_CI_CHECKOUT_ROOT`, and a full path must stay within Win32's `MAX_PATH`.
    - It also bounds every `/`-separated component to 190 characters, within the file-name limits of ext4 and APFS
      (255 bytes) and NTFS (255 characters), so no separate component limit exists.
  - No `.h` path ever exists under `fragments/` (the `.` of the upstream file name becomes `_`), so a fragment directory can
    never shadow an upstream header (T6.1, "Shim markers").

### `[[fragment]]` entries in `third_party/cycles/VENDORED.toml`
```toml
[[fragment]]
name = "kernel/svm/svm_h/svm_case/NODE_END"
upstream = "cycles"
upstream_path = "kernel/svm/svm.h"
kind = "svm_case"
anchor = "NODE_END"
upstream_lines = [118, 119]
sha256 = "6333d42a50d11a297ac5a91d999a44962a2101b5a94c328311be26620a6804aa"
```
- Keys come in the order of `FRAGMENT_KEYS`.
  - Every kind except `span` has `anchor`. A `member` or `function` selected with `params` has `params` right after
    `anchor`.
  - A `span` has `id`, `begin` and `end` after `kind`, instead of `anchor`.
- `upstream_lines` is `[first, last]`, 1-based and inclusive, in the unpatched upstream file. `patches/` never applies to
  fragments.
- `render_manifest` writes every entry ("Changes to T3.1's code"). `add-fragment` appends its entries after the existing
  `[[fragment]]` entries and re-renders the file. `tomllib` reads `[[file]]` and `[[fragment]]` tables in any
  interleaving, and `render_manifest` always writes the `[[file]]` tables first.
- Rules. `check_structure` enforces them, so every command that loads or writes the manifest does: `add-fragment` before
  it writes anything, `add`, `remove` and `sync` through `sync_manifest`, and `check` on the whole file.
  1. Each entry has:
     - a known `kind`, and exactly the keys above for it;
     - an `upstream` that has an `[upstream.<name>]` table, and an `upstream_path` that T3.1's `_rel_path` accepts;
     - a valid anchor (with `params` a string, if present) or a valid id;
     - `upstream_lines`: two integers, not booleans, with 1 ≤ first ≤ last;
     - a `sha256` of 64 lowercase hex digits;
     - string values made only of printable ASCII characters (U+0020-U+007E). `_toml` writes JSON escapes, and it would
       write a character outside the Basic Multilingual Plane as a surrogate pair, which TOML 1.0 and `tomllib` reject.
       `kernel/svm/svm.h`, `scene/shader_nodes.cpp` and `scene/svm.cpp` contain no byte outside printable ASCII except
       `\n`, so no anchor needs more;
     - a `name` equal to `fragment_name(...)` of its fields, which also bounds the length of its file's path ("Names and
       files").

     Names are unique.
  2. Fragments of one upstream file never overlap: their `upstream_lines` ranges are disjoint. Code included twice would be
     defined twice.
  3. A file is vendored whole or fragmented, never both: no fragment's (`upstream`, `upstream_path`) is a `[[file]]`
     entry's (`upstream`, `upstream_path`).

### `tools/vendor_sync.py` subcommands
`--upstream NAME` defaults to `cycles`. The source is `<checkout>/<root>/UPSTREAM_PATH` in the checkout that `fetch`
creates for NAME. The CLI passes its `checkouts` (upstream name → checkout directory, the repository root) to the Python
API:
- `add-fragment`, `extract` and `list-anchors` map every upstream of the manifest to T3.1's `checkout_dir(upstream)`. A
  missing checkout is a `FragmentError` that says to run `tools/vendor_sync.py fetch`. These commands never fetch, and
  they print nothing on stderr except what is specified below.
- `sync` and `check --upstream` map each upstream that a `[[fragment]]` entry uses to T3.1's
  `ensure_checkout(upstream)`, which fetches an absent checkout, as T3.1's own `sync` and `check --upstream` do. So both
  still work on a fresh clone. A `VendorError` from `ensure_checkout` reaches `main`'s handler unchanged.
- `add-fragment [--upstream NAME] UPSTREAM_PATH KIND [ANCHOR ...] [--params TEXT] [--id ID --begin TEXT --end TEXT]`
  - Extracts every ANCHOR, appends one entry per ANCHOR in command-line order after the existing `[[fragment]]` entries,
    re-renders `VENDORED.toml`, writes their `.inc` files and prints their names, one per line.
  - All or nothing: every name, extraction and rule is checked first; on any error, nothing is written.
  - `span` takes no ANCHOR and needs `--id`, `--begin` and `--end`. The other kinds need at least one ANCHOR and refuse
    `--id`, `--begin` and `--end`.
  - `--params` is only for `member` and `function`, and applies to every ANCHOR. `--params ''` is given and empty.
- `remove-fragment NAME...`: deletes these entries (re-rendering `VENDORED.toml`), their `.inc` files, and the
  directories under `fragments/` left empty. An unknown name is an error and changes nothing.
- `extract [--upstream NAME] UPSTREAM_PATH KIND [ANCHOR] [--params TEXT] [--begin TEXT --end TEXT]`: prints the fragment
  text on stdout, and `UPSTREAM_PATH:FIRST-LAST sha256=HEX` on stderr. It writes nothing.
- `list-anchors [--upstream NAME] UPSTREAM_PATH`: one line per anchor that `extract` resolves,
  `KIND<TAB>ANCHOR<TAB>PARAMS<TAB>FIRST<TAB>LAST`, sorted by FIRST, then KIND, then ANCHOR.
  - It tries every `SVM_CASE(…)` header, every top-level `NODE_DEFINE(…)` line, every directive line at depth 0 matching
    `#\s*define\s+(<identifier>)`, and every top-level line with a declarator. It prints those that resolve.
  - A declarator that contains `::` is tried as kind `member`, and any other as kind `function`.
  - A `member` or `function` is resolved with its full parameter text as `params`, so overloads get one line each. A
    declarator without parameter text is resolved without `params`. PARAMS prints that text (empty if there is none), and
    is empty for the other kinds.
- `sync`: `cmd_sync` first calls `sync_fragments(MANIFEST, checkouts)`, before T3.1's `sync_manifest` writes anything.
  - It re-extracts every fragment. If any extracted text's sha256 or line range differs from its entry's, it names that
    fragment, nothing is written, and `sync` exits 1.
  - Otherwise it writes every `.inc` file. Then `sync_manifest` runs as in T3.1, and its re-rendered `VENDORED.toml`
    keeps every `[[fragment]]` entry byte-identical.
  - After T3.1's output line, `sync` prints `synced <M> fragments`.
- `check`: rules 1-3 hold on the whole file because `load_manifest` enforces them. Offline, `cmd_check` adds
  `check_fragments(MANIFEST)`: every `.inc` file exists with its entry's sha256, and every file under
  `third_party/cycles/fragments/` belongs to an entry. `check --upstream` calls `check_fragments(MANIFEST, checkouts)`
  instead, which also re-extracts every fragment and compares its bytes and `upstream_lines`.
  - Each problem prints as `vendor-check: <problem>`, like T3.1's.
  - On success, after T3.1's line, `check` prints `vendor-check: <M> fragments match third_party/cycles/VENDORED.toml`.
    With `--upstream`, ` and re-extraction from upstream` is appended.
- A `FragmentError` reaches T3.1's handler in `main`: `vendor_sync: error: <message>` on stderr, exit status 1.
- Read and write files as bytes, so Windows never translates newlines.

### `tools/vendor_sync.py` Python API (the tests call it; the CLI wraps it)
```python
from collections.abc import Mapping, Sequence
from dataclasses import dataclass
from pathlib import Path


class FragmentError(VendorError):
    """An anchor that does not resolve to exactly one well-formed fragment, or a broken fragment entry."""


@dataclass(frozen=True)
class Manifest:  # T3.1's class with a third field and no defaults.
    upstreams: dict[str, Upstream]
    entries: list[Entry]
    fragments: list[dict[str, object]]  # [[fragment]] tables in file order.


@dataclass(frozen=True)
class Fragment:
    text: str  # The extent's lines, each ending in "\n".
    first_line: int  # 1-based, inclusive.
    last_line: int  # 1-based, inclusive.


@dataclass(frozen=True)
class Anchor:
    kind: str
    anchor: str  # "" for span.
    params: str  # Parameter text for member/function ("" if none); "" for the other kinds.
    first_line: int
    last_line: int


def extract_fragment(source: str, kind: str, anchor: str | None = None, *, params: str | None = None,
                     begin: str | None = None, end: str | None = None) -> Fragment: ...
def list_anchors(source: str) -> list[Anchor]: ...
def fragment_name(upstream_path: str, kind: str, anchor: str | None = None, *, params: str | None = None,
                  fragment_id: str | None = None) -> str: ...
def add_fragments(manifest: Path, checkouts: Mapping[str, Path], upstream: str, upstream_path: str, kind: str,
                  anchors: Sequence[str] = (), *, params: str | None = None, fragment_id: str | None = None,
                  begin: str | None = None, end: str | None = None) -> list[str]: ...
def sync_fragments(manifest: Path, checkouts: Mapping[str, Path]) -> None: ...
def check_fragments(manifest: Path, checkouts: Mapping[str, Path] | None = None) -> list[str]: ...
def remove_fragments(manifest: Path, names: Sequence[str]) -> None: ...
```
- `source` is the decoded file text. `extract_fragment` raises `FragmentError` if it contains `\r`.
- `manifest` is a `VENDORED.toml`. Its fragment files live under `manifest.parent / "fragments"`.
- `checkouts` maps an upstream name to its checkout directory, the repository root. The source of a fragment is
  `<checkout>/<root>/<upstream_path>`, with `root` from the manifest's `[upstream.<name>]`.
- `add_fragments` returns the names it added. `sync_fragments` and `remove_fragments` raise `FragmentError` on failure.
  Every public function above raises only `FragmentError`.
- `check_fragments` returns one message per problem, each naming the fragment or the file; the list is empty when all is
  well. With `checkouts`, it also makes the `--upstream` comparison. A manifest that breaks rule 1, 2 or 3 makes it raise
  `FragmentError`, as `load_manifest` does.
- The CLI builds `checkouts` as "`tools/vendor_sync.py` subcommands" says: `checkout_dir` for `add-fragment`, `extract`
  and `list-anchors`, and `ensure_checkout` for `sync` and `check --upstream`.

### `tools/gen_svm_switch.py`
`gen_svm_switch.py --manifest PATH --vendored PATH (--output PATH | --check PATH)`
- Reads the manifest and the `[[fragment]]` entries of `--vendored`. Fragment files are
  `<directory of --vendored>/fragments/<name>.inc`.
- Uses the fragments `kernel/svm/svm_h/span/svm_case_macro`, `kernel/svm/svm_h/span/svm_eval_nodes_head` and
  `kernel/svm/svm_h/span/svm_eval_nodes_tail`, plus `kernel/svm/svm_h/svm_case/<NODE>` for each case. Before using a
  file, it checks the file's sha256 against its entry.
- `--output` writes the result as bytes and creates missing parent directories. `--check` compares the result with an
  existing file.
- Exit status:
  - 0 on success;
  - 1, with `gen_svm_switch: <message>` on stderr, when a file cannot be read or is not valid TOML, a manifest key,
    include or case is invalid, a case is listed twice, an entry or a file is missing, a sha256 differs, or `--check`
    finds a difference;
  - 2 on a usage error (`argparse`).
- Python API:
  ```python
  class GenerateError(Exception):
      """An input that cannot produce the switch. The message names the file, entry or case."""


  def generate(manifest: Path, vendored: Path) -> str: ...
  def main(argv: list[str] | None = None) -> int: ...
  ```
  - `generate()` raises `GenerateError`, with the message, for every exit-1 condition above except `--check`. It
    converts `OSError` and `tomllib.TOMLDecodeError` into `GenerateError`.
  - `main` catches only `GenerateError`: it prints `gen_svm_switch: <message>` on stderr and returns 1. Its own
    `--output` write and `--check` read also turn an `OSError` into `GenerateError`. A `--check` difference prints
    `gen_svm_switch: <path> differs from the generated text` on stderr and returns 1. Otherwise `main` returns 0.

The output is exactly the concatenation of:
1. the header below, which ends with a newline;
2. `"\n#pragma once\n\n"`;
3. `'#include "<path>"\n'` for each include, in manifest order;
4. `"\nCCL_NAMESPACE_BEGIN\n\n"`;
5. P(`svm_case_macro`), then `"\n"`;
6. P(`svm_eval_nodes_head`);
7. P(case) for each case, in increasing `upstream_lines[0]`. The manifest order does not matter;
8. P(`svm_eval_nodes_tail`);
9. `"\nCCL_NAMESPACE_END\n"`.

P(f) is `/* <upstream_path>:<first>-<last> */` and `"\n"`, followed by the fragment's text, with `first` and `last` from
`upstream_lines`. Nothing else enters the output: no timestamp, and no path given on the command line.
