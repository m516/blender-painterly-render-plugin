# T6.8 — Image texture SVM nodes on the CPU (untiled float, half and byte RGBA), an in-memory `ImageManager` with explicit colour-space classes, and the X-colour pre-registration

## Goal
After this card:
- Cycles' image texture evaluators are vendored verbatim and dispatched by the generated `svm_eval_nodes()` (`cycles_svm`,
  T6.3): six cases, `NODE_TEX_IMAGE`, `NODE_TEX_IMAGE_BOX`, `NODE_TEX_ENVIRONMENT` and their `*_DERIVATIVE` variants.
  - Vendored files: `kernel/svm/image.h`, `kernel/image.h`, `kernel/device/cpu/image.h`, `kernel/util/image_2d.h` and
    `util/half.h`. `util/types_image.h` is already vendored (T6.1).
  - One new shim, `src/cycles/shim/util/atomic.h`: upstream's `util/atomic.h` includes `atomic_ops.h` from Blender's
    `intern/atomic` (`util/atomic.h:10`), which lies outside the pinned root, and no vendored code calls an atomic operation.
- The shim `src/cycles/shim/scene/image.h` (T6.4) grows into a minimal, in-memory `ImageManager`:
  - it takes an image as Blender holds it (float RGBA or byte RGBA) plus an explicit colour-space class, since painterly has no
    OCIO;
  - it stores and conforms the pixels as Cycles does (bytes, half floats for converted byte images, floats; alpha association;
    ignored alpha; non-finite pixels);
  - it fills the kernel arrays `image_textures` and `image_info` for untiled CPU images
    (`KernelImageTexture::tile_descriptor_offset == UINT_MAX`).
- Doctests sample small synthetic images through `svm_eval_nodes()` and compare, bit for bit, with expectations computed
  independently of the code under test:
  - closest, linear and cubic interpolation, each with the periodic, clamp, black and mirror extensions;
  - every storage type and colour-space class, alpha association, the unassociate flag, missing images;
  - box and environment projections and the derivative cases.
- Experiment X-colour of `docs/plan.md` is pre-registered in this card. It gets its number when it runs, in M6b.

M6a builds Cycles' shader VM as standalone vendored libraries. Nothing in the painterly engine samples images yet: M6b wires
the image path into `painterly_trace_pixel`, `PainterlyScene` and the Blender sync.

## Decisions (Opus, 2026-10-09)
1. **Scope: the kernel image path and an in-memory image manager, not the image node classes.**
   - This card vendors the evaluators and makes `ImageManager` produce what they read. It does not extract `ImageTextureNode`
     or `EnvironmentTextureNode` from `scene/shader_nodes.cpp`.
   - Their out-of-line members need much more than the image manager: `ImageTextureNode::cull_tiles`
     (`scene/shader_nodes.cpp:319-381`) reads `Scene::params`, `Scene::geometry`, `Geometry::get_used_shaders()`,
     `get_uv_tiles()` and `UVMapNode`; `update_images` and `compile` (`:406-485`) read `ImageMetaData` through
     `ImageHandle::metadata(Progress &)` and call `ColorSpaceManager::colorspace_is_data()`. M6b, which owns the Blender sync,
     extracts them ("For later cards").
   - The doctests therefore encode the node structs by hand, as `ImageTextureNode::compile` would (`:432-485`).
2. **Untiled CPU images only.**
   - `get_use_texture_cache()` is false, so no image has tiles or mipmaps.
   - Every `KernelImageTexture` keeps `tile_descriptor_offset` at its default `KERNEL_TILE_LOAD_NONE`, which is `UINT_MAX`
     (`util/types_image.h:120, 149`). `kernel_image_interp()` then samples `image_info` directly
     (`kernel/device/cpu/image.h:357-366`). Every handle is a single image (no UDIM), so its id is `>= 0` and
     `kernel_image_udim_map()` returns it unchanged (`kernel/util/image_2d.h:21-23`).
   - Consequences: the tiled path (`kernel/util/image_2d.h:48-190`) never runs, so `KernelGlobalsCPU::image_load_requested_cpu`
     is never called, `kernel_data.image.mip_bias` is never read, and `sd->lcg_state` is never read. Evaluation draws no random
     number (SPEC §2).
3. **`util/atomic.h` is a shim that defines nothing.**
   - Upstream's CPU branch (`util/atomic.h:7-20`) includes `atomic_ops.h` from Blender's `intern/atomic`, outside the pinned
     `intern/cycles` root. Vendoring `intern/atomic` would add a third upstream for no use.
   - The only vendored includer, `kernel/util/image_2d.h:10`, calls no atomic operation on the CPU. Neither does any other
     vendored file. `tests/core/test_cycles_svm_images.py` checks that, so a card that vendors such code finds out and extends
     the shim.
4. **Colour without OCIO: explicit classes, upstream's storage rules.**
   - Cycles classifies every image's colour space with OCIO (`ColorSpaceManager::detect_known_colorspace()`,
     `util/colorspace.cpp:281-383`). Painterly has no OCIO. The caller states the class, as `PainterlyImageColorSpace`:
     scene linear, scene linear with the sRGB transfer function, data, or converted. For the converted class it gives the
     pixels already converted to scene linear. M6b's Python export decides both; experiment X-colour tests how.
   - From the class and the source type, `ImageManager::add_image()` makes the decisions of `ImageMetaData::finalize()`
     (`util/image_metadata.cpp:124-170`) and the OCIO-free steps of `conform_pixels_to_metadata_type()` (`:484-611`), in
     upstream's order:

     | source (Blender buffer) | class | storage | `is_compressible_as_srgb` |
     |---|---|---|---|
     | bytes | scene linear, data | `IMAGE_DATA_TYPE_BYTE4` | no |
     | bytes | scene linear sRGB | `IMAGE_DATA_TYPE_BYTE4` | yes |
     | bytes | converted | `IMAGE_DATA_TYPE_HALF4` (`float_to_half_image()` of the converted floats) | no |
     | floats | scene linear, data, converted | `IMAGE_DATA_TYPE_FLOAT4` | no |
     | floats | scene linear sRGB | `IMAGE_DATA_TYPE_FLOAT4` | yes |

     Alpha: associated on load when the class is not data and the alpha type is `UNASSOCIATED`, or `AUTO` with an
     unassociated source; never for `ASSOCIATED`, `IGNORE`, `CHANNEL_PACKED` or data. `IGNORE` sets alpha to one. A float or
     half pixel with a non-finite channel becomes zero.
   - The converted class and alpha. The caller's contract is the comment on `PAINTERLY_IMAGE_COLORSPACE_CONVERTED` in
     "Interface". Write c for a pixel's colour, a for its alpha and conv() for the conversion to scene linear. For a byte
     source, c and a are the half floats `float_to_half_image(b / 255)` that upstream converts (`blender/image.cpp:146-154`).
     - Upstream converts every RGBA pixel of a converted image by unpremultiplying, converting and premultiplying,
       conv(c · (1 / a)) · a, unless a <= 0, a == 1, or the alpha type is `IGNORE` or `CHANNEL_PACKED`; then it converts
       conv(c) (`util/colorspace.cpp:498-503, 524-528`; the `ignore_alpha` argument is
       `metadata.ignore_alpha || metadata.is_channel_packed`, `util/image_metadata.cpp:565-578`). If the alpha is
       unassociated, upstream associates it before converting (`util/image_metadata.cpp:498-509`).
     - When `add_image()` does not associate the alpha (`ASSOCIATED`; `AUTO` with an associated source, such as every Blender
       float buffer; `IGNORE`; `CHANNEL_PACKED`), the caller passes upstream's converted values. Painterly then stores what
       upstream stores.
     - When `add_image()` associates the alpha (`UNASSOCIATED`, or `AUTO` with an unassociated source), the caller passes
       conv(c) of the straight values, and `add_image()` multiplies by a afterwards. Upstream computes
       conv((c · a) · (1 / a)) · a, with c · a rounded to the storage type. The two agree when a == 1, and when a == 0 if
       conv(0) == 0. Otherwise they agree only up to rounding. This is the one known deviation, left to X-colour
       (measurement H4(f)) and M6b.
   - `is_compressible_as_srgb` is reported in `PainterlyImageMetaData`. Turning it into the node flag
     `NODE_IMAGE_COMPRESS_AS_SRGB` is the node's compile step (`scene/shader_nodes.cpp:440-448`), so the doctests set the
     flag by hand.
5. **Expected values do not run the code under test** (as T6.6, "Decisions" 3).
   - Closest and linear interpolation sample images of small integers at points with dyadic weights. Every intermediate
     result is exact in float32, so the written-out values are exact.
   - Cubic interpolation samples a delta image. Only the taps that land on its single non-zero texel contribute, so each
     expected value is a short expression in the B-spline weights, written in the kernel's order of operations. At a texel
     centre the weights are the B-spline constants 1/6, 2/3, 1/6, 0. At other positions `cubic_weights_reference()` evaluates
     the polynomials of `SET_CUBIC_SPLINE_WEIGHTS` operation by operation.
   - The sRGB case compares with `color_srgb_to_linear_v4()` of `util/color.h` (vendored by T3.2), the function that the kernel
     applies after interpolation. The doctest also checks that converting first would give a different value.
   - Comparisons are exact: `PainterlySvmTestProgram::check_equal()` (T6.3) inside the VM, `CHECK(a == b)` outside.
6. **Upstream behaviour is pinned, not corrected.** `frac()` (`kernel/device/cpu/image.h:30-35`) truncates and then
   subtracts 1 for every negative `x`. At a negative integer it therefore gives `ix = x - 1` and `t = 1` instead of
   `floor(x)` and `t = 0`. Closest interpolation then reads the texel to the left. Painterly must match Blender's Cycles, so
   the doctests pin this behaviour (closest: `u = -0.25`; cubic: `P2`).

```cpp
 *
 * SPDX-License-Identifier: Apache-2.0 */

/* Modified by the Painterly project: ImageParams without animated, colorspace and frame;
 * ImageHandle for one untiled image; ImageManager reduced to add_image() of pixels given in
 * memory; and the painterly types PainterlyImageColorSpace, PainterlyImagePixels and
 * PainterlyImageMetaData. */

#pragma once

#define PAINTERLY_SHIM_SCENE_IMAGE_H 1

#include "util/half.h"
#include "util/types_float4.h"
#include "util/types_image.h"
#include "util/types_uchar4.h"

CCL_NAMESPACE_BEGIN

class ImageManager;

/* Upstream's ImageParams (scene/image.h:38-55) reduced to the members that the in-memory path
 * reads, with upstream's defaults. Upstream also has animated, colorspace and frame: painterly
 * gets one frame of pixels from Blender, and the colour space comes with the pixels
 * (PainterlyImagePixels). Upstream's operator== compares every member (scene/image.h:49-54);
 * the defaulted one does the same, also for members that a later card adds. */
class ImageParams {
 public:
  InterpolationType interpolation = INTERPOLATION_LINEAR;
  ExtensionType extension = EXTENSION_CLIP;
  ImageAlphaType alpha_type = IMAGE_ALPHA_AUTO;

  bool operator==(const ImageParams &other) const = default;
};

/* Painterly: how an image's colour space relates to scene linear. Upstream decides it with OCIO
 * in ColorSpaceManager::detect_known_colorspace() (util/colorspace.cpp:281-383). Painterly has
 * no OCIO, so the caller decides it (card T6.8; experiment X-colour). It selects what
 * ImageMetaData::finalize() selects (util/image_metadata.cpp:124-170). */
enum PainterlyImageColorSpace {
  /* u_colorspace_scene_linear: stored as given. */
  PAINTERLY_IMAGE_COLORSPACE_SCENE_LINEAR = 0,
  /* u_colorspace_scene_linear_srgb: scene linear primaries with the sRGB transfer function.
   * Stored as given; the kernel converts to linear after interpolation
   * (is_compressible_as_srgb, util/image_metadata.cpp:133-137; NODE_IMAGE_COMPRESS_AS_SRGB,
   * kernel/svm/image.h:33-35). */
  PAINTERLY_IMAGE_COLORSPACE_SCENE_LINEAR_SRGB = 1,
  /* u_colorspace_data: non-colour data, stored as given; its alpha is never associated
   * (util/image_metadata.cpp:159-163). */
  PAINTERLY_IMAGE_COLORSPACE_DATA = 2,
  /* Any other colour space. Upstream converts it to scene linear with OCIO when it loads the
   * pixels, and stores a byte source as half floats (util/image_metadata.cpp:138-147, 565-578).
   * Painterly has no OCIO: the caller converts and gives the result as `floats`, and add_image()
   * stores and conforms it as for the other classes. Below, c is a pixel's colour, a its alpha
   * and conv() the conversion to scene linear. For a byte source, c and a are the half floats
   * float_to_half_image(b / 255) that upstream converts (blender/image.cpp:146-154).
   * - Upstream converts each RGBA pixel as conv(c * (1 / a)) * a, in float32 in this order, and
   *   as conv(c) when a <= 0, a == 1, or the alpha type is IMAGE_ALPHA_IGNORE or
   *   IMAGE_ALPHA_CHANNEL_PACKED (util/colorspace.cpp:498-503, 524-528;
   *   util/image_metadata.cpp:565-578). Unassociated alpha it associates before that
   *   (util/image_metadata.cpp:498-509).
   * - If add_image() does not associate the alpha (IMAGE_ALPHA_ASSOCIATED; IMAGE_ALPHA_AUTO with
   *   an associated source, such as every Blender float buffer; IMAGE_ALPHA_IGNORE;
   *   IMAGE_ALPHA_CHANNEL_PACKED), the caller passes upstream's converted values above. Painterly
   *   then stores what upstream stores.
   * - If add_image() associates the alpha (IMAGE_ALPHA_UNASSOCIATED, or IMAGE_ALPHA_AUTO with an
   *   unassociated source), the caller passes conv(c) of the straight values and add_image()
   *   multiplies by a afterwards. This agrees with upstream when a == 1, and when a == 0 if
   *   conv(0) == 0; otherwise only up to rounding (card T6.8, Decision 4; experiment X-colour). */
  PAINTERLY_IMAGE_COLORSPACE_CONVERTED = 3,
};

/* Painterly: one image as Blender holds it in memory, the input that upstream's
 * BlenderImageLoader reads (blender/image.cpp:46-94). Painterly treats every image as a Blender
 * builtin image: it has no file loader. */
struct PainterlyImagePixels {
  /* Dimensions in pixels. If either is 0 the image is missing, as upstream treats an empty image
   * (scene/image_cache.cpp:200-216): the kernel returns IMAGE_MISSING_RGBA. */
  int width = 0;
  int height = 0;
  /* What Blender's buffer holds: IMAGE_DATA_TYPE_BYTE4 (a byte buffer) or
   * IMAGE_DATA_TYPE_FLOAT4 (a float buffer), as BlenderImageLoader::load_metadata() reports it
   * (blender/image.cpp:72-91). */
  ImageDataType source_type = IMAGE_DATA_TYPE_FLOAT4;
  PainterlyImageColorSpace colorspace = PAINTERLY_IMAGE_COLORSPACE_SCENE_LINEAR;
  /* Whether the source's alpha is unassociated. BlenderImageLoader sets it for byte buffers and
   * clears it for float buffers (blender/image.cpp:62). */
  bool is_unassociated_alpha = false;
  /* width * height pixels, row by row, the first row at v = 0 (y = v * height,
   * kernel/device/cpu/image.h:365). A byte source is in `bytes`. A float source is in `floats`,
   * and so is a source of any type in PAINTERLY_IMAGE_COLORSPACE_CONVERTED, converted to scene
   * linear by the caller as that class's comment says. The other vector is empty. */
  vector<uchar4> bytes;
  vector<float4> floats;
};

/* Painterly: the part of upstream's ImageMetaData (util/image_metadata.h:24-95) that
 * ImageMetaData::finalize() decides (util/image_metadata.cpp:124-170). Upstream's class needs
 * OIIO. */
struct PainterlyImageMetaData {
  /* The storage type: IMAGE_DATA_TYPE_BYTE4, IMAGE_DATA_TYPE_HALF4 or IMAGE_DATA_TYPE_FLOAT4.
   * IMAGE_DATA_NUM_TYPES for a missing image. */
  ImageDataType type = IMAGE_DATA_NUM_TYPES;
  int width = 0;
  int height = 0;
  bool is_compressible_as_srgb = false;
  bool is_unassociated_alpha = false;
  bool ignore_alpha = false;
  bool is_channel_packed = false;
};

/* Upstream's ImageHandle (scene/image.h:63-96) for a single image in the in-memory path:
 * no reference counting, no UDIM tiles and no volume images. The image lives as long as its
 * ImageManager. scene/shader_nodes.h holds an ImageHandle by value (:102, :196) and compares two
 * of them (:91). */

 public:
  /* scene/image.cpp:99-102. */
  bool empty() const

    return manager == nullptr;
  }

  /* The image's index into the kernel array image_textures, KERNEL_IMAGE_NONE for an empty
   * handle (scene/image.cpp:145-154). */
  int kernel_id() const

    return image_texture_id;

  /* scene/image.cpp:185-188. */

  }

  /* Upstream compares the manager and the image (scene/image.cpp:190-193). */
  bool operator==(const ImageHandle &other) const = default;

 protected:

  int image_texture_id = KERNEL_IMAGE_NONE;

/* Upstream's ImageManager (scene/image.h:149-238) for images given in memory, loaded on the CPU
 * without the texture cache. add_image() loads the pixels at once into host memory, conformed as
 * upstream conforms them (util/image_metadata.cpp:484-611), and fills the kernel arrays
 * image_textures and image_info (kernel/data_arrays.h:93, 97) as upstream's device update does
 * (scene/image.cpp:467-523; scene/image_cache.cpp:125-149, 192-274; device/memory.cpp:214-306).
 * Every image is untiled: KernelImageTexture::tile_descriptor_offset keeps its default
 * KERNEL_TILE_LOAD_NONE, which is UINT_MAX (util/types_image.h:120, 149), so the kernel samples

 public:
  ImageManager();
  ~ImageManager();

  ImageManager(const ImageManager &) = delete;
  ImageManager &operator=(const ImageManager &) = delete;

  /* Upstream's add_image() of a builtin image (scene/image.cpp:324-330, 350-389), with the pixels
   * in place of the loader. Every call adds a new image; upstream reuses an image whose loader and
   * params are equal (scene/image.cpp:356-363), which painterly's caller does by keeping its
   * handles. Invalid pixels (see PainterlyImagePixels) give a missing image and an error in the
   * log, as a failed load does upstream (scene/image_cache.cpp:237-244). */
  ImageHandle add_image(const PainterlyImagePixels &pixels, const ImageParams &params);

  /* scene/image.h:184-185: painterly never uses the texture cache. */
  bool get_use_texture_cache() const
  {
    return false;
  }
  bool get_auto_texture_cache() const
  {
    return false;
  }

  /* Painterly: the metadata of `handle`'s image; a default PainterlyImageMetaData for an empty
   * handle. */
  PainterlyImageMetaData metadata(const ImageHandle &handle) const;

  /* Painterly: the kernel arrays image_textures and image_info, indexed by
   * ImageHandle::kernel_id() and KernelImageTexture::image_info_id. add_image() may move the
   * arrays, so bind them to KernelGlobalsCPU after the last add_image(). KernelImageInfo::data
   * points into this manager's pixel storage and stays valid until the manager is destroyed. */
  const vector<KernelImageTexture> &get_image_textures() const
  {
    return image_textures;
  }
  const vector<KernelImageInfo> &get_image_info() const
  {
    return image_info;
  }

 private:
  /* The pixels of one image in its storage type; only the vector of that type is non-empty. */
  struct Storage {
    PainterlyImageMetaData metadata;
    vector<uchar4> bytes;
    vector<half4> halfs;
    vector<float4> floats;
  };

  vector<unique_ptr<Storage>> images;
  vector<KernelImageTexture> image_textures;
  vector<KernelImageInfo> image_info;
};
```

### `src/cycles/shim/scene/image.cpp`
```cpp
/* Shim: replaces Cycles scene/image.cpp without OIIO, OCIO, devices or the texture cache */

/* SPDX-FileCopyrightText: 2011-2022 Blender Foundation
 *
 * SPDX-License-Identifier: Apache-2.0 */

/* Modified by the Painterly project: ImageManager::add_image() of pixels given in memory, with
 * the pixel conforming of util/image_metadata.cpp and util/image.h and the kernel array fill of
 * scene/image.cpp, scene/image_cache.cpp and device/memory.cpp, without OIIO, OCIO, devices or
 * the texture cache. */

#include "scene/image.h"

#include <cmath>

#include "util/log.h"

CCL_NAMESPACE_BEGIN

namespace {

/* util_image_cast_from_float(1.0f) for each storage type (util/image.h:53-80): the alpha that
 * IMAGE_ALPHA_IGNORE writes (util/image_metadata.cpp:512, 554-562). */
uchar4 with_opaque_alpha(uchar4 pixel)
{
  pixel.w = 255;
  return pixel;
}

half4 with_opaque_alpha(half4 pixel)
{
  pixel.w = float_to_half_image(1.0f);
  return pixel;
}

float4 with_opaque_alpha(float4 pixel)
{
  pixel.w = 1.0f;
  return pixel;
}

/* util_image_multiply_native() (util/image.h:83-100), applied to the colour channels as
 * conform_pixels_to_metadata_type() associates alpha (util/image_metadata.cpp:498-509). */
uchar4 associate_alpha(uchar4 pixel)
{
  const uchar alpha = pixel.w;
  pixel.x = uchar(((uint32_t)pixel.x * (uint32_t)alpha) / 255);
  pixel.y = uchar(((uint32_t)pixel.y * (uint32_t)alpha) / 255);
  pixel.z = uchar(((uint32_t)pixel.z * (uint32_t)alpha) / 255);
  return pixel;
}

half4 associate_alpha(half4 pixel)
{
  const half alpha = pixel.w;
  pixel.x = float_to_half_image(half_to_float_image(pixel.x) * half_to_float_image(alpha));
  pixel.y = float_to_half_image(half_to_float_image(pixel.y) * half_to_float_image(alpha));
  pixel.z = float_to_half_image(half_to_float_image(pixel.z) * half_to_float_image(alpha));
  return pixel;
}

float4 associate_alpha(float4 pixel)
{
  const float alpha = pixel.w;
  pixel.x = pixel.x * alpha;
  pixel.y = pixel.y * alpha;
  pixel.z = pixel.z * alpha;
  return pixel;
}

/* util_image_is_finite() (util/image.h:103-120) of all four channels: an RGBA pixel with any
 * non-finite channel becomes zero (util/image_metadata.cpp:580-599). Bytes are always finite. */
uchar4 zero_if_not_finite(const uchar4 pixel)
{
  return pixel;
}

half4 zero_if_not_finite(half4 pixel)
{
  if (!half_is_finite(pixel.x) || !half_is_finite(pixel.y) || !half_is_finite(pixel.z) ||
      !half_is_finite(pixel.w))
  {
    const half zero = float_to_half_image(0.0f);
    pixel = {zero, zero, zero, zero};
  }
  return pixel;
}

float4 zero_if_not_finite(float4 pixel)
{
  if (!std::isfinite(pixel.x) || !std::isfinite(pixel.y) || !std::isfinite(pixel.z) ||
      !std::isfinite(pixel.w))
  {
    pixel = zero_float4();
  }
  return pixel;
}

/* conform_pixels_to_metadata_type() (util/image_metadata.cpp:484-611) for RGBA pixels whose
 * colour space needs no conversion here: associate alpha, then ignore alpha, then zero the
 * non-finite pixels, in upstream's order. */
template<typename StorageType>
void conform_pixels(const PainterlyImageMetaData &metadata, vector<StorageType> &pixels)
{
  for (StorageType &pixel : pixels) {
    if (metadata.is_unassociated_alpha) {
      pixel = associate_alpha(pixel);
    }
    if (metadata.ignore_alpha) {
      pixel = with_opaque_alpha(pixel);
    }
    pixel = zero_if_not_finite(pixel);
  }
}

/* The reason why `pixels` cannot be loaded, or nullptr if they can. */
const char *invalid_pixels_reason(const PainterlyImagePixels &pixels)
{
  if (pixels.width < 0 || pixels.height < 0) {
    return "negative size";
  }
  if (pixels.width == 0 || pixels.height == 0) {
    return "empty image";
  }
  const size_t num_pixels = size_t(pixels.width) * size_t(pixels.height);
  const bool use_bytes = pixels.source_type == IMAGE_DATA_TYPE_BYTE4 &&
                         pixels.colorspace != PAINTERLY_IMAGE_COLORSPACE_CONVERTED;
  if (pixels.source_type != IMAGE_DATA_TYPE_BYTE4 && pixels.source_type != IMAGE_DATA_TYPE_FLOAT4)
  {
    return "source_type is neither IMAGE_DATA_TYPE_BYTE4 nor IMAGE_DATA_TYPE_FLOAT4";
  }
  if (use_bytes && (pixels.bytes.size() != num_pixels || !pixels.floats.empty())) {
    return "a byte image needs width * height bytes and no floats";
  }
  if (!use_bytes && (pixels.floats.size() != num_pixels || !pixels.bytes.empty())) {
    return "a float or converted image needs width * height floats and no bytes";
  }
  return nullptr;
}

}  // namespace

ImageManager::ImageManager() = default;

ImageManager::~ImageManager() = default;

ImageHandle ImageManager::add_image(const PainterlyImagePixels &pixels, const ImageParams &params)
{
  unique_ptr<Storage> storage = make_unique<Storage>();
  PainterlyImageMetaData &metadata = storage->metadata;

  /* scene/image.cpp:481-488: the texture's size, interpolation and extension. The metadata's
   * defaults give use_transform_3d = false, transform_3d = identity and a zero average colour
   * (util/image_metadata.h:38, 47-48). */
  KernelImageTexture tex;
  tex.interpolation = params.interpolation;
  tex.extension = params.extension;
  tex.use_transform_3d = false;
  tex.transform_3d = transform_identity();
  tex.average_color = zero_float4();

  const char *invalid = invalid_pixels_reason(pixels);
  if (invalid) {
    if (pixels.width != 0 && pixels.height != 0) {
      LOG_ERROR << "Image texture " << images.size() << " not loaded: " << invalid;
    }
    /* A missing image: image_info_id stays KERNEL_IMAGE_NONE (scene/image_cache.cpp:200-216,
     * 237-244), and the kernel returns IMAGE_MISSING_RGBA (kernel/device/cpu/image.h:359-361). */
  }
  else {
    /* ImageMetaData::finalize() (util/image_metadata.cpp:124-170). */
    metadata.width = pixels.width;
    metadata.height = pixels.height;
    metadata.type = pixels.source_type;
    if (pixels.colorspace == PAINTERLY_IMAGE_COLORSPACE_SCENE_LINEAR_SRGB) {
      metadata.is_compressible_as_srgb = true;
    }
    else if (pixels.colorspace == PAINTERLY_IMAGE_COLORSPACE_CONVERTED &&
             pixels.source_type == IMAGE_DATA_TYPE_BYTE4)
    {
      metadata.type = IMAGE_DATA_TYPE_HALF4;
    }
    metadata.ignore_alpha = params.alpha_type == IMAGE_ALPHA_IGNORE;
    metadata.is_channel_packed = params.alpha_type == IMAGE_ALPHA_CHANNEL_PACKED;
    if (pixels.colorspace == PAINTERLY_IMAGE_COLORSPACE_DATA ||
        params.alpha_type == IMAGE_ALPHA_ASSOCIATED || params.alpha_type == IMAGE_ALPHA_IGNORE ||
        params.alpha_type == IMAGE_ALPHA_CHANNEL_PACKED)
    {
      metadata.is_unassociated_alpha = false;
    }
    else if (params.alpha_type == IMAGE_ALPHA_UNASSOCIATED) {
      metadata.is_unassociated_alpha = true;
    }
    else {
      metadata.is_unassociated_alpha = pixels.is_unassociated_alpha;
    }

    /* The pixels in their storage type, conformed. A converted byte source becomes half floats
     * with float_to_half_image(), as BlenderImageLoader's load_half_pixels() stores them
     * (blender/image.cpp:146-154). */
    const void *data = nullptr;
    switch (metadata.type) {
      case IMAGE_DATA_TYPE_BYTE4:
        storage->bytes = pixels.bytes;
        conform_pixels(metadata, storage->bytes);
        data = storage->bytes.data();
        break;
      case IMAGE_DATA_TYPE_HALF4:
        storage->halfs.reserve(pixels.floats.size());
        for (const float4 &pixel : pixels.floats) {
          storage->halfs.push_back({float_to_half_image(pixel.x),
                                    float_to_half_image(pixel.y),
                                    float_to_half_image(pixel.z),
                                    float_to_half_image(pixel.w)});
        }
        conform_pixels(metadata, storage->halfs);
        data = storage->halfs.data();
        break;
      default:
        storage->floats = pixels.floats;
        conform_pixels(metadata, storage->floats);
        data = storage->floats.data();
        break;
    }

    /* scene/image.cpp:482-483: the texture's size. */
    tex.width = metadata.width;
    tex.height = metadata.height;

    /* ImageCache::alloc_full() (scene/image_cache.cpp:125-149), with what the device_image
     * constructor and alloc() write into KernelImageInfo (device/memory.cpp:214-268, 290-306),
     * and the host pointer that the CPU device stores in it (device/cpu/device_impl.cpp:258-259).
     */
    KernelImageInfo info;
    info.data = (uint64_t)data;
    info.data_type = metadata.type;
    info.interpolation = params.interpolation;
    info.extension = params.extension;
    info.width = metadata.width;
    info.height = metadata.height;
    info.inv_width = 1.0f / (float)metadata.width;
    info.inv_height = 1.0f / (float)metadata.height;
    tex.image_info_id = uint(image_info.size());
    image_info.push_back(info);
  }

  ImageHandle handle;
  handle.manager = this;
  handle.image_texture_id = int(image_textures.size());
  image_textures.push_back(tex);
  images.push_back(std::move(storage));
  return handle;
}

PainterlyImageMetaData ImageManager::metadata(const ImageHandle &handle) const
{
  if (handle.manager != this || handle.image_texture_id == KERNEL_IMAGE_NONE) {
    return PainterlyImageMetaData();
  }
  return images[handle.image_texture_id]->metadata;
}
```

```cpp
/* The 4 x 2 value image. Texel (x, y) is (1 + x, 1 + y, n, n / 16) with n = 1 + x + 4y: every
 * texel differs, blue names the texel, and alpha is blue / 16. Row y = 0 is at v = 0. */
PainterlyImagePixels value_image()
{
  vector<float4> floats;
  for (int y = 0; y < 2; y++) {
    for (int x = 0; x < 4; x++) {
      const float n = float(1 + x + 4 * y);
      floats.push_back(make_float4(float(1 + x), float(1 + y), n, n / 16.0f));
    }
  }
  return float_image(4, 2, floats);
}

/* Texel (x, y) of value_image(). */
float4 texel(const int x, const int y)
{
  const float n = float(1 + x + 4 * y);
  return make_float4(float(1 + x), float(1 + y), n, n / 16.0f);
}

/* The 4 x 2 delta image: (1, 1, 1, 1) at texel (0, 0), zero elsewhere. */
PainterlyImagePixels delta_image()
{
  vector<float4> floats(8, zero_float4());
  floats[0] = one_float4();
  return float_image(4, 2, floats);
}

/* SET_CUBIC_SPLINE_WEIGHTS (kernel/device/cpu/image.h:21-28), operation by operation: the cubic
 * B-spline weights of the taps at -1, 0, +1, +2 for a fractional position t. */
void cubic_weights_reference(const float t, float w[4])
{
  w[0] = (((-1.0f / 6.0f) * t + 0.5f) * t - 0.5f) * t + (1.0f / 6.0f);
  w[1] = ((0.5f * t - 1.0f) * t) * t + (2.0f / 3.0f);
  w[2] = ((-0.5f * t + 0.5f) * t + 0.5f) * t + (1.0f / 6.0f);
  w[3] = (1.0f / 6.0f) * t * t * t;
}

 * the extension (kernel/device/cpu/image.h:135-168, 110-131). frac() is floor() except at
 * negative integers (kernel/device/cpu/image.h:30-35). */

  int ids[4];

  KernelGlobalsCPU globals;
  bind_images(globals, manager);

  const float4 inside = texel(1, 0);
  const float4 outside[4] = {texel(2, 1), texel(0, 1), zero_float4(), texel(1, 0)};

    add_sample(program, ids[e], -0.375f, 1.75f, outside[e], name + " outside");

  ShaderData sd = painterly_svm_test_shader_data(0);
  run_and_check(globals, program, sd, 2 * 12);
}

/* Cubic: x = u * width - 0.5 = ix + tx; the taps ix - 1, ix, ix + 1, ix + 2 weigh the B-spline
 * weights of tx, likewise in y; the result sums, row tap by row tap, the row weight times the
 * weighted sum of the row's four texels (kernel/device/cpu/image.h:224-311). On the delta image
 * only taps that land on texel (0, 0) contribute. A = 2/3 and B = 1/6 are the weights of the
 * taps ix and ix +/- 1 at a texel centre (t = 0); the tap ix + 2 weighs 0 there. */
TEST_CASE("cycles svm images: cubic interpolation and the four extensions")
{
  ImageManager manager;
  int ids[4];
  for (int e = 0; e < 4; e++) {
    ids[e] =
        manager.add_image(delta_image(), params(INTERPOLATION_CUBIC, extensions[e])).kernel_id();
  }
  /* INTERPOLATION_SMART is cubic on the CPU (kernel/device/cpu/image.h:320-321). */
  const int smart_id =
      manager.add_image(delta_image(), params(INTERPOLATION_SMART, EXTENSION_REPEAT)).kernel_id();
  KernelGlobalsCPU globals;
  bind_images(globals, manager);

  const float A = 2.0f / 3.0f;
  const float B = 1.0f / 6.0f;
  float w[4];
  cubic_weights_reference(0.5f, w);
  float v[4];
  cubic_weights_reference(1.0f, v);

  /* Row taps at v = 0.25 (y = 0, iy = 0): -1, 0, 1, 2 with weights B, A, B, 0. Row 0 is hit by
   * tap 0 only (A) for periodic (1, 0, 1, 0) and black; by taps -1 and 0 (B, A) for clamp and
   * mirror (0, 0, 1, 1). */
  struct Sample {
    float u, v;
    float expected[4]; /* periodic, clamp, black, mirror */
    const char *label;
  };
  const Sample samples[] = {
      /* Centre of texel (0, 0): column taps -1, 0, 1, 2. periodic (3, 0, 1, 2) and black hit
       * column 0 with A; clamp and mirror (0, 0, 1, 2) with B and A. */
      {0.125f, 0.25f, {A * A, B * (B + A) + A * (B + A), A * A, B * (B + A) + A * (B + A)}, "P1"},
      /* Centre of texel (-2, 0): x = -2 is a negative integer, so frac() gives ix = -3 and
       * t = 1 (kernel/device/cpu/image.h:30-35): column taps -4, -3, -2, -1 with the weights
       * v[0..3] of t = 1. periodic wraps them to (0, 1, 2, 3): column 0 with v[0]. clamp (0, 0,
       * 0, 0): all four. black: ix < -2, so zero (kernel/device/cpu/image.h:252-254). mirror
       * (3, 2, 1, 0): column 0 with v[3]. */
      {-0.375f,
       0.25f,
       {A * v[0],
        B * (((v[0] + v[1]) + v[2]) + v[3]) + A * (((v[0] + v[1]) + v[2]) + v[3]),
        0.0f,
        B * v[3] + A * v[3]},
       "P2"},
      /* Centre of texel (3, 1): column taps 2, 3, 4, 5 and row taps 0, 1, 2, 3. periodic wraps
       * them to (2, 3, 0, 1) and (0, 1, 0, 1): column 0 with B, row 0 by the row taps 0 and 2
       * with B each. clamp (2, 3, 3, 3), black (2, 3, out, out) and mirror (2, 3, 3, 2) never
       * reach column 0. */
      {0.875f, 0.75f, {B * B + B * B, 0.0f, 0.0f, 0.0f}, "P3"},
      /* x = 0.5: ix = 0, tx = 0.5, column weights w[0..3]; rows as P1. periodic and black hit
       * column 0 with w[1]; clamp and mirror (0, 0, 1, 2) with w[0] and w[1]. */
      {0.25f,
       0.25f,
       {A * w[1],
        B * (w[0] + w[1]) + A * (w[0] + w[1]),
        A * w[1],
        B * (w[0] + w[1]) + A * (w[0] + w[1])},
       "P4"},
  };

  PainterlySvmTestProgram program = new_program();
  int lookups = 0;
  for (const Sample &sample : samples) {
    for (int e = 0; e < 4; e++) {
      const float e_value = sample.expected[e];
      add_sample(program,
                 ids[e],
                 sample.u,
                 sample.v,
                 make_float4(e_value, e_value, e_value, e_value),
                 std::string(sample.label) + " " + extension_names[e]);
      lookups++;
    }
  }
  add_sample(program,
             smart_id,
             0.125f,
             0.25f,
             make_float4(A * A, A * A, A * A, A * A),
             "P1 smart periodic");
  lookups++;
  ShaderData sd = painterly_svm_test_shader_data(0);
  run_and_check(globals, program, sd, 2 * lookups);
}

/* What ImageMetaData::finalize() decides from the colour space and the source type

   * half (float_to_half_image, util/half.h:284-287). */
  PainterlyImagePixels converted_bytes = float_image(

  converted_bytes.colorspace = PAINTERLY_IMAGE_COLORSPACE_CONVERTED;

      srgb_floats, params(INTERPOLATION_CLOSEST, EXTENSION_EXTEND));

  CHECK_FALSE(manager.metadata(linear_bytes).is_compressible_as_srgb);
  CHECK(manager.metadata(srgb_bytes).type == IMAGE_DATA_TYPE_BYTE4);

  CHECK(manager.metadata(srgb_float_image).type == IMAGE_DATA_TYPE_FLOAT4);

   * give 0.5 * 0 + 0.5 * color_srgb_to_linear(1), a different value. */
```

### README text (title, Background, Hypothesis, Method)
```markdown
# Experiment NNN: how do Blender's image pixels and colour spaces reach Cycles' image textures? (colour)

Pre-registered by Opus on 2026-10-09 in card T6.8 (X-colour in `docs/plan.md`). Run on <DATE>.

## Background

- `docs/plan.md`, "Experiments programme": X-colour asks whether Blender's bundled PyOpenColorIO sees Blender's colour
  configuration, and what `Image.pixels` holds. Milestone M6 samples Blender's image textures with Cycles' own kernel code.
- Painterly has no OCIO (`docs/plan.md`, M6). Cycles classifies each image's colour space with OCIO
  (`intern/cycles/util/colorspace.cpp:281-383`; `is_builtin_colorspace()` `:385-448`; `colorspace_is_data()` `:171-206`). The
  class decides how the pixels are stored and sampled (`util/image_metadata.cpp:124-170, 484-611`;
  `kernel/svm/image.h:22-38`):
  - bytes in the sRGB encoding stay bytes and are converted to linear after interpolation;
  - bytes in any other non-linear colour space are converted with OCIO and stored as half floats;
  - unassociated alpha is associated on load, for bytes with integer division.
- Card T6.8 reproduces this storage model in painterly's in-memory `ImageManager` (`src/cycles/shim/scene/image.h`). Its
  caller gives, per image:
  - the class (`PainterlyImageColorSpace`: scene linear, scene linear sRGB, data or converted);
  - the pixels as Blender holds them, and for the converted class the pixels converted to scene linear, by a rule that
    depends on the alpha type (the comment on `PAINTERLY_IMAGE_COLORSPACE_CONVERTED`).
  M6b's Python export will supply these from `bpy`. The export rests on three assumptions, H1-H3, and on the storage model
  itself, H4. Measurement H4(f) compares the converted-class rule with Blender's Cycles for alpha below 1.
- Cycles reads an image file itself, with OpenImageIO, unless the image is packed, generated, a movie or modified. Only then
  does it read Blender's buffer (`intern/cycles/blender/util.h:326-342`, `blender/shader.cpp:928-968`,
  `blender/image.cpp:46-227`). Painterly always reads Blender's buffer, through `Image.pixels`.
- No earlier experiment concerns images or colour. Experiment 005 fetched Blender 5.2.2 (`make blender`).

## Hypothesis

Every observable is a count, a set or an exact equality, so the decision rules need no tolerance and no statistical test, as
in experiment 005. The tolerances inside the classification of H2 are Cycles' own (`util/colorspace.cpp:412-441`).

- **H1. Blender's bundled Python imports PyOpenColorIO and loads Blender's own colour configuration, which names every colour
  space that Blender offers for images.**
  - Derivation: Blender's Cycles classifies colour spaces with OCIO's current configuration (`util/colorspace.cpp:281-383`),
    which inside Blender is Blender's own. Painterly's classification needs the same configuration in Python.
  - Observables, from `probe_blender.py` inside `blender -b --factory-startup`:
    - (a) whether `import PyOpenColorIO` succeeds;
    - (b) whether `PyOpenColorIO.Config.CreateFromFile(p)` succeeds for
```
