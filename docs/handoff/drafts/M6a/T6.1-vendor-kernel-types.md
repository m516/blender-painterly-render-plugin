# T6.1 — Vendor Cycles `kernel/types.h` and its data templates, with a CPU `KernelGlobals` shim and one kernel definition set
Milestone: M6a · Depends on: T3.1, T3.2, T3.3 · Parallel-safe: no

## Goal
After this card:
- Cycles' kernel data types compile, from verbatim files, in the `painterly` namespace:
  - `kernel/types.h` (`ShaderData`, `ShaderClosure`, `KernelData`, …), `kernel/features.h`, `kernel/data_template.h`,
    `kernel/data_arrays.h`, `kernel/svm/types.h`, `kernel/svm/node_types_template.h` and `kernel/globals.h`;
  - plus their include closure.
- `src/cycles/shim/kernel/device/cpu/globals.h` replaces upstream's CPU globals without the profiler, OSL or path guiding.
  Vendored kernel code reads `KernelGlobals kg` through it exactly as in Cycles (`kernel_data_fetch`, `kernel_data`, …).
- An INTERFACE library `cycles_kernel` carries the one global definition set. Every translation unit of a target that links
  `cycles_kernel` therefore compiles the same `KernelData` and `ShaderData` ("Definition set" says which targets must link it).
- Tests prove three things:
  - Cycles' and painterly's kernel types coexist in one translation unit.
  - Two targets compile one layout, and the check fails when they do not.
  - Every shim header is the file its upstream path resolves to. GCC (`make build`) and Clang check this in this card's
    acceptance. MSVC checks it in CI once the M6a branch is pushed: in the Windows wheel build, and, if the branch
    contains T2.10, in the `windows` job of `.github/workflows/ci.yml`, which also builds and runs the doctests.

M6a builds Cycles' shader VM as standalone vendored libraries. Nothing in the painterly engine uses these types yet: M6b
wires them into `painterly_trace_pixel`, `PainterlyScene` and the Blender sync.

## Definition set (Opus decision, 2026-10-09)
Preprocessor state changes the layout of `KernelData` and `ShaderData`:
- `kernel/types.h:11-16`, `829-833`, `1059-1080` and `1386-1405`;
- `kernel/features.h:173-216`.

Two translation units that disagree compile two different structs under one name, which is an ODR violation. So exactly one
definition set exists, and it is attached to `cycles_kernel`:

| Macro | Value | Why |
|---|---|---|
| `CCL_NAMESPACE_BEGIN`, `CCL_NAMESPACE_END` | `namespace painterly {`, `}` | from `cycles_util` (T3.2), unchanged |
| `__MAX_CLOSURE__` | `${PAINTERLY_MAX_CLOSURE}`, a CMake cache knob with default `64` | Cycles uses 64 when `__MAX_CLOSURE__` is undefined (`kernel/types.h:829-830`). The knob gives that value a name. |
| `__KERNEL_FEATURES__` | undefined | Upstream sets it only for runtime-compiled GPU kernels (`device/cuda/device_impl.cpp:231`, `device/hip/device_impl.cpp:218`, `device/metal/device_impl.mm:347`). Blender's CPU Cycles, which M6's golden tests compare against, compiles every guard of `features.h:125-147`, and painterly does the same. |
| `WITH_EMBREE`, `WITH_OSL`, `WITH_PATH_GUIDING`, `WITH_CYCLES_DEBUG_NAN`, `__KERNEL_GPU__` | undefined | `WITH_EMBREE` would add an Embree `device_bvh` to `KernelData` (`kernel/types.h:11-16`, `1393-1401`). Painterly's own Embree target (`painterly::embree`) never defines it. OSL, path guiding and GPU kernels are out of scope; the shim `#error`s on them. |

Consequences that later M6a cards rely on:
- `__OBJECT_MOTION__`, `__HAIR__`, `__POINTCLOUD__`, `__VOLUME__`, `__SUBSURFACE__`, `__SHADER_RAYTRACE__`,
  `__RAY_DIFFERENTIALS__`, `__DPDU__` and `__SVM__` are defined, as in upstream CPU builds.
- `features.h` could not undefine `__SHADER_RAYTRACE__` anyway. The generated SVM switch leaves out the
  ao/bevel/raycast cases instead.
- A target whose sources include any `kernel/` header links `cycles_kernel`. Nothing enforces this rule:
  - vendored `kernel/types.h:829-830` falls back to 64 closure slots when `__MAX_CLOSURE__` is undefined;
  - only the shim `kernel/device/cpu/globals.h` `#error`s on a missing `__MAX_CLOSURE__`, and a file that includes
    `kernel/types.h` without `kernel/globals.h` never reaches it;
  - so, with a non-default `PAINTERLY_MAX_CLOSURE`, a target that includes `kernel/types.h` without linking `cycles_kernel`
    compiles a second `ShaderData`. That is an ODR violation that no test detects.

For orientation only; tests never assert sizes. Opus's dry run of this card (Linux x86-64, GCC 13.3, `make build`) printed
`sizeof(ShaderData)` = 6480, `sizeof(KernelData)` = 2576, `sizeof(ShaderClosure)` = 96 and `sizeof(KernelGlobalsCPU)` = 3456.
In the skewed build (`__KERNEL_FEATURES__=0`), `ShaderData` shrinks to 6384, because `ob_tfm_motion` and `ob_itfm_motion`
vanish (`kernel/types.h:1075-1080`), and `features` reads 4576 instead of 511.

 * SPDX-License-Identifier: Apache-2.0 */

/* Modified by the Painterly project: upstream's kernel_array, the KernelGlobalsCPU members and the
 * kernel_data_* macros (kernel/device/cpu/globals.h:29-54, 102-106), without ProfilingState,
 * ThreadKernelGlobalsCPU, OSL and path guiding; KernelGlobals is const KernelGlobalsCPU *. */

#pragma once

#define PAINTERLY_SHIM_KERNEL_DEVICE_CPU_GLOBALS_H 1

#include "kernel/types.h"
#include "util/types_image.h"

/* The one configuration this shim supports: cycles_kernel's definition set (T6.1). */
#if defined(WITH_OSL) || defined(__OSL__) || defined(WITH_PATH_GUIDING) || \
    defined(__PATH_GUIDING__) || defined(WITH_EMBREE) || defined(__EMBREE__) || \
    defined(__KERNEL_GPU__)
#  error "kernel/device/cpu/globals.h shim: no OSL, path guiding, Embree or GPU kernels"
#endif
#ifndef __MAX_CLOSURE__
#  error "kernel/device/cpu/globals.h shim: link cycles_kernel, which defines __MAX_CLOSURE__"

/* Array for kernel data, with size to be able to assert on invalid data access. */
template<typename T> struct kernel_array {
  const ccl_always_inline T &fetch(const int index) const
  {
    kernel_assert(index >= 0 && index < width);
    return data[index];
  }

  ccl_always_inline void write(const int index, const T &value) const
  {
    data[index] = value;
  }

  T *data = nullptr;
  int width = 0;
};

/* Constant globals shared between all threads. Upstream's KernelGlobalsCPU without the profiler
 * state; painterly has no ThreadKernelGlobalsCPU. */
struct KernelGlobalsCPU {
#define KERNEL_DATA_ARRAY(type, name) kernel_array<const type> name;
#define KERNEL_DATA_ARRAY_WRITABLE(type, name) kernel_array<type> name;
#include "kernel/data_arrays.h"

  KernelData data = {};

  KernelImageLoadRequestedCPU image_load_requested_cpu;
};

using KernelGlobals = const KernelGlobalsCPU *;

/* Abstraction macros */
#define kernel_data_fetch(name, index) (kg->name.fetch(index))
#define kernel_data_write(name, index, value) (kg->name.write(index, value))
#define kernel_data_array(name) (kg->name.data)
#define kernel_data (kg->data)

CCL_NAMESPACE_END

### Shim markers
- Every header under `src/cycles/shim/` defines `#define PAINTERLY_SHIM_<P> 1` directly after `#pragma once`, with one blank
  line before and one after it.
  - `<P>` is the header's path relative to `src/cycles/shim/`, in POSIX form (`/` separators, as
    `path.relative_to(SHIM_DIR).as_posix()` gives it), upper-cased, with `/` and `.` replaced by `_`.
  - Example: `kernel/device/cpu/globals.h` gives `PAINTERLY_SHIM_KERNEL_DEVICE_CPU_GLOBALS_H`.
  - If a shim header has no `#pragma once`, stop and report it.
- Every later card that adds a shim header does three things:
  - it defines the marker in the header;
  - it adds `#include "<upstream path>"` to the direct-include block of `src/cycles/shim_markers.cpp` (its step 4), in path
    order;
  - it adds `static_assert(<marker> == 1, "<path> did not resolve to src/cycles/shim/<path>");` at the same position in
    the `static_assert` block that follows.
- `tests/core/test_shims.py` enforces the marker and the `static_assert`. The build enforces the `#include` of a header that
  nothing else in `shim_markers.cpp` reaches: without it, the `static_assert` names an undefined macro and does not compile.
- clang-format may wrap a long `static_assert` directly after `static_assert(`. The test ignores whitespace.
- Why: a shim shadows its upstream path only while the compiler finds no other file at that relative path first.
  - GCC and Clang look first in the including file's own directory.
  - MSVC looks first in the directories of every open includer, then in `/I`.
  - The `static_assert`s prove that each upstream spelling reached the shim. The three of steps 2 and 3 are reached through
    a vendored includer, and the rest directly.

/* Layout fingerprint of the vendored Cycles kernel types, recorded per translation unit.
 * Translation units that disagree compile different KernelData or ShaderData layouts, an ODR
 * violation. test_cycles_kernel_layout.cpp compares one recorded in painterly_tests with one
 * recorded in the library painterly_test_kernel_layout_probe. */

CCL_NAMESPACE_BEGIN

struct PainterlyKernelLayout {
  size_t max_closure; /* MAX_CLOSURE (kernel/types.h:829-833). */

   * __VOLUME__, __SUBSURFACE__, __SHADER_RAYTRACE__, __RAY_DIFFERENTIALS__, __DPDU__, __SVM__,
   * __EMBREE__, __OSL__, __PATH_GUIDING__, __KERNEL_FEATURES__. */

  size_t shader_closure_size, shader_closure_align;
  size_t shader_data_size, shader_data_align;
  /* offsetof(ShaderData, m) for m = P, N, Ng, wi, type, shader, flag, object_flag, num_closure,
   * num_closure_left, prim, u, v, object, time, ray_length, ray_P, ray_dP, lcg_state,
   * closure_emission_background, closure_transparent_extinction, closure (always last). */

  size_t kernel_data_size, kernel_data_align;
  /* offsetof(KernelData, m) for m = kernel_features, max_closures, max_shaders,
   * volume_stack_size, cam, bake, tables, light_link_sets, scene_time, background, bvh, film,
   * integrator, image, svm_usage. */
  size_t kernel_data_offsets[15];
  /* sizeof of KernelCamera, KernelFilm, KernelIntegrator, KernelBackground, KernelTables,

  size_t kernel_struct_sizes[8];

#endif

  features |= size_t(1) << 3;
#endif

#endif

#endif

  features |= size_t(1) << 6;
#endif
#ifdef __DPDU__
  features |= size_t(1) << 7;
#endif
#ifdef __SVM__
  features |= size_t(1) << 8;
#endif
#ifdef __EMBREE__
  features |= size_t(1) << 9;
#endif
#ifdef __OSL__
  features |= size_t(1) << 10;
#endif
#ifdef __PATH_GUIDING__
  features |= size_t(1) << 11;
#endif
#ifdef __KERNEL_FEATURES__
  features |= size_t(1) << 12;
#endif
  return PainterlyKernelLayout{
      .max_closure = MAX_CLOSURE,
      .features = features,
      .shader_closure_size = sizeof(ShaderClosure),
      .shader_closure_align = alignof(ShaderClosure),
      .shader_data_size = sizeof(ShaderData),
      .shader_data_align = alignof(ShaderData),

                              offsetof(ShaderData, wi),
                              offsetof(ShaderData, type),
                              offsetof(ShaderData, shader),
                              offsetof(ShaderData, flag),
                              offsetof(ShaderData, object_flag),
                              offsetof(ShaderData, num_closure),
                              offsetof(ShaderData, num_closure_left),
                              offsetof(ShaderData, prim),

                              offsetof(ShaderData, v),
                              offsetof(ShaderData, object),
                              offsetof(ShaderData, time),
                              offsetof(ShaderData, ray_length),
                              offsetof(ShaderData, ray_P),
                              offsetof(ShaderData, ray_dP),
                              offsetof(ShaderData, lcg_state),
                              offsetof(ShaderData, closure_emission_background),
                              offsetof(ShaderData, closure_transparent_extinction),
                              offsetof(ShaderData, closure)},
      .kernel_data_size = sizeof(KernelData),
      .kernel_data_align = alignof(KernelData),
      .kernel_data_offsets = {offsetof(KernelData, kernel_features),
                              offsetof(KernelData, max_closures),
                              offsetof(KernelData, max_shaders),
                              offsetof(KernelData, volume_stack_size),
                              offsetof(KernelData, cam),
