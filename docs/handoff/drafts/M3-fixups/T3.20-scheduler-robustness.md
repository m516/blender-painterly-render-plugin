# T3.20 — Scheduler robustness: lane clamp, knob checks, thread-pool error path, hit record, unknown lobe (TQ.1 F1–F8)
Milestone: M3 · Depends on: T3.12, TQ.1, T3.19 · Parallel-safe: no

## Goal
This card implements the audit's proposed card TQ.1-1 (`docs/audits/TQ.1.md`, findings F1–F8) and adds its tests. It runs
before T3.13, because T3.13–T3.16 build on `PainterlyPathTrace`.

- **F1 (High).** `lanes_per_row` in `src/painterly/integrator/path_trace.cpp` computes `(width + lane_length - 1) / lane_length`
  in `int`. For `lane_length > INT_MAX - width + 1` this overflows, which is undefined behaviour. In practice the result is 0
  lanes: `render_passes` renders nothing and still returns `true` with `passes_done` advanced. The audit reproduced this on the
  32×32 fixture with `lane_length = INT_MAX`. The fix clamps the lane length to `L = min(lane_length, width)`. The clamp is exact
  by SPEC §3: a lane of `L >= width` pixels is the whole row, with `lane_in_row = 0`. Its K0 is therefore the row chain's
  K0, so `lane:L` with `L >= width` equals `row` bit for bit. The oracle already clamps the same way
  (`std::min(o.chain_param, n)` in `src/app/smallpaint_oracle.cpp`).
- **F2.** The `catch` in the `PainterlyThreadPool` constructor (`src/painterly/util/thread_pool.cpp`) calls `request_stop()`
  and then rethrows. The destructor body does not run. The members are destroyed in reverse declaration order, so `mutex_`,
  `work_ready_` and `work_done_` are destroyed before `workers_` joins the threads that already started, while those threads
  may still be inside `work_ready_.wait`. The fix joins the workers in the `catch` (`workers_.clear()`) before rethrowing.
- **F3.** No test covers cancellation, the `pass_begin != passes_done` check, the constructor's validation, or
  `render_object_id`. This card adds doctests for all four.
- **F4.** `k0_phase_lock_bits` (q) is not validated. `1u << q` in `painterly_chain_start` is undefined for q < 0 or q >= 32.
  The constructor now requires `0 <= q <= PAINTERLY_K0_BITS`, which is the knob's domain (SPEC §3, §8; the T3.13 socket is
  "int, 0…22").
- **F5.** When an analytic primitive beats a triangle hit, `painterly_scene_intersect` (`src/painterly/kernel/bvh/bvh.h`)
  leaves the triangle's `prim`, `u`, `v` and `Ng` in a record whose `kind` is `HIT_ANALYTIC`. The record is now reset first.
- **F6.** An unknown `lobe.kind` matches no `case` in `painterly_trace_pixel` (`src/painterly/kernel/integrator/path.h`).
  The path then records no vertex, and the hit's emission is lost. A `default:` case now ends the path with the hit's
  emission, as at total internal reflection. The host side of F6 (the scene rejects unknown kinds) is already in T3.13's
  material validation ("known kinds"). This card does not touch it.
- **F7.** The kernel returns the literal `-1` for a miss, while the integrator defines `PAINTERLY_OBJECT_ID_MISS`. The
  constant moves to the kernel (`path.h`), keeping the same name, type and value. The kernel uses it, and
  `painterly/integrator/buffers.h` includes `path.h`.
- **F8.** The core accepts `max_depth = 0`, but the oracle (`--max-depth N >= 1`) and the T3.13 socket ("int, min 1") do not.
  The constructor now requires `max_depth >= 1`.

On valid inputs, everything except F1 is bitwise neutral. F1 changes output only for `lane_length > INT_MAX - width + 1`,
which used to render nothing. No oracle source changes, and default renders are byte-identical. The existing test cases,
including the determinism test in `test_path_trace.cpp`, and the whole of `test_path.cpp` stay unchanged and keep passing.
F2 has no unit test: thread creation cannot be made to fail deterministically.

       * pixels in global image coordinates. The clamp is exact: a lane_length of at least the width

      {
        return p.chain == CHAIN_ROW ? width : std::min(p.lane_length, width);
      }

      /* The number of lanes in one row (SPEC §3). ROW is one lane of the whole row. LANE is
       * ceil(width / L) lanes, the last one possibly shorter. A row of width 0 has no lanes; the early
       * return also keeps L = 0 out of the division. */
      int lanes_per_row(const KernelPainterlyIntegrator &p, const int width)
      {
        if (p.chain == CHAIN_ROW) {
          return 1;

        if (width == 0) {
          return 0;

                                                   std::numeric_limits<double>::infinity(),

        CHECK(isect.Ng.y == fresh.Ng.y);

      TEST_CASE("painterly path: an unknown lobe kind ends the path with the emission of its hit")
      {
        // With max_depth = 1 every path records one vertex, at its first hit. The backward evaluation
        // adds a zero child radiance to that vertex's emission term (SPEC §6), and x + (+-0) == x
        // bit for bit, so each pass adds exactly the first hit's emission term.
        Fixture first_hit(CHAIN_ROW, NO_LANE_LENGTH);
        first_hit.data.integrator.max_depth = 1;
        const PainterlyRenderBuffers expected = render_scene(first_hit, 1, one_batch());
        CHECK(std::any_of(
            expected.combined.begin(), expected.combined.end(), [](double v) { return v != 0.0; }));

        // Every lobe of every material gets the unknown kind. The default case ends each path at its
        // first hit with that emission term, and no path draws from K.
        Fixture unknown(CHAIN_ROW, NO_LANE_LENGTH);
        for (KernelPainterlyLobe &lobe : unknown.lobes) {
          lobe.kind = UNKNOWN_LOBE_KIND;

        const PainterlyRenderBuffers result = render_scene(unknown, 1, one_batch());
        CHECK(result.passes_done == PASSES);
        REQUIRE(result.combined.size() == expected.combined.size());
        CHECK(std::memcmp(result.combined.data(),
                          expected.combined.data(),
                          result.combined.size() * sizeof(double)) == 0);
        CHECK(std::all_of(
            result.k_consumed.begin(), result.k_consumed.end(), [](uint64_t k) { return k == 0; }));
