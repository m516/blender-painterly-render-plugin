# T3.19 — Zero-length diffuse direction: d = 0 stays 0 in the core and the oracle (SPEC §4)
Milestone: M3 · Depends on: T3.9, TQ.1, SPEC §4 "Zero-length d" (commit 696dc0c) · Parallel-safe: no

## Goal
Decision D33. The native first-light parity run (2026-10-10) compared 18 configurations bit for bit, and exactly three held
NaN. The 400 px, 64-pass image-chain renders `alpha_025`, `alpha_05` and `alpha_1` had 9, 21 and 15 NaN values: 3, 7 and 5
pixels with all three channels NaN (bits `0xfff8000000000000`). The positions were the same in the native core and in a fresh
`smallpaint_oracle --halton exact`. The cached `--halton incremental` renders of the same configurations had none. Two
instrumented probes confirmed the mechanism:
- vdc(K) = 0 exactly when K ≡ 0 mod 2^23 (SPEC §2). The draw is then u1 = u2 = 0, so s = (1, 0, 0).
- On a surface with N = −F·(1, 0, 0) exactly, d = N + F·s = (0, 0, 0). In the reference scene F = I, and the bottom plane has
  N = (−1, 0, 0) (SPEC §9).
- The rescale d·|d|^(−α) is then 0·pow(0, −α) = 0·∞ = NaN for α > 0. For α = 0, pow(0, −0) = 1, so d stays 0.

SPEC §4 now has the rule (commit 696dc0c): if d = 0, d stays 0, the rescale is not evaluated, cost = 0, the bounce contributes
nothing, and the path continues as it does for α = 0. This card implements it, with the same condition, in the two places
that evaluate the rescale:
- the core: `painterly_diffuse_bounce` (`src/painterly/kernel/closure/bounce.h:54`);
- the oracle: `trace()` (`src/app/smallpaint_oracle.cpp:288`). Both Halton modes run this one line, so one edit covers
  `--halton incremental` and `--halton exact`. `src/app/CHANGES.md` gets item 22.

Every other input stays bitwise unchanged. For d ≠ 0 the same expression is evaluated as before, and for α = 0 the rule gives
the old result, d·1 = d. D33 rejected ending the path at d = 0, because that would change K consumption for α = 0 exact
renders.

Where it occurs. Only a chain that reaches K = 2^23 can draw the zero.
- The image chain does. The 400 px reference consumes about 1.67e8 draws in 64 passes, so it crosses 2^23 about 20 times.
- Row and lane chains restart below 2^22 in every pass (SPEC §3) and consume far fewer than 2^22 draws per pass, so they do
  not reach it.
- `--halton incremental` never draws exactly 0 (SPEC §4).

The smallest reproduction was found with the dev oracle at commit 696dc0c and an instrumented copy of it outside the
repository:
- `--size 64 --passes 129 --seed 7 --chain image --halton exact --alpha 0.5`. 128 passes consume 8375930 draws and 129 consume
  8441263, so 129 is the smallest pass count that reaches K = 2^23 = 8388608. That draw falls on the bottom plane at pixel
  (row 12, col 11), pass 128, depth 9. It leaves NaN in the three channels of that pixel and nowhere else.
- The α = 0 counterpart is `--size 64 --passes 126 --seed 11 --chain image --halton exact`. Its draw K = 2^23 falls on the
  bottom plane at pixel (59, 19), pass 125, depth 0. The rule must leave this render byte-identical.

```cpp
// The oracle's diffuse lines with --alpha (trace() in src/app/smallpaint_oracle.cpp, items 13 and
// 22 of src/app/CHANGES.md): smallpaint's d = N + hemisphere(u1, u2), then d * |d|^-alpha, which
// is skipped for d = 0 (SPEC §4), then the cost of the rescaled d. Returns the cost.
double oracle_alpha_block(const smallpaint_bounce_ref::Vec &N,
                          smallpaint_bounce_ref::Vec &d,
                          const double u1,
                          const double u2,
                          const double alpha)
{
  d = (N + smallpaint_bounce_ref::hemisphere(u1, u2));
  if (d.x != 0 || d.y != 0 || d.z != 0) {
    d = d * std::pow(d.length(), -alpha);
  }
  return d.dot(N);
}
```

  // ZERO_DRAW_K0 is 0, so s = (1, 0, 0) and d = N + F s = (+0, +0, +0) exactly. The origin is a

    # The image chain is one chain (SPEC §3), so --threads must not change the output.
