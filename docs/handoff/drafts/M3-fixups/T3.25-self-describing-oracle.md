# T3.25 — Self-describing oracle renders: `meta.json` version 2 records the T3.4 knobs, one cited default per knob, experiment cache keys unchanged
Milestone: M3 · Depends on: T3.4, TQ.1, T3.19, T3.23, T3.24 (batch order D34: T3.19–T3.24 are committed) · Parallel-safe: no

## Goal
This card implements the audit's proposed card TQ.1-5 (`docs/audits/TQ.1.md`, finding F22) and the confirmed review-panel
finding #17. It also keeps the experiments' render cache valid, which a literal reading of TQ.1-5 would break.

- **F22: `meta.json` does not describe its render.** `write_meta()` in `src/app/smallpaint_oracle.cpp` omits the four T3.4
  knobs `diffuse_gain`, `emission_gain`, `ray_epsilon` and `max_depth`. T3.16 passes all four on every parity run, so a render
  directory inspected later cannot tell which values it used. After this card, `meta.json` records them right after `jitter`:
  doubles with `%.17g`, like `jitter`, and `max_depth` with `%d`. Its `oracle_version` becomes `"2"`, and
  `ORACLE_VERSION` in `analysis/painterly_analysis/experiment.py` becomes `"2"` too.
- **Panel #17: each default is written three times, and the values that apply carry no citation.** The globals `eps`,
  `g_jitter`, `g_diffuse_gain`, `g_emission_gain` and `g_max_depth` carry the smallpaint citations. The `Options` members
  repeat the same literals without one, and `usage_text` repeats them a third time. `oracle_main()` always overwrites the
  globals from `Options`, so the defaults that actually apply are the uncited ones (CLAUDE.md rule 2), and the three copies can
  drift apart. After this card there is one cited `constexpr` per default, defined next to the globals: `DEFAULT_RAY_EPSILON`,
  `DEFAULT_JITTER` (from `SMALLPAINT_JITTER_DIVISOR`), `DEFAULT_DIFFUSE_GAIN`, `DEFAULT_EMISSION_GAIN` and `DEFAULT_MAX_DEPTH`.
  The globals, the `Options` members and the usage text all take their values from these constants. The usage text becomes
  the printf format `usage_format`, and `usage_error()` fills in the defaults. The printed text changes in one place only: the
  `--ray-epsilon` default reads `0.0001` (`%g`) instead of `1e-4`.
- **The cache key and `ORACLE_VERSION` (checked for this card).** `experiment.job_key()` hashes the job's options, its seed,
  `"oracle_version": ORACLE_VERSION` and the oracle binary's sha256. The experiments render and load with
  `PAINTERLY_BUILD_DIR=.cache/oracle-build`. That binary is **not** rebuilt by this card (never run `make oracle`). It is the
  pre-T3.4 oracle of experiments 001–006 (sha256 `066bb5d4…`), has no T3.4 flags, and writes `oracle_version` `"1"`.
  - A literal bump breaks the experiments. With `ORACLE_VERSION = "2"` inside the key, every key of that unchanged binary
    changes. Measured with the key patched to `"2"`: the 848 cached job keys of experiments 001–006 gave 0 cache hits, and so
    did the 32 cached renders that the pre-registered 008 job list reuses and the 96 that 009 reuses. Experiment 007 renders
    nothing: its plan only calls `experiment.load()` on 006's renders, so its first `load()` would raise FileNotFoundError and
    007 could not run at all. 008 and 009 would render their reused jobs again with the old binary, whose `meta.json` would
    still say `"1"`.
  - The field adds nothing to the key, whose `oracle_sha256` changes with any change to `write_meta()`. Dropping the field
    would change the canonical JSON, and so every key, as well. So this card freezes the field at its present value, as
    `_KEY_ORACLE_VERSION = "1"`, and `ORACLE_VERSION = "2"` only states the version that this tree's `write_meta()` writes.
    Every job key stays byte-identical, and experiments 007–009 keep their cache hits. A new pytest pins that `job_key` does
    not read `ORACLE_VERSION`.
  - The cost that F22 names ("the rebuild invalidates `.cache/renders`") does not arise here. This card rebuilds only
    `build/dev`, and no experiment renders with it. Whenever the orchestrator rebuilds `.cache/oracle-build` later, the new
    sha256 changes every key, as any oracle rebuild does, whatever this card does.
  - `load()` is unaffected by the bump: `io.read_oracle()` parses `meta.json` as JSON and `OracleRender.passes` reads only
    `"passes"`. Nothing reads the four new keys or checks the version, so a version "1" render loads exactly as before. The new
    contract test `tests/oracle/test_oracle_contract.py::test_meta_json_records_the_knobs` checks that the version written by
    the dev oracle equals `experiment.ORACLE_VERSION`.
- **Output is unchanged.** Each constant is the literal it replaces, so every render is byte-identical: `sum.npy`,
  `k_consumed.npy`, `object_id.npy` and `image.ppm`, for the default `--size 64 --passes 2 --seed 7` and two other
  configurations (Steps 2 and 5). Only `meta.json` and the usage text change.
- **Moved citations.** The seven new lines go just before line 38 (`double eps`), so every oracle line from 38 on moves down by
  7. Two files written by T3.23 cite such lines:
  - `src/test/smallpaint_ref.h`. Four `// verbatim src/app/smallpaint_oracle.cpp:<range>` markers, which
    `tests/core/test_smallpaint_ref.py` checks against the source. The test fails on a stale range and names it.
  - `src/test/smallpaint_camcr_ref.cpp`. Two comment citations.

  The citations of lines 32 and 36 stay. All other insertions start at old line 562 (`write_meta`), and nothing cites a line
  from there on.

## Appendix B — `.cache/t3.25/cache_keys.py`
```python
"""T3.25 check (card Appendix B): the render-cache keys of every experiment's JOBS. Read-only.

Run it from the repository root with PAINTERLY_BUILD_DIR=.cache/oracle-build.
- stdout, one line per experiments/*/jobs.py: "<dir> keys=<n> sha256=<digest of the sorted keys>".
- stderr, one line per experiment: how many of those keys hold a finished render, and the
  meta.json "oracle_version" of the first finished job, read back with experiment.load().
"""

import hashlib
import sys
from pathlib import Path

from painterly_analysis import experiment

for jobs_file in sorted(Path("experiments").glob("*/jobs.py")):
    name = jobs_file.parent.name
    jobs = experiment.load_jobs_module(jobs_file).JOBS
    keys = sorted({experiment.job_key(job) for job in jobs})
    digest = hashlib.sha256("".join(key + "\n" for key in keys).encode("ascii")).hexdigest()
    print(f"{name} keys={len(keys)} sha256={digest}")
    done = [job for job in jobs if (experiment.cache_root() / experiment.job_key(job) / "done").is_file()]
    cached = len({experiment.job_key(job) for job in done})
    version = experiment.load(done[0]).meta["oracle_version"] if done else "-"
    print(f"{name} cached={cached}/{len(keys)} oracle_version={version}", file=sys.stderr)
```
