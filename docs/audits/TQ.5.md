## Method

- As TQ.4: static reading at `f5d101e`, tests first, plus read-only Python on text extracted with `git show`. Nothing in
  the repository was built or run: no Blender, `make`, pytest or import of the add-on. Reader H ran `ruff` and
  `clang-format` on extracted copies.
- Add-on reader: every file of `src/blender/addon/` (11 `.py` files, the preset, the manifest),
  `src/blender/python.cpp`, `_painterly.pyi`, the integrator and session sources, the smallpaint source, the cards
  T4.1-T4.4 and SPEC §0-§9. Compared with Cycles' add-on and `intern/cycles/blender/{session.cpp,camera.cpp,util.h}` in
  `.cache/vendor/`, and, for Blender's own `bl_ui`, `bl_operators/presets.py`, `addon_utils.py` and the OCIO config,
  with the installed 5.2.2 release, read as text. Seven small scripts re-derived the numbers: resolution rounding, the
  seed + frame bound, buffer sizes, the film chain's time and memory at 1080p, the sRGB curve against the OCIO config,
  SPEC §8 against the sockets, every numeric literal of the add-on.
- Tests and build reader: every file in scope, the stats of the six commits, `pyproject.toml`, both workflows, R76, the
  queue's T4.4 artifacts (`answer.md`, `audit.json`, `test.log`) and Blender 5.2.2's `bl_pkg/cli/blender_ext.py`. Nine
  scratch scripts, three of them mutation harnesses: the scripted poll-loop tests re-implemented against stubs of
  `session.py` (14 mutants), and the extracted `test_film.py` functions run against mutated copies of `film.py` (12
  mutants, and 8 constant changes).
- Landing reader (`6f37eec`, `f5d101e`): each commit's diff against the queue proposal byte for byte; each claim of
  `answer.md` against `test.log` and the tree; the IT's expected values re-derived (the jitter bits, the hex digits, the
  struct layout); `extension_platform` against Blender's own rule on 16 platform tags; the zip's size re-created in
  memory; the mutations of each new test.
- Searched for: tests that cannot fail (each finding names the mutation that survives), silent failure paths, false or
  stale comments, CLAUDE.md rule 2 and 3 violations, CI coverage, and differences from Cycles' add-on.
- Severity scale as in TQ.1, TQ.3 and TQ.4, with the user-visible case added: **Medium**, a gap that lets regressions
  through, a reproducibility problem with real cost, or a defect that a user of the add-on sees; **Low**, consistency or
  hygiene. Line numbers are at `f5d101e`.

## Verdict

No finding blocks the M4 review. M4's deliverable holds: the extension builds, installs into an isolated profile and
renders the reference scene bit for bit against the oracle in real Blender 5.2.2 (T4.4's IT, `1 passed`; landing 7's
fresh-clone check). M4.FB (blocking fix-ups) is empty; M4.FN is the four items M4-FIX-TQ5a to -TQ5d.

There are ten Medium findings. F1 and F2 change what a user sees in Blender: the engine registers no render pass, and
nothing in the UI reaches the display settings that the default output mode needs. F3 to F10 are gaps that let
regressions through: CI runs no bpy test (F3), the poll-loop tests never look at a partial render (F4), nothing asserts
that `unregister()` unregisters (F5), four tests pass only after an earlier test registered the add-on (F6), the build
tool has no test (F7) and leaves stale zips in `dist/` (F8), four reference knobs are pinned by no test (F9), and the
`uv` branch of the wheel build was never run (F10). The other 42 are Low.

The fix items are BACKLOG M4-FIX-TQ5a, -TQ5b, -TQ5c and -TQ5d. M3-FIX-TQ3f takes the leftovers of TQ3c's landing
(F48-F50, F52), and F51 amends M6a-FIX-TQ4a. Six items are deferred (below).
