# T2.9 — First three-platform CI run: Windows export rule, per-OS coexist, enforced glibc baseline, licence texts
Milestone: M2 · Depends on: T2.8 · Parallel-safe: no

## Goal
The first dispatch of `.github/workflows/wheels.yml` (run 37935120179, 2026-10-09) built, imported and tested wheels on
all three platforms. Two things went wrong:
- Windows failed **only** our symbol audit. The `.pyd` exports 19 nanobind symbols besides `PyInit__painterly`.
- Because one `wheels` job failed, GitHub skipped the `coexist` job on **every** OS, so gate G1 got no data.

The close-out review also found that the wheel lacks the full licence texts of the code it links statically, and that the
glibc-baseline check never runs on a manylinux-tagged wheel in CI.

After this card all four problems are fixed. CI is not run here; the orchestrator re-dispatches the workflow after the
commit.

## Read first
- `tools/symbol_audit.py`, `tests/core/test_symbol_audit_parsers.py`, `.github/workflows/wheels.yml`, `pyproject.toml`,
  `THIRD_PARTY_NOTICES.md`.
- nanobind 3.1.0: `.venv/lib/python3.13/site-packages/nanobind/include/nanobind/nb_error.h:35,99` (`class NB_EXPORT
  python_error`, `class NB_EXPORT builtin_exception`) and `nb_defs.h:27` (`NB_EXPORT` is `__declspec(dllexport)` on
  Windows, unconditionally).
- PEP 425 (compressed tag sets, e.g. `manylinux_2_27_x86_64.manylinux_2_28_x86_64`) and PEP 600 (legacy aliases).

## Modify
1. `tools/symbol_audit.py`, PE export rule.
   - The allowed exports are `PyInit__painterly` plus the members of nanobind's two `NB_EXPORT` exception classes.
     Those are the MSVC-decorated names that contain `@python_error@` or `@builtin_exception@` together with
     `@nanobind@@`, e.g. `??0python_error@abi1@nanobind@@QEAA@XZ` and `??_7builtin_exception@abi1@nanobind@@6B@`. Compile
     one named regex (`NANOBIND_EXCEPTION_EXPORT_PATTERN_WINDOWS`) for this.
   - Comment the reason:
     - nanobind marks these classes `NB_EXPORT`, which is `__declspec(dllexport)` on Windows (nanobind 3.1.0
       `nb_error.h:35,99`, `nb_defs.h:27`), so that exceptions can cross module boundaries;
     - a PE image's imports bind by DLL name, so an export cannot interpose into another module;
     - the rule still rejects every other export.
   - Update the rule string: `exports: PyInit__painterly and nanobind's NB_EXPORT exception classes only`. ELF and Mach-O
     rules are unchanged.
2. `tools/symbol_audit.py`, `_manylinux_baseline`.
   - Split the platform tag on `.` (PEP 425 compressed tag sets) and read every element.
   - Accept `manylinux_X_Y_<arch>`, and map the PEP 600 legacy aliases: `manylinux1` → (2, 5), `manylinux2010` →
     (2, 12), `manylinux2014` → (2, 17). Cite PEP 600 in a comment.
   - The baseline is the minimum (X, Y) over the set, because the wheel claims every tag in it.
   - An element that starts with `manylinux` but matches neither form still raises AuditError.
3. `tests/core/test_symbol_audit_parsers.py`.
   - The 19 export names of the failed Windows run, as a fixture: copy them from the run log, listed below.
     - With `PyInit__painterly` they pass.
     - Adding `rtcNewDevice` or `?foo@bar@@YAXXZ` fails.
   - Compressed tag sets:
     - `…-cp312-abi3-manylinux_2_27_x86_64.manylinux_2_28_x86_64.whl` gives (2, 27);
     - `…-manylinux_2_17_x86_64.manylinux2014_x86_64.whl` gives (2, 17);
     - `manylinux2014_x86_64` alone gives (2, 17);
     - `manylinuxfoo_x86_64` raises.
4. `.github/workflows/wheels.yml`.
   - `coexist` job: add `if: ${{ !cancelled() }}`. Each OS then runs whenever its own wheel exists. An OS whose wheel is
     missing fails at the download step, which is the right outcome.
   - Linux `ldd` check: replace the line with
     `test -x "$BLENDER_EXE" || exit 1; deps=$(ldd "$BLENDER_EXE") || exit 1; if grep 'not found' <<<"$deps"; then exit 1; fi`.
     The old line passed vacuously when ldd itself failed.
   - `wheels` job, Linux only, after cibuildwheel: a step `Audit the repaired wheel (glibc baseline)` that runs
     `python tools/symbol_audit.py wheelhouse/*.whl`. The test-command audits the installed module, which has no tag, so
     until now the manylinux baseline was never enforced in CI.
5. Licence texts.
   - Create `LICENSES/BSD-3-Clause-nanobind.txt`, a verbatim copy of
     `.venv/lib/python3.13/site-packages/nanobind-3.1.0.dist-info/licenses/LICENSE`.
   - Create `LICENSES/Apache-2.0-embree.txt`, a verbatim copy of `build/dev/_deps/embree-src/LICENSE.txt` (Embree v4.4.1).
     Run `make build` first if it is missing.
   - `pyproject.toml` `[project] license-files = ["LICENSE", "THIRD_PARTY_NOTICES.md", "LICENSES/*.txt"]`.
   - `THIRD_PARTY_NOTICES.md`:
     - the nanobind and Embree rows each name their `LICENSES/` file;
     - the Embree row reads "linked statically into `_painterly` through `cmake/painterly_embree.cmake` (used by
       `src/blender/selftest.cpp`; from T3.10 also by `src/painterly/bvh/embree.{h,cpp}`)".
   - Embree's `third-party-programs*.txt` cover components we do not build (TBB, OIDN, DPC++). Note that in one sentence
     of the Embree row; do not copy them.
