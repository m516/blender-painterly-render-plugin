# T2.8 — Experiment 005 instrument: the allocator-coherence rule for later runs
Milestone: M2 · Depends on: T2.7 · Parallel-safe: no

## Goal
`experiments/005-2026-10-08-native-coexistence/bindings.py` implements the rule in the README's section
"Amendment for later runs (Opus, 2026-10-09, after the 2026-10-08 run)". The pre-registered rule stays available, so the
recorded 2026-10-08 verdicts can still be reproduced. `run.sh` and the CI coexist job use the new rule.

## Modify (only these, plus the test file under Create)
1. `experiments/005-…/bindings.py`
   - `ALLOCATOR_FAMILY = frozenset({...})` with the ten names in the amendment. A comment cites glibc manual §3.2.5.
   - Extend `GLIBC_PROVIDER` with `libpthread.so.0`, `libdl.so.2`, `librt.so.1`, `libutil.so.1`, `libresolv.so.2`.
     These are separate glibc objects before glibc 2.34.
   - A second regex `ANY_BINDING`, which has the same shape as `BINDING` but any source object. Use it to collect
     `libc.so.6`'s allocator-family bindings in the same process's trace (see `coherent`), self-bindings included. Match the source by basename
     (`Path(src).name == "libc.so.6"`), never by substring.
   - CLI option `--rule {registered,coherent}`, default `coherent`.
     - `registered` is today's `is_violation` unchanged (Amendment 4), except that the five new `GLIBC_PROVIDER` names
       are only part of `coherent`. Keep the old regex as `GLIBC_PROVIDER_REGISTERED`, so `registered` reproduces
       2026-10-08 exactly.
     - `coherent` evaluates the allocator family as a whole, **per process**. Only `ld.<pid>` files that contain at least one
       `BINDING` match (a binding made by `_painterly`) contribute. Other processes' files are ignored, e.g. the `sh` child
       (`ld.30100`) of the 2026-10-08 trace, whose libc binds `malloc` to itself. Record the contributing file names in
       `bindings.json` as `allocator.processes`.
       Let D be the union, over the contributing files, of the destinations of the module's allocator-family bindings
       and of libc.so.6's allocator-family bindings.
       - If |D| == 1, every allocator-family binding of the module is allowed.
       - Otherwise every one of them is a violation.
       All other bindings follow the registered rule, using the extended `GLIBC_PROVIDER`.
   - `bindings.json` gains:
     - `rule`;
     - `allocator`: `{module_destinations: [...], libc_destinations: [...], coherent: bool}`;
     - when `--baseline <main bindings.json>` is given, `control_specific_violations`: the control's violations minus
       the baseline's, compared by (symbol, version, basename of destination), with the list and its count.
   - Update the module docstring to describe both rules and point to the README amendment.
2. `experiments/005-…/run.sh`
   - Pass `--rule coherent` explicitly in every `bindings.py` call.
   - Control runs pass `--baseline "$OUT/bindings.json"`.
   - The pass rule for an applicable control becomes `control_specific_violations.count >= 1`.
     Read it from that control's `bindings.json` with `python -I -c`.
   - Do not change anything else in run.sh.
3. `.github/workflows/wheels.yml`: the Linux trace step passes `--rule coherent`.

## Create
- `experiments/005-…/test_bindings.py`, a pytest on synthetic `ld.<pid>` lines written into `tmp_path`, with a stub
  module whose `undefined_symbols` is monkeypatched. No real trace is needed. Cases:
  1. module `malloc`, `free`, `posix_memalign` → proxy, and libc `malloc`, `free` → proxy: coherent, 0 violations.
  2. module `malloc` → proxy, libc `malloc` → libc.so.6 (self): incoherent, so the module's allocator bindings are violations.
  3. module `malloc` → proxy, module `free` → libc.so.6: incoherent.
  4. `pthread_create@GLIBC_2.2.5` → `libpthread.so.0`: allowed under `coherent`, a violation under `registered`.
  5. `__cxa_pure_virtual` → `libstdc++.so.6`: a violation under both rules.
  6. `--baseline` arithmetic: a control with {A, B} against a baseline {A} gives `control_specific_violations` == [B].
  7. A second `ld.<pid>` file with only `libc.so.6 → libc.so.6 malloc` lines and no `_painterly` line leaves case 1's result
     coherent with 0 violations.
  - Make pytest collect it. Add `experiments` to `testpaths` in `pyproject.toml` only if `experiments/*/test_*.py`
    is not collected yet, and say so in your report.
  - It must run under `make test`.
