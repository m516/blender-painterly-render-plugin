## Modify
1. **`__cxa_pure_virtual` leak** (`src/blender/CMakeLists.txt`, Linux `target_link_options`).
   - Add `-Wl,-u,__cxa_pure_virtual` with the comment: "Embree's vtables reference __cxa_pure_virtual only weakly, so the static libstdc++
     member would not be linked and the weak import would bind to the host process's libstdc++. A strong reference links our own copy
     (made local by --exclude-libs)."
   - Acceptance: `nm -D --undefined-only build/dev/src/blender/_painterly*.so | grep -c __cxa_pure_virtual` prints 0.
2. **Audit: ELF import rule as an allowlist** (`tools/symbol_audit.py`).
   - Parse `nm -D --undefined-only` and keep each symbol's version: split on the first `@` and drop a second leading `@`.
   - An undefined symbol is allowed iff one of:
     - its version starts with `GLIBC_`;
     - its name matches `^_?Py` (the Python C API, resolved from the interpreter or from Blender's executable);
     - its name is in `CRT_WEAK_HOOKS_LINUX = frozenset({"__gmon_start__", "_ITM_deregisterTMCloneTable", "_ITM_registerTMCloneTable", "__cxa_finalize"})`,
       commented as the toolchain's standard weak hooks.
   - Rule text: "imports: only glibc-versioned, Python C-API or toolchain weak hooks".
   - Prove that it now catches the leak: relink without `-Wl,-u,__cxa_pure_virtual` into a scratch dir and run the audit, which must FAIL naming `__cxa_pure_virtual`.
3. **Audit: Mach-O imports.**
   - Add a third check: run `nm -m -u <path>`. Every symbol marked `(dynamically looked up)` must match `^_+Py`; any other is reported as
     `<name>: flat-namespace lookup would bind into the host process`.
   - Check name `imports`.
4. **Audit: Windows.**
   - `ALLOWED_DLLS_WINDOWS = frozenset({"python3.dll", "kernel32.dll", "advapi32.dll"})`, with the comment "advapi32.dll: Embree enables
     SeLockMemoryPrivilege for huge pages (embree common/sys/alloc.cpp, called from kernels/common/device.cpp); a Windows system DLL, not one Blender ships."
   - Remove the api-ms-win-crt-* allowance and the `fnmatch` import. With `/MT` the UCRT is static, so such imports would mean the static CRT regressed.
5. **Audit: fail closed, consistent names.**
   - Export-table parsers raise `AuditError` on any non-empty line inside the table that they cannot parse.
   - The dependency check is named `dependencies` on all formats. The JSON key is `file_format`.
   - `_audit_pe` reuses `_export_violations`.
   - Constant order: `MODULE_SYMBOL`, `MACOS_MODULE_SYMBOL`, `CACHE_DIR`.
   - The docstring says the rules follow the binary's format and each format needs its platform tools (or `llvm-objdump` for PE).
6. **Parser tests.** Create `tests/core/test_symbol_audit_parsers.py`, importing the tool via `importlib.util.spec_from_file_location`. Use canned outputs:
   - `dumpbin /exports` and `/dependents`, including a `[NONAME]` row (expect AuditError);
   - `llvm-objdump --private-headers`;
   - `otool -L`;
   - `nm -m -u` (one Py symbol passes; `_rtcNewDevice` fails);
   - ELF `nm -D --undefined-only` with versions (`__cxa_pure_virtual` fails; `memcpy@GLIBC_2.14` and `PyLong_FromLong` pass).
7. **arm64 Embree** (`cmake/painterly_embree.cmake`). Embree refuses a static multi-ISA build under AppleClang, and `EMBREE_MAX_ISA=NEON2X`
   enables both NEON and NEON2X.
   - For arm64 set `EMBREE_MAX_ISA NONE`, then exactly one of `EMBREE_ISA_NEON` / `EMBREE_ISA_NEON2X` ON according to `PAINTERLY_EMBREE_MAX_ISA`. The default is `NEON2X`.
   - Cite Embree `CMakeLists.txt:494-520` in a comment, and delete the wrong comment.
8. **Modern FetchContent.**
   - `cmake_minimum_required(VERSION 3.28)`.
   - `FetchContent_Declare(embree ... GIT_SHALLOW TRUE EXCLUDE_FROM_ALL)` plus `FetchContent_MakeAvailable(embree)`. No more Populate/add_subdirectory and no CMP0169 warning.
   - Interface target: `add_library(painterly_embree INTERFACE)`, `target_link_libraries(painterly_embree INTERFACE embree)`, plus the alias.
9. **Oracle-only builds skip Embree.** In the root `CMakeLists.txt`, include `painterly_embree` only `if(PAINTERLY_BUILD_MODULE)`, and use `PROJECT_SOURCE_DIR`.
   Verify that `cmake -S . -B <scratch> -G Ninja -DPAINTERLY_BUILD_MODULE=OFF` creates no `_deps/embree-*`.
10. **CMP0091 line.** Delete `cmake_policy(SET CMP0091 NEW)`; it is NEW via `cmake_minimum_required`. Keep the runtime-library line and its comment.
11. **Makefile `audit`.** Pass exactly one module path: `$(firstword $(wildcard $(BUILD_DIR)/src/blender/_painterly*.so))`. Fail with a clear message if there is none.
12. **Selftest hardening** (`selftest.h/.cpp`, `python.cpp`).
    - Add `int tasking_system` from `rtcGetDeviceProperty(device, RTC_DEVICE_PROPERTY_TASKING_SYSTEM)` (Embree: 0 internal, 1 TBB, 2 PPL) and expose it as the key `tasking_system`.
    - Null-check every `rtcSetNewGeometryBuffer`; on failure release everything and return an error result. Never write through null.
    - Cite "SPEC §4, §5" for the parametric-t convention.
    - Move python.cpp's static wrappers into an anonymous namespace inside `CCL_NAMESPACE_BEGIN/END`, keeping `NB_MODULE` global.
13. **Selftest test criterion** (`tests/core/test_import.py`). Replace the float tolerance with the discriminating property:
    `assert abs(r["t"] - 0.5) < abs(r["t"] - 1.0)  # parametric (0.5) vs metric (1.0) distance along |d| = 2 (SPEC §4, §5)`.
    Also `assert r["tasking_system"] == 0  # EMBREE_TASKING_SYSTEM=INTERNAL`.
    Embree's hit t depends on the runtime ISA (its AVX2 kernels use explicit FMA), so no exact value is asserted.
14. `src/blender/CMakeLists.txt`: keep everything else.
