# T2.4 — Stable-ABI wheels on three platforms (cibuildwheel + GitHub Actions)
Milestone: M2 · Depends on: T2.3, T2.6 · Parallel-safe: no

## Goal
After this card:
- `uv build --wheel` produces `painterly_core-0.1.0-cp312-abi3-<platform>.whl` locally.
- A GitHub Actions workflow builds, audits and smoke-tests wheels on linux-x64 (manylinux_2_28), windows-x64 and macos-arm64.

## Modify
- `pyproject.toml`: add `[tool.cibuildwheel]`:
  - `build = "cp313-*"` (one build per platform; the abi3 tag makes it valid for ≥3.12);
  - `skip = "*-musllinux* *-win32 *_i686"`;
  - `build-verbosity = 1`;
  - `[tool.cibuildwheel.linux]`: `manylinux-x86_64-image = "manylinux_2_28"`, `archs = ["x86_64"]`, `repair-wheel-command = "auditwheel repair -w {dest_dir} {wheel}"`;
  - `[tool.cibuildwheel.macos]`: `archs = ["arm64"]`, `environment = { MACOSX_DEPLOYMENT_TARGET = "11.0" }`;
  - `[tool.cibuildwheel.windows]`: `archs = ["AMD64"]`;
  - `test-command = "python -m pytest {project}/tests/core/test_import.py -q && python {project}/tools/symbol_audit.py <installed module path>"`.
    Reuse the same selftest criterion as the unit test (T2.5), not a new tolerance.
  - Make sure the scikit-build-core wheel build still sets `PAINTERLY_BUILD_TESTS=OFF` and `PAINTERLY_BUILD_ORACLE=OFF`.
- `Makefile`: `wheel:` → `uv build --wheel --out-dir dist/`.

## Modify (additionally)
- `tools/fetch_blender.py`:
  - `--platform linux-x64` (tar.xz, existing).
  - `--platform macos-arm64`: `.dmg`. Verify the sha256, `hdiutil attach -nobrowse -readonly`, copy `Blender.app` into `.cache/blender/`, detach.
  - `--platform windows-x64`: `.zip`. Extract with `zipfile` into a staging directory, then move it into place.
  - Every platform prints the executable path.
  - Windows: report whether `python3.dll` ships next to Blender's Python. An abi3 module needs it. The coexist job fails clearly if it is missing.

## Create
- `.github/workflows/wheels.yml`:
  - Triggers: `push` to tags `v*`, `workflow_dispatch`, and `pull_request` touching `src/**`, `cmake/**`, `CMakeLists.txt`, `pyproject.toml`.
  - Matrix: `ubuntu-24.04`, `windows-2022`, `macos-14`.
  - Steps: checkout, then `pypa/cibuildwheel@<pinned tag found via git ls-remote --tags https://github.com/pypa/cibuildwheel.git>`, then `actions/upload-artifact@v4` with name `wheel-${{ matrix.os }}`.
  - Cache only the **Embree source**, never compiled objects: cibuildwheel builds in a container on a copy of the project, and objects
    would risk an ABI mismatch.
    - A step runs `git clone --depth 1 --branch v4.4.1 https://github.com/RenderKit/embree.git .cache/src/embree`, guarded by
      `actions/cache` on `.cache/src/embree` with key `embree-src-${{ hashFiles('cmake/painterly_embree.cmake') }}`.
    - Pass `FETCHCONTENT_SOURCE_DIR_EMBREE={project}/.cache/src/embree` via `CIBW_ENVIRONMENT` or `[tool.scikit-build.cmake.define]`.
  - **Coexistence job per OS** (G1 must be decided on all three platforms). Add a second job `coexist`, with `needs: wheels` and the same
    matrix. On each OS:
    1. download the Blender 5.2.2 release for that platform from download.blender.org and verify its `.sha256`;
    2. extract `_painterly` from the built wheel into a directory;
    3. run `<blender> -b --factory-startup --python-exit-code 1 --python experiments/005-*/coexist.py -- <dir>`;
    4. upload `out/coexist.json` as an artifact.
    Linux also runs `bindings.py`. macOS and Windows rely on the audit plus the coexistence run.

## Acceptance
- `make wheel` produces exactly one `dist/painterly_core-0.1.0-cp312-abi3-linux_x86_64.whl`.
- In a fresh `uv venv .cache/wheeltest --python 3.13`, install the wheel and print `_painterly.selftest()`. Check `abs(t - 0.5) < abs(t - 1.0)`
  and `tasking_system == 0`. Embree's t depends on the ISA (T2.5).
- `tools/symbol_audit.py dist/*.whl` passes.
- The YAML parses. `make check` passes.
