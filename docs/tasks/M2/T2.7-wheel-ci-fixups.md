## Goal

- the wheel ships the third-party notices;
- the CI coexist job tests H1 as well as H2, installs Blender's system libraries on Linux, and decides the Windows

- the build requirements are pinned to `uv.lock`.

## Modify (only these, plus the two files under Create)
1. `pyproject.toml`
   - `[project]`: add `license-files = ["LICENSE", "THIRD_PARTY_NOTICES.md"]`.
   - `[build-system] requires`: pin both to the exact versions in `uv.lock`, i.e. `scikit-build-core==<lock>` and `nanobind==<lock>`.
     Read the versions from `uv.lock`; do not guess them.
   - `[tool.cibuildwheel]`: add `test-environment = { PAINTERLY_TEST_INSTALLED = "1" }`.
   - Replace the comment sentence "CMAKE_ARGS is the only channel that reaches CMake through scikit-build-core: …"
     with: "CMake turns a relative untyped `-D` PATH value into an absolute one against the working directory, which is
     the project root under the build backend, so the relative path is the same on every platform."
2. `tests/conftest.py`: do not insert the build directory into `sys.path` when `os.environ.get("PAINTERLY_TEST_INSTALLED") == "1"`.
   Document the variable in the module docstring.
3. `tests/core/test_import.py`: add `test_module_origin`.
   - When `PAINTERLY_TEST_INSTALLED == "1"`, it asserts that `"site-packages" in Path(_painterly.__file__).parts`.
   - Otherwise it asserts that `Path(_painterly.__file__)` is inside the build directory resolved as in `conftest.py`.
   - Expose that resolved directory from `conftest.py` as a module-level `BUILD_DIR`, so the test does not repeat the rule.
4. `tests/core/test_build_requirements.py` (new): `build-system.requires` pins exactly the `uv.lock` versions of
   scikit-build-core and nanobind. Parse both files with `tomllib`.
5. `tools/symbol_audit.py`
   - Reword the dependency rule string to `glibc only (manylinux_2_28 baseline)`.
   - Add a check `glibc_versions` to the ELF audit.
     - When the input is a wheel whose platform tag is `manylinux_X_Y_<arch>` (parse the wheel filename per PEP 427),
       every imported `GLIBC_a.b[.c]` version must be ≤ (X, Y), compared as integer tuples.
     - For a bare module, or a wheel with a `linux_<arch>` tag (which is what a local `uv build` produces), the check
       passes and its rule string reports the highest imported version, for information:
       `highest imported GLIBC_2.38 (no manylinux tag to check against)`.
     - Thread the tag through `_audit_input` → `_audit_module` → `_audit_elf` as an optional argument. Do not use a global.
   - Tests in `tests/core/test_symbol_audit_parsers.py`, all on synthetic `nm` output:
     - versions 2.17, 2.28 under manylinux_2_28 pass;
     - 2.29 under manylinux_2_28 fails, and the message names the symbol;
     - 2.3.4 parses as (2, 3, 4) and passes;
     - wheel filename parsing for `…-cp312-abi3-manylinux_2_28_x86_64.whl` and `…-linux_x86_64.whl`.
6. `tools/fetch_blender.py`
   - `--print-path-only` help: `stdout carries only the executable path, with no network or file access (used by run.sh)`.
   - `_download`: if anything raises (`except BaseException`), `partial.unlink(missing_ok=True)` before re-raising.
   - `--platform` default: the host platform, from a mapping table `{("linux", "x86_64"): "linux-x64", ("darwin", "arm64"): "macos-arm64", ("win32", "amd64"): "windows-x64"}`.
     Use `sys.platform` and `platform.machine().lower()`. If the host is not in the table, there is no default and `--platform` is required.
   - Replace `_report_python3_dll`. The new function prints one line per `python3.dll` and `python3??.dll` found under the
     install (`rglob`), with its path relative to the install. Then it prints exactly one of these lines, with no MISSING
     wording:
     - `python3.dll next to blender.exe: yes|no`;
     - `python3.dll in blender.shared: yes|no`.
     Blender's process (blender.exe) loads `_painterly`, so its DLL search directories are the ones that matter, not python.exe's.
7. `.github/workflows/wheels.yml`
   - Linux only, before "Fetch Blender": `sudo apt-get update && sudo apt-get install -y $(cat tools/blender_system_deps.txt)`.
     After the fetch: `if ldd "$BLENDER_EXE" | grep 'not found'; then exit 1; fi`.
   - Fetch step: remove the `grep -q MISSING … exit 1` block.
   - New step after "Run the coexistence experiment in Blender", on every OS: **H1 on CI**. It uses setup-python's 3.13,
     which is abi3-compatible:
     ```
     python -I -c "import json, sys; sys.path.insert(0, sys.argv[1]); import _painterly; ref = dict(_painterly.selftest()); got = json.load(open(sys.argv[2]))['selftest']; print(ref, got); sys.exit(0 if ref == got and ref['tasking_system'] == 0 else 1)" "$MODULE_DIR" "$EXP_DIR/out/coexist.json"
     ```
     Check first which key `coexist.py` writes the selftest under, and use that key.
   - Step after a failed coexist run (`if: failure() && matrix.platform == 'windows-x64'`): print fetch.log's python3
     lines and coexist.json's `error` field (if the file exists) as `::error::` annotations.
   - Upload step: use `${{ env.EXP_DIR }}/out/…` instead of the literal directory in all three paths.
8. `src/blender/python.cpp`: `version_info()["compiler"]` is `"<id> <version>"` for every compiler: `GCC 13.3.0`,
   `Clang 18.1.3`, `AppleClang 15.0.0`, `MSVC 194435207`.
   - Build it with preprocessor branches. Test `__clang__` before `__GNUC__`, because Clang also defines `__GNUC__`.
     - Clang: `__clang_major__.__clang_minor__.__clang_patchlevel__`. Apple's Clang defines `__apple_build_version__`; report it as AppleClang.
     - GCC: `__GNUC__.__GNUC_MINOR__.__GNUC_PATCHLEVEL__`.
     - MSVC: `_MSC_FULL_VER`.
     - Any other compiler: `#error`.
   - Add a pytest in `tests/core/test_import.py` that the compiler string matches `^(GCC|Clang|AppleClang|MSVC) \d+(\.\d+)*$`.
