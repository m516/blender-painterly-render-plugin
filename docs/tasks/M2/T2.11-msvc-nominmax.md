# T2.11 — Windows: `NOMINMAX` for every consumer of vendored Cycles, and a keep-going MSVC CI build
Milestone: M2 · Depends on: T2.10 · Parallel-safe: no

## Goal
After T2.10, `cycles_util` compiles with MSVC: CI run 38003046949 compiled `aligned_malloc.cpp` and `guarded_allocator.cpp`.
The next failures all have one cause. `<windows.h>` defines function-like macros `min(a,b)` and `max(a,b)` unless `NOMINMAX` is
defined, and those macros break every later declaration or call spelled `min(` or `max(`.
- CI `windows` job, the first translation unit Ninja reached: `src/painterly/util/thread_pool.cpp(20): error C2589: '(': illegal
  token on right side of '::'`, at `std::max(int(std::thread::hardware_concurrency()), 1)`. The macro comes in through
  `painterly/util/thread_pool.h` → shim `util/thread.h:23` → `util/windows.h:16` → `<windows.h>`.
- Wheels run 38003053457 (`wheels (windows-2022)`). MSBuild keeps building other projects after a failure, so it shows all
  148 errors. Every one is at a `min`/`max` spelling:
  - `third_party/cycles/util/math_base.h:124-189`, Cycles' own `min`/`max` overloads;
  - `math_base.h:923`, `Extrema(T value) : min(value), max(value)`;
  - `third_party/cycles/util/simd.h:110,121`, `std::numeric_limits<int>::min()/max()`;
  - `thread_pool.cpp:20`, as above.
- Upstream never meets this, because Blender defines `NOMINMAX` for every source on Windows (Blender v5.2.2
  `build_files/cmake/platform/platform_win32.cmake:133-142`, `add_definitions(... -DNOMINMAX)`). Cycles' `util/windows.h`
  defines `NOGDI` and `WIN32_LEAN_AND_MEAN` itself, but not `NOMINMAX`.

The fix restores that definition for every target that sees the vendored headers. It also makes the CI MSVC build keep going
after a failure, so that one run reports every failing translation unit. Run 38003046949 reported one, and finding the rest
took a second hour-long run.

Not needed: the other definitions in that Blender block.
- `_USE_MATH_DEFINES`: no compiled vendored or painterly code uses `M_PI`-style macros; they appear only in comments of
  `math_fast.h`.
- `_CRT_*_NO_DEPRECATE` and `_SCL_*`: silence warnings only.
- `_CONSOLE` and `_LIB`: Blender's application settings.
- `WIN32_LEAN_AND_MEAN`: already in `util/windows.h`.

## Read first
- `src/cycles/CMakeLists.txt` (the `if(MSVC)` block from T2.10 just after the `CCL_NAMESPACE_*` definitions).
- `third_party/cycles/util/windows.h`, `third_party/cycles/util/math_base.h:120-190`, `src/cycles/shim/util/thread.h:15-30`.
- `.github/workflows/ci.yml`, the `windows` job.

## Modify
1. `src/cycles/CMakeLists.txt`. Directly after the T2.10 `if(MSVC) ... /FImemory ... endif()` block, add:
   ```cmake
   # Windows: <windows.h> (reached through util/windows.h, e.g. from util/thread.h) defines the macros min(a,b) and max(a,b)
   # unless NOMINMAX is defined, which breaks Cycles' own min/max overloads (util/math_base.h) and every std::min/max call.
   # Upstream defines NOMINMAX for every Windows source (Blender v5.2.2 build_files/cmake/platform/platform_win32.cmake:133-142).
   # PUBLIC, because every consumer includes these headers.
   if(WIN32)
     target_compile_definitions(cycles_util PUBLIC NOMINMAX)
   endif()
   ```
   `WIN32` (not `MSVC`) is the right condition: the macros come from the Windows SDK header, whatever the compiler.
2. `.github/workflows/ci.yml`, `windows` job, step "Build the C++ libraries and unit tests with MSVC".
   - Replace the line `cmake --build build/msvc || exit /b 1` with `cmake --build build/msvc -- -k 0 || exit /b 1`.
   - Add one comment line above the step's `run:` key:
     `# -k 0: Ninja keeps building after a failure, so one run reports every failing translation unit (as MSBuild does).`
   - Nothing else in `ci.yml` changes.

Do not change any other file. `third_party/`, `wheels.yml` and `pyproject.toml` stay as they are.
