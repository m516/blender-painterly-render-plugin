# T2.3 — Fetch Blender 5.2.2 and run the coexistence experiment
Milestone: M2 · Depends on: T2.2 · Parallel-safe: no · Experiment slug: `native-coexistence`

## Goal
After this card:
- `tools/fetch_blender.py` provides a verified Blender 5.2.2 Linux binary under `.cache/`.
- An experiment shows that `_painterly` loads and works inside Blender's process next to Blender's own Cycles. If it does not, the experiment shows exactly how it fails, which triggers gate G1 in docs/plan.md.

## Create
- `tools/fetch_blender.py`. CLI `[--version 5.2.2] [--platform linux-x64]`.
  1. Download `https://download.blender.org/release/Blender{major.minor}/blender-{v}-{platform}.tar.xz` to `.cache/blender/`.
  2. Verify it against `blender-{v}.sha256` from the same directory.
  3. Extract to `.cache/blender/blender-{v}-{platform}/`.
  4. Print the absolute path of the `blender` executable.
  It is idempotent: it skips work when the file is already present and verified.
- `Makefile`: target `blender:` runs the fetch tool. Export `BLENDER ?= $(shell .venv/bin/python tools/fetch_blender.py --print-path-only)`, adding that flag to the tool.
- An experiment directory following `docs/tasks/M1/_experiment_protocol.md`, numbered next, slug `native-coexistence`, with:
  - `coexist.py`, run as `$BLENDER -b --factory-startup --python-exit-code 1 --python coexist.py -- <build_dir>`. It:
    1. Inserts `<build_dir>/src/blender` at the front of `sys.path`, imports `_painterly`, and records `version_info()` and `selftest()`.
    2. Sets the scene to CYCLES, CPU device, 64×64, 4 samples, and writes PNGs to `out/` (git-ignored).
    3. Repeats 20 times: `bpy.ops.render.render(write_still=False)` (Cycles), then `_painterly.selftest()`. Every selftest must equal the first.
    4. Writes `out/coexist.json` with Blender's version, `bpy.app.build_platform`, the results, and per-iteration timings.
  - A `run.sh` that runs coexist.py twice:
    - plainly;
    - with `LD_DEBUG=bindings LD_DEBUG_OUTPUT=out/ld`.
    Then it greps the bindings log for **any** symbol binding *from* `_painterly` *to* a Blender library (`blender`, `libtbb*`, `libembree*`, `libOpenImageIO*`, `libOpenColorIO*`, `libusd*`) and writes the count to `out/bindings_summary.txt`. The expected count is 0.
- README hypotheses to pre-register:
  - **H1.** `_painterly` imports and `selftest` returns `t = 0.5`, `hit = true` inside Blender 5.2.2.
  - **H2.** 20 alternating Cycles renders and `_painterly` selftests complete with exit code 0.
  - **H3.** Zero symbol bindings from `_painterly` into Blender-shipped libraries.
  Derive each from docs/plan.md "Isolation" and the research facts: Blender links `libembree4.so.4` and `libtbb.so.12` dynamically and exports `ccl::` symbols on macOS.

## Notes
If Blender fails to start because of missing system libraries:
1. Run `ldd` on the binary.
2. Install the missing packages with `sudo apt-get install -y …`.
3. List them in the README Method section and in a new `tools/blender_system_deps.txt`.
