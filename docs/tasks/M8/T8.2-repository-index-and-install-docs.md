# T8.2 — Remote repository: `server-generate` index with absolute release URLs on GitHub Pages, install guide
Milestone: M8 · Depends on: T8.1 (and through it T4.4); T7.5 is deferred past v1.0 by decision D8 (Micah, 2026-10-26), and Step 5's insertion point, before `## Layout`, holds without it · Parallel-safe: no

## Goal
After this card:
- `tools/repo_index.py generate` turns the three extension zips of a release into Blender's remote-repository index.
  It runs `blender --command extension server-generate` over exactly those zips. Then it rewrites every `archive_url`
  from Blender's relative `./<zip>` to the zip's absolute download URL in the GitHub Release `v<version>`, orders the
  entries by platform, and verifies every byte of the result against the zips.
- `.github/workflows/release.yml` builds and verifies that index in its `package` job in every mode, and uploads it as
  the workflow artifact `site`. `.github/workflows/static.yml` is the only Pages publisher: `release.yml` calls it through
  `workflow_call` after `publish` has created the release, and every deployment carries the repository tree plus the
  latest release's index and archives. A release deploys only in `mode=release`, after `publish`, and only once a
  check job has confirmed that the release is the Latest one and has downloaded every archive URL of the index from the
  published Release. The index is served at `https://m516.github.io/blender-painterly-render-plugin/index.json`.
- `publish` attaches `index.json` to the GitHub Release beside its five assets, so a deployment never depends on an
  artifact that has expired.
- `docs/install.md` tells users how to add that remote repository in Blender's Preferences, how updates arrive, how to
  install from disk, and what each platform needs. `README.md` links to it.
- A fast test validates the index logic against synthetic zips, the workflow structure and the install guide. A slow test
  runs real Blender 5.2.2 end to end through `file://` URLs:
  1. build the release zips;
  2. generate the index;
  3. add it as a remote repository;
  4. install from it;
  5. publish a newer index and update to it;
  6. show that a tampered archive and a missing platform entry are both refused.

- **Verified by Opus on Blender 5.2.2, 2026-10-10.** These were tested with split zips built from a T4.1 manifest and
  T8.1's synthetic wheels, in isolated `BLENDER_USER_RESOURCES` directories. The card relies on each of them:
  1. `blender --command extension server-generate --repo-dir D`, with no `--html` and no `blender_repo.toml` in D, writes
     `D/index.json`. The file is `json.dump({"version": "v1", "blocklist": [], "data": [...]}, fh, indent=2)`, with no
     trailing newline. It holds one entry per `*.zip` of D (names starting with `.` are skipped), **in `os.scandir`
     order**: one run gave `macos_arm64, linux_x64, windows_x64`. The command prints `found 3 packages.` and exits 0. An
     archive that fails validation is only logged and skipped, and the exit status is still 0, so the entry count is our
     check.
  2. Each entry is built from the zip's `blender_manifest.toml`. First `[build.generated]` replaces `platforms` and `wheels`
     (`pkg_manifest_dict_apply_build_generated_table`). The entry then holds every field of `PkgManifest` that the manifest
     sets, except `wheels`. Blender adds `python_versions`: `["3"]` for an abi3 wheel, because `python_versions_from_wheel`
     returns only the major version of an abi3 tag. It also adds `archive_url = "./" + pathname2url(<zip name>)`,
     `archive_size` (bytes) and `archive_hash = "sha256:" + <lowercase hex>`. `build` is not a `PkgManifest` field and is
     dropped. Rebuilding the three entries with this rule reproduced Blender's exactly, key order included. So did
     re-serializing the file with `json.dumps(index, indent=2)`.
  3. The client resolves an `archive_url` that starts with `./` against the repository URL. Any other value is used as
     given (`subcmd_client.install_packages`). Downloads go through `urllib.request.urlopen`, which follows redirects, and
     GitHub's release download URLs redirect. An absolute `file://` archive URL in a `file://` repository installs.
  4. A remote repository's URL is fetched as given. For `https://` URLs Blender appends
     `?platform=<p>&blender_version=<v>&python_version=<v>` (`url_append_query_for_blender`), and only `file://` URLs get
     `/index.json` appended. A static site therefore needs the full index URL.
  5. From the command line (`--command`), `list --sync`, `install` and `update` need `--online-mode`, even when the only
     repository is `file://`. With no active repository, the poll assumes online access. Without the flag the sync fails
     with `Online access required to check for updates.` If `repo-add <id> --clear-all --url file://…/index.json` has made
     that repository the only one, nothing touches the network.
  6. Blender lists only the entries compatible with the running platform, Blender version and Python version. With the
     host platform's entry missing from the index, `install painterly` exits 1 and prints
     `Package "painterly" not found in remote repositories!`.
  7. An archive whose size or SHA-256 differs from its entry is refused. Blender prints
     `FATAL_ERROR Archive size mismatch "painterly", expected N, was M` or `FATAL_ERROR Archive checksum mismatch "painterly", …`
     and installs nothing, **but the exit status is 0**. The installed directory decides.
  8. `install painterly` (without `-e`) unpacks into `<BLENDER_USER_RESOURCES>/extensions/<repo id>/painterly/`, whose
     manifest is the zip's own (e.g. `[build.generated] platforms = ["linux-x64"]`).
     - Once the index lists another version, `list --sync` prints `painterly [outdated: <old> -> <new>]`.
     - `update` then prints `Reinstalled "painterly"` and leaves `<new>` installed. Afterwards `list` prints
       `painterly [installed]`.
     - Blender's test is inequality, not order: `is_outdated = item_local_version != item_version` (`bl_extension_cli.py`,
       `bl_extension_ui.py`). An index with an *older* version would therefore offer a downgrade.
  9. The CLI prints no colour codes when stdout is not a TTY or when `NO_COLOR` is set.
  10. Labels, read from Blender 5.2.2's RNA and UI code:
      - Preferences sections **Get Extensions** and **System**. **Allow Online Access** sits in **System → Network**.
      - The **Get Extensions** header has a **Repositories** popover, whose **+** offers **Add Remote Repository**. The
        dialog "Add New Extension Repository" has **URL**, **Check for Updates on Startup**, **Requires Access Token** and
        the button **Create**.
      - Creating the repository syncs it at once. From `https://m516.github.io/blender-painterly-render-plugin/index.json`

      - The header menu (⌄) holds **Refresh Remote**, **Refresh Local**, **Install Available Updates** and

### The index (`index.json`), as deployed
- Exactly `json.dumps(index, indent=2) + "\n"`, UTF-8: Blender's own formatting (fact 1) plus a final newline.
- `index = {"version": "v1", "blocklist": [], "data": [<linux-x64>, <macos-arm64>, <windows-x64>]}`: one entry per
  platform, in `RELEASE_PLATFORMS` order.
- Each entry equals Blender's `server-generate` entry for that zip (fact 2), except `archive_url`, which is
  `release_base_url(repository, version) + <zip name>`. Nothing else is added or removed.
- Workflow artifact `site`: exactly `index.json`. Built in every mode; attached to the Release by `publish` and
  deployed to Pages (through `static.yml`) only when `mode=release`.

### `tools/repo_index.py` command line
```
python -I tools/repo_index.py generate --blender PATH --assets-dir DIR (--repository OWNER/NAME | --base-url URL)
        [--out-dir dist/site] [--work-dir build/repo-index]
    Writes and verifies <out-dir>/index.json; <out-dir> must not exist yet. Runs Blender in <work-dir>/repo.
    stdout: the path of index.json, one line. Blender's output goes to stderr.
python -I tools/repo_index.py verify --index PATH --assets-dir DIR (--repository OWNER/NAME | --base-url URL)
    stdout: nothing; exit 0 when the index matches the zips of DIR.
python -I tools/repo_index.py check-urls --index PATH
    Downloads every archive_url and compares its size and SHA-256 with the index. stdout: "<url>: OK" per entry.
python -I tools/repo_index.py base-url --repository OWNER/NAME     # stdout: release_base_url(R, <version>) + "\n"
python -I tools/repo_index.py pages-url --repository OWNER/NAME    # stdout: pages_index_url(R) + "\n"
    <version> is release_version(REPO_ROOT). Every subcommand: on failure, nothing on stdout,
    "repo_index: <reason>" on stderr, exit 1.
```

Sibling tools, loaded once at import:
```python
TOOLS_DIR = Path(__file__).resolve().parent
REPO_ROOT = TOOLS_DIR.parent


def _load_tool(name: str) -> ModuleType:
    # Under `python -I` the script's directory is not on sys.path, so the sibling tools are
    # loaded by file path. Each is registered in sys.modules under a private name before it
    # runs, so code that looks its own module up there works.
    path = TOOLS_DIR / f"{name}.py"
    spec = importlib.util.spec_from_file_location(f"_painterly_tool_{name}", path)
    module = importlib.util.module_from_spec(spec)
    sys.modules[spec.name] = module
    spec.loader.exec_module(module)
    return module


_build_extension = _load_tool("build_extension")
_release = _load_tool("release")
```

Functions, in this order:
- `release_tag(version)` = `f"v{version}"`, T8.1's release tag (`RELEASE_TAG`). Comment that a dry-run tag never gets a
  Release, so the index always points at `v<version>`, in every mode.
- `_split_repository(repository)` (private): `REPOSITORY_FORM.fullmatch`. If there is no match, raise
  `RepoIndexError(f"repository {repository!r} is not OWNER/NAME")`. Otherwise return `(owner, name)`.
- `release_base_url(repository, version)` = `f"https://github.com/{owner}/{name}/releases/download/{release_tag(version)}/"`.
  This is T8.1's download URL ("Interface", Release assets) without the asset name.
- `pages_index_url(repository)` = `f"https://{owner.lower()}.github.io/{name}/{INDEX_NAME}"`. Comment it as GitHub's
  project-site address, whose host name is lowercase.
- `index_zip_names(extension_id, version)` = `[_build_extension.extension_zip_name(extension_id, version, p) for p in _release.RELEASE_PLATFORMS]`.
- `check_base_url(base_url)`: `base_url` must start with one of `f"{s}://"` for `s` in `BASE_URL_SCHEMES` and end with `/`.
  Otherwise raise `RepoIndexError(f"base URL {base_url!r} must start with https:// or file:// and end with /")`.
- `run_server_generate(blender, repo_dir)`:
  - run `[str(blender), "--command", "extension", "server-generate", "--repo-dir", str(repo_dir)]` with
    `capture_output=True, text=True` and no `check`;
  - write its stdout, then its stderr, to `sys.stderr`;
  - a nonzero exit raises `RepoIndexError(f"server-generate exited {code} for {repo_dir}")`;
  - a missing `repo_dir / INDEX_NAME` raises naming that path;
  - return `json.loads` of that file, read as UTF-8.
  Capturing, rather than passing `sys.stderr` as stdout, works under any pytest capture mode.
- `rewrite_index(index, base_url, zip_names)` returns a new dict and never modifies `index`:
  1. `check_base_url(base_url)`.
  2. For each entry of `index["data"]`, `url = entry.get("archive_url")` must equal `"./" + n` for exactly one `n` in
     `zip_names` (fact 1: `pathname2url` leaves these ASCII names unchanged). Otherwise raise
     `RepoIndexError(f"index entry archive_url {url!r} is not './' + one of {list(zip_names)}")`. A name seen twice raises
     `RepoIndexError(f"index lists {n} twice")`.
  3. Any name of `zip_names` without an entry raises `RepoIndexError(f"index has no entry for {', '.join(missing)}")`.
  4. Each new entry is `{**entry, "archive_url": base_url + n}`, which keeps the key order. The new `data` lists them in
     `zip_names` order: `server-generate` lists them in `os.scandir` order (fact 1).
  5. Return `{**index, "data": new_data}`. The other top-level keys are copied unchanged; `verify_index` checks them.
- `write_index(index, path)`: `path.write_text(json.dumps(index, indent=2) + "\n", encoding="utf-8")`.
- `expected_entry(zip_path, platform, archive_url, *, extension_id, version)` gives the entry that `server-generate`
  writes for this zip (fact 2), with `archive_url` in place of the relative one. Raise `RepoIndexError` naming the zip
  when:
  - the zip cannot be opened;
  - it has no `blender_manifest.toml` at its root;
  - the manifest has no `build.generated` table (message: "… has no [build.generated] table: not built with
    --split-platforms");
  - `manifest["id"] != extension_id`, or `manifest["version"] != version` (the message names both versions);
  - `generated["platforms"] != [platform]`;
  - a wheel of `generated["wheels"]` fails `_build_extension.parse_wheel_filename(PurePosixPath(w).name)`, or its `abi`
    is not `"abi3"`. Convert the `ValueError` to `RepoIndexError`.

  Build it as: `m = {**manifest, "platforms": generated["platforms"], "wheels": generated["wheels"]}`;
  `entry = {k: m[k] for k in INDEX_MANIFEST_FIELDS if k in m}`; then add `python_versions = list(ABI3_PYTHON_VERSIONS)`,
  `archive_url`, `archive_size = zip_path.stat().st_size` and `archive_hash = "sha256:" + <hex digest>`. Hash the file in
  `IO_CHUNK_BYTES` blocks.
- `verify_index(index_path, assets_dir, base_url, *, extension_id, version)`, raising `RepoIndexError` on the first failing
  check:
  1. `check_base_url(base_url)`.
  2. The text (UTF-8) parses as JSON (a `JSONDecodeError` becomes `RepoIndexError` naming the file), and it equals
     `json.dumps(index, indent=2) + "\n"`. Otherwise: `f"{index_path.name} is not in the canonical format json.dumps(index, indent=2) plus a newline"`.
  3. `list(index) == ["version", "blocklist", "data"]`, `index["version"] == INDEX_SCHEMA_VERSION` and
     `index["blocklist"] == []`. Each failure names the key and the value found.
  4. `found = [e.get("platforms") for e in index["data"]]` must equal `[[p] for p in RELEASE_PLATFORMS]`. Otherwise:
     `f"{index_path.name}: the entries list platforms {found}; expected one entry per platform in the order {list(RELEASE_PLATFORMS)} (missing: {missing}, unexpected: {unexpected})"`,
     with `missing = [p for p in RELEASE_PLATFORMS if [p] not in found]` and
     `unexpected = [f for f in found if f not in [[p] for p in RELEASE_PLATFORMS]]`.
  5. For each position `k`, with `p = RELEASE_PLATFORMS[k]` and `n = index_zip_names(extension_id, version)[k]`:
     - `assets_dir / n` must be a file. Otherwise: `f"{assets_dir}: no {n}"`;
     - `index["data"][k]` must equal `expected_entry(assets_dir / n, p, base_url + n, extension_id=…, version=…)`. Otherwise:
       `f"{index_path.name}: the entry for {n} differs from the archive in {', '.join(keys)}"`, where `keys` is
       sorted. It holds every key that is in only one of the two dicts, or whose values differ.
- `generate_index(blender, assets_dir, base_url, out_dir, work_dir, *, extension_id, version)`. Its checks run before
  Blender does and before anything is written:
  1. `check_base_url(base_url)`.
  2. `names = index_zip_names(extension_id, version)`; every `assets_dir / n` must be a file. Otherwise:
     `f"{assets_dir}: missing {', '.join(missing)}"`.
  3. `blender` must be an existing file. Otherwise: `f"{blender}: no Blender executable"`.
  4. `out_dir` must not exist. Otherwise:
     `f"{out_dir} exists; remove it first: an index never mixes the output of two runs"`.
  5. `repo_dir = work_dir / "repo"`. If it exists, `shutil.rmtree` it, then `mkdir(parents=True)` it, and
     `shutil.copyfile` the three zips into it. Comment why: `server-generate` lists every `*.zip` of the directory and
     reads a `blender_repo.toml` there, so the directory holds exactly the release's zips.
  6. `index = rewrite_index(run_server_generate(blender, repo_dir), base_url, names)`.
  7. `out_dir.mkdir(parents=True)`, then `write_index(index, out_dir / INDEX_NAME)`.
  8. `verify_index(out_dir / INDEX_NAME, assets_dir, base_url, extension_id=…, version=…)`. Return the path.
- `check_urls(index_path)`:
  - an index with no entries raises;
  - for each entry, `url = entry["archive_url"]` must start with one of the `BASE_URL_SCHEMES` prefixes;
  - read `urllib.request.urlopen(urllib.request.Request(url, headers={"User-Agent": USER_AGENT}), timeout=NETWORK_TIMEOUT_S)`
    in `IO_CHUNK_BYTES` blocks, counting bytes and hashing them;
  - an `OSError` (which includes `URLError` and `HTTPError`) raises `RepoIndexError(f"{url}: {exc}")`;
  - a size other than `archive_size` raises `f"{url}: {size} bytes, but the index says {archive_size}"`;
  - a hash other than `archive_hash` raises `f"{url}: sha256:{hex}, but the index says {archive_hash}"`;
  - return the URLs.
  urllib follows the redirect of GitHub's download URLs, as Blender's client does (fact 3).
- `main(argv)`, with argparse subcommands:
  - `generate`: `--blender` and `--assets-dir` are required. A required, mutually exclusive group holds `--repository`
    and `--base-url`. `--out-dir` (default `dist/site`) and `--work-dir` (default `build/repo-index`) are relative to the
    working directory.
  - `verify`: `--index` and `--assets-dir` are required, with the same group.
  - `check-urls`: `--index` is required.
  - `base-url` and `pages-url`: `--repository` is required.

  `extension_id = _release.read_manifest(REPO_ROOT)["id"]` and `version = _release.release_version(REPO_ROOT)`.
  `--repository R` means `base_url = release_base_url(R, version)`. `generate` prints the index path and `check-urls`
  prints `f"{url}: OK"` per URL. `RepoIndexError` and `_release.ReleaseError` print `repo_index: <message>` to stderr and
  return 1. Nothing goes to stdout before a subcommand has succeeded. End with `if __name__ == "__main__": sys.exit(main())`.

# Installing Painterly

Painterly is a render engine for Blender 5.2.0 or later, packaged as a Blender extension. Each release publishes one
extension zip per platform on [GitHub Releases](https://github.com/m516/blender-painterly-render-plugin/releases), and a

| Platform | Blender's name | Release asset |
|---|---|---|
| Linux on x86-64 | `linux-x64` | `painterly-<version>-linux_x64.zip` |
| macOS on Apple silicon | `macos-arm64` | `painterly-<version>-macos_arm64.zip` |
| Windows on x86-64 | `windows-x64` | `painterly-<version>-windows_x64.zip` |

Each zip holds the add-on and the native module for its platform (the wheel `painterly_core`). No other platform is

## Install from the remote repository

This is the recommended way: Blender then offers every new release as an update. The repository URL is

```
https://m516.github.io/blender-painterly-render-plugin/index.json
```

1. Open **Edit → Preferences**. Under **System → Network**, turn on **Allow Online Access**. Blender contacts remote
   repositories only while it is on.
2. Open **Get Extensions**. In its header, open **Repositories**, click **+** and choose **Add Remote Repository**.
3. Paste the URL into **URL**, all of it, including `index.json`. Blender reads the file at exactly that address, and the
   site has no page at its root.
4. Optionally turn on **Check for Updates on Startup**. Leave **Requires Access Token** off: the repository is public.
5. Click **Create**. Blender reads the repository at once and names it `m516.github.io`, after the URL's host.
6. In **Get Extensions**, search for "Painterly" and click **Install**. Blender lists only the zip for your platform. It
   downloads that zip from the GitHub Release and installs it only if its size and SHA-256 match the repository index.
7. In **Properties → Render**, set **Render Engine** to **Painterly**.

## Updates

- The repository always lists the newest release, and only that one.
- With **Check for Updates on Startup** on, Blender looks for a new release each time it starts. Otherwise, open the menu
  at the right end of the **Get Extensions** header (⌄) and choose **Refresh Remote**.
- When a new release is available, Painterly's row shows `<installed> → <new>` and an **Update** button. The
  **Installed** section offers **Update All**, and the header menu offers **Install Available Updates**.
- **Restart Blender after an update.** A running Blender cannot unload the native module of the previous version, and
  Painterly does not start with a native module whose version differs from its own.
- For a short while after a release is published, GitHub Pages may still serve the previous index, until its cached copy
  expires. If a release on GitHub is not offered yet, refresh again later.
- The repository offers no older versions. To go back to one, uninstall Painterly, then install that release's zip from
  disk (below). Blender offers no updates for a copy installed from disk. To return to the repository's copy, uninstall
  it and install Painterly from the repository again.

1. On the release's page under [GitHub Releases](https://github.com/m516/blender-painterly-render-plugin/releases),

4. In **Properties → Render**, set **Render Engine** to **Painterly**.

## Platform notes

- **Linux (`linux-x64`).** The native module runs on glibc 2.28 or later, the baseline of Blender's own Linux builds.
- **macOS (`macos-arm64`).** Apple silicon only. The native module is built for macOS 11.0 and later, and Blender's own

- **Windows (`windows-x64`).** x86-64 only; Windows on Arm (`windows-arm64`) is not supported. The C++ runtime is linked

- **All platforms.** Painterly renders on the CPU; there is no GPU support yet. It runs in the same Blender session as

def make_assets(root: Path, manifest_text: str = SOURCE_MANIFEST) -> Path:
    assets = root / "assets"
    assets.mkdir()
    names = repo_index.index_zip_names(ID, V)
    for platform, name in zip(release.RELEASE_PLATFORMS, names, strict=True):
        write_split_zip(assets / name, manifest_text, platform, WHEELS[platform])
    return assets


def blender_like_index(assets: Path, order: list[int]) -> dict:
    names = repo_index.index_zip_names(ID, V)
    data = []
    for k in order:
        path = assets / names[k]
        with zipfile.ZipFile(path) as archive:
            manifest = tomllib.loads(archive.read("blender_manifest.toml").decode("utf-8"))
        generated = manifest["build"]["generated"]
        manifest |= {"platforms": generated["platforms"], "wheels": generated["wheels"]}
        entry = {f: manifest[f] for f in repo_index.INDEX_MANIFEST_FIELDS if f in manifest}
        data_bytes = path.read_bytes()
        entry |= {
            "python_versions": ["3"],
            "archive_url": "./" + names[k],
            "archive_size": len(data_bytes),
            "archive_hash": "sha256:" + hashlib.sha256(data_bytes).hexdigest(),
        }
        data.append(entry)
    return {"version": "v1", "blocklist": [], "data": data}
