## Design
P=64, 8 pairs, size 400, `scene=gui`, `ghost=all`. Configs:
- `chain=lane:L` for L ∈ {1, 2, 4, 8, 16, 32, 64, 128};
- `chain=row`;
- `chain=image` (shared cache).

## Hypotheses to pre-register
- **H1.** `all.pattern_corr` is non-decreasing in L.
  - Refuted iff any Holm-corrected adjacent comparison `permutation_pvalue(longer, shorter, "less") ≤ α`, i.e. a significant decrease.
  - Also list the steps with a significant increase (`"greater"`).
- **H2.** Define L* = the smallest L for which `permutation_pvalue(lane_L, row, "less")` on `all.pattern_corr` is **not** rejected under Holm across all L.
  - Report the full curve (mean ± sd, relative to row, Cohen's d) for `all.pattern_corr`, `r4.structure_std`, `r4.lag1.x` and `r4.lag1.y`.
  - Lane length also changes anisotropy (pilot: r4.lag1.x is 0.156 at L=16 vs 0.204 for row).
- **H3.** `chain=row`, which restarts each pass at a hashed K0, matches `chain=image` (continuous).
  - Report `effect_summary` on the key family together with `min_attainable_p`.
  - Pilot: 0.588 vs 0.589 pattern_corr.
  - Derived from: research found the start-index distribution reaches stationarity within about one pixel.

## Deliverable for the plan
Recommend the default `chain` and `lane_length`. The CPU core parallelizes over (row, pass) units, which already exceed any core count.
Weigh fidelity (H2 curve) against parallelism: report the number of independent chains per pass for 1920×1080 at each L. Opus decides.


## Design rules (apply to every comparison in this experiment)
- **Key family.** `compare_ensembles` uses `metrics.DIFFUSE_KEY_FAMILY(keys)` (46 keys for the GUI scene), never all keys. The power
  guard in `compare_ensembles` raises if a family is too large for the ensemble size.
- **Estimation over verdicts.** Report `ensemble.effect_summary` (mean ± sd, relative difference, Cohen's d) for every comparison.
  "Indistinguishable" may only be written together with `min_attainable_p` and the largest observed |relative difference|.
- **Seeds.** Every configuration owns a disjoint seed block (`base_seed = 16 * block index`), as in experiment 001.
  - The positive control `chain=image, passes=64` is experiment 001's `img64` (block 0, seeds 0–15) and is reused from the cache.
  - New blocks start after 001's last block (9), at block 10, to keep seeds globally unique.
- **Two phases.** Phase A (this card's first commit): README with Background/Hypothesis/Method, `jobs.py`, and `analyze.py`.
  Validate `analyze.py` on a 2-pair smoke subset rendered at size 64 into a scratch cache (`PAINTERLY_CACHE`), not the real one.
  The orchestrator then renders `jobs.py` to completion. Phase B (a second commit `… results`): run `analyze.py`, then add Results and the DRAFT Conclusion.
