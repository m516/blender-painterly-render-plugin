# T1.9 — Experiment: is the texture pixel-locked? (Resolution and jitter units)
Milestone: M1 · Depends on: T1.6 · Parallel-safe: no · Slug: `resolution-dependence`

(Insert the experiment protocol from `docs/tasks/M1/_experiment_protocol.md`; follow it exactly.)

## Design
`chain=image`, `ghost=all`, P=64, 8 pairs, `scene=gui`. Configs:
- size ∈ {200, 400, 800} with `jitter=1/700` (the reference image-plane jitter, which is W/1400 pixels);
- size 800 with `jitter=1/1400`, which matches the 400 px pixel-jitter of 0.29 px.

## Analysis
`metrics.measure` needs a reference image, so compute the reference-free metrics directly with the metric functions
(`structure_std`, `lag1_autocorrelation` along x and y, `radial_spectral_slope`, region means) per region, using each size's own `object_id`.

**Downsample test.**
- Box-downsample the 800 renders' float sums by 2×2 (sum of 4 / 4) to 400.
- Apply `smallpaint_display` with the same passes.
- Compare against native 400 renders with `compare_ensembles` on the reference-free keys plus `pattern_corr` vs the reference.

## Hypotheses to pre-register
- **H1, pixel-locked.**
  - Derived from: the K chain couples neighbouring *pixels* while geometry is in world units.
  - Prediction: lag-1 autocorrelation in pixels is about the same at 200/400/800, and so is the correlation length in pixels.
    The downsampled 800 is therefore *distinguishable* from native 400 (its texture is finer in world units).
  - Test: `compare_ensembles` on the lag1 keys across sizes must be indistinguishable; downsampled-800 vs 400 must be distinguishable.
- **H2, jitter units.** At 800, `jitter=1/700` vs `jitter=1/1400` is distinguishable on lag1 and structure_std. If not, jitter units
  do not matter for the look.

## Deliverable
A recommendation, with numbers, for SPEC §3/§7: lane length and jitter specified in pixels (pixel-locked) or scaled with
resolution. Opus decides.
