## Create
(`jobs.py` is part of the pre-registration and already exists. Do not modify it. `analyze.py` reads `DESIGN`,
`REFERENCE_SIDE` and `build_ensembles` from it.)
- `experiments/006-2026-10-09-jitter-units/analyze.py`. It implements the README's Common definitions and H1-H5:
  - Scale-equivariant parameters as functions of the side `s`, with s₀ = `jobs.REFERENCE_SIDE` (400):
    - `sigma(s) = (metrics.HIGHPASS_SIZE / sqrt(12)) * s / jobs.REFERENCE_SIDE`;
    - `erosion(s) = (metrics.HIGHPASS_SIZE // 2) * s // jobs.REFERENCE_SIDE`;
    - `lag(s) = s // LAG_UNIT_SIDE` with `LAG_UNIT_SIDE = 200` (the smallest native side).
    At full scale, assert that erosion and lag are exact integers (`(HIGHPASS_SIZE // 2) * s % jobs.REFERENCE_SIDE == 0`, and
    likewise for the lag). At smoke scale, round to the nearest integer ≥ 1 and print that it did (README, Commands).
  - The design check: blocks and options as in the table. Every reused configuration's options must equal those of the
    004 configuration named in the table's source column. Load 004's `jobs.py` with `report.load_jobs_module` and compare.
  - The 18-key family T, the estimation-only keys, and all comparisons, using `report.family_test` (Holm, power guard)
    and `ensemble.effect_summary`.
  - H3's Δ_u and the bootstrap intervals, using `numpy.random.default_rng(0)` and `BOOTSTRAP_RESAMPLES = 10_000`
    (comment as in the README).
  - H5 with both erosions.
  - `results.json` via `report.write_results_json`, and the two figures via `io.write_png`.
  - `--pairs`, `--scale` and `--out-dir` options, as in 004.
