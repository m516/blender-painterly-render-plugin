# T1.3 — Oracle test suite
Milestone: M1 · Depends on: T1.1, T1.2 · Parallel-safe: no

## Goal
After this card the oracle's guarantees are pinned by tests:
- determinism;
- thread invariance;
- exact Halton equivalence below 2^23;
- scene geometry;
- K accounting.

A slow statistical test shows that the oracle reproduces the reference look and that each SPEC ingredient is necessary
(negative controls are significantly worse).

## Read first
- `docs/spec.md` §2, §3, §5, §9
- `src/app/CHANGES.md`
- `analysis/painterly_analysis/{oracle,metrics,ensemble}.py`

## Create
- `tests/oracle/conftest.py`: a fixture `oracle` that returns `painterly_analysis.oracle`. Fail with a clear message if the binary is missing; tell the user to run `make build`.
- `tests/oracle/test_oracle_contract.py` (fast; size 64 unless stated):
  - `test_deterministic`: same options twice give byte-identical `sum.npy` and `k_consumed.npy`.
  - `test_thread_invariance`: parametrize over `row`, `lane:16`, `lane:5`, `omp-restart:4` and `pixel-major-omp:3`; `threads=1` vs `threads=4` give identical arrays.
  - `test_halton_exact_equals_incremental_below_period`: `chain=image, passes=2`; the `halton` options agree.
    Also assert `meta["total_k_consumed"] < 2**23`, so the test is in range.
  - `test_total_k_matches_k_consumed`: `meta["total_k_consumed"] == k_consumed.sum()` for `image`.
  - `test_object_id_geometry` at size 400, passes 1: `object_id[200,200] == 4` and `object_id[73,200] == 9`.
    Derive the light pixel in a comment from SPEC §9 and §7: the light centre (−1.9, 0, −3) projects to `cam.x = −1.9/3`, so `row = (1 − 1.9/3)·200 ≈ 73.3`.
  - `test_alpha_zero_is_identity`: `alpha=0` and the default give identical sums.
  - `test_ghost_none_darkens`: at passes 4, the image mean with `ghost=none` is below the mean with `ghost=all`.
    Use `ensemble.separated` on 8 seeds per side; it is a statistical claim, so no thresholds.
- `tests/oracle/test_oracle_reference.py` (`@pytest.mark.slow`):
  - Module-level knobs with comments:
    - `ENSEMBLE_PAIRS = 8` (8 pairs give exact permutation p-values down to 1.6e-4; with α=0.01 and Holm over ≤ 4 comparisons this is enough);
    - `ENSEMBLE_PASSES = 32` (provisional: the X-oracle experiment estimates the reference's pass count, and this constant then cites it). The docstring must not claim reference indistinguishability: this test checks correlation and control separation only;
    - `ALPHA = 0.01`.
  - Render `2·ENSEMBLE_PAIRS` seeds, size 400, for each config:
    - `positive`: `chain=image` (SPEC reference mode);
    - `per_path_random_start`: `chain=lane:1`;
    - `normalized`: `alpha=1`;
    - `u2_independent`: `u2=independent`.
  - Seeds `2k` and `2k+1` form pair k. Compute `metrics.measure(a.sum, b.sum, ENSEMBLE_PASSES, ref8, object_id)` per pair, with `object_id` from the positive render.
  - Assertions:
    1. `sign_flip_pvalue(positive["all.pattern_corr"], "greater") < ALPHA`: the pattern correlates with the reference.
    2. For each negative control c: `separated(positive["all.pattern_corr"], c["all.pattern_corr"], "greater", ALPHA)`, Holm-corrected across the three controls.
  - Print a compact table of the ensemble means for every metric key (it shows with `-s`), and write it to `.cache/test_reports/oracle_reference.json`.
