# T1.1 — `smallpaint_oracle`: the reference renderer
Milestone: M1 · Depends on: T0.3 · Parallel-safe: no

## Goal
After this card, `build/dev/src/app/smallpaint_oracle` exists. It is a headless, deterministic, instrumented copy of
`smallpaint_painterly.cpp` and is the ground truth for every later test and experiment.

It must stay a **minimal diff** of the original:
- The geometry, material and path code in `trace()`, `Sphere`, `Plane`, `Halton`, `hemisphere()` and `camcr()` keeps the
  same expressions in the same order. Only the hooks listed below may be added.
- Do not refactor, rename or "fix" anything.

## Changes to apply (the only allowed ones)
1. **Remove the GUI.** Remove the `../src_gui/main.h` include and the uses of `smallpaint::isRunning`, `imageOutput` and `running`.
   Replace `render(...)` with the loop drivers below plus a `main()`.
2. **Remove `rand_r`, `srand` and the `RND`/`RND2` macros.**
   - Jitter becomes `cam.x = cam.x + rng_signed(seed, PURPOSE_JITTER_X, 0, row, col, pass) * jitter;`.
   - y is the same with `PURPOSE_JITTER_Y`.
   - `jitter` defaults to `1.0 / 700.0` (`painterly.cpp:291`).
3. **Halton instrumentation.**
   - Add a member `uint64_t index` that `number(i, base)` sets to `i` and `next()` increments.
   - Add a global `g_halton_exact` (CLI `--halton exact`). In exact mode, for base 2 only:
     - `number(i,2)` sets `value = bitrev23(i mod 2^23) * 2^-23`;
     - `next()` does `index++` and then sets `value` the same way.
     Implement `bitrev23` as a plain loop or bit trick with a comment citing SPEC §2.
   - Incremental mode is byte-for-byte the original code path.
4. **Path context.** Add `thread_local` context `{uint32_t seed; int row, col, pass;}` set before each `trace()` call.
5. **u2 mode** (`--u2 same|independent|base3`). In the diffuse branch, `u2` is:
   - `same`: `hal2.get()` (the original);
   - `independent`: `rng_unit(seed, PURPOSE_U2, depth, row, col, pass)`. `hal2.next()` is still called, so K accounting is unchanged.
   - `base3`: `hal2` is initialised with base 3 wherever `hal2.number(K0, ·)` is called.
6. **Alpha** (`--alpha X`, default 0). Immediately after `ray.d = (N + hemisphere(...));` add
   `ray.d = ray.d * pow(ray.d.length(), -g_alpha);`. No `if`: with alpha 0, `pow(L,-0.0)=1` and `d*1.0` is exact (SPEC §4).
7. **Ghost policy** (`--ghost all|lights|none`, default `all`) inside `Sphere::intersect`:
   - `all`: the original;
   - `lights`: the original if `emission > 0`, otherwise the exact quadratic of SPEC §5;
   - `none`: the exact quadratic.
   Implement the exact quadratic exactly as written in SPEC §5: eps is compared on the undivided roots, which are then divided by `2a`.
8. **Emitter continuation** (`--continue-after-emitter yes|no`, default yes). After the emission line, `no` returns when `emission > 0`.
9. **Scene selection** (`--scene gui|standalone`). `gui` is the existing list (SPEC §9).
   - `standalone` uses the values from the standalone source, including its sphere normal formula. Use a global flag read in
     `Sphere::normal` so the `gui` path is unchanged.
   - Report any value that disagrees with SPEC §9.
10. **Chains** (`--chain image|row|lane:L|omp-restart:T|pixel-major`, SPEC §3). Images are stored as `[row][col]` with `row = i` and `col = j`.
    - `image`: `hal.number(0,2); hal2.number(0,base2)` once; `for s, for i, for j`.
    - `row`: per (i, s): `K0 = rng_u32(seed, PURPOSE_LANE_K0, 0, i, 0, s) & ((1u<<22)-1)`, then `number(K0,…)`; `for j`.
    - `lane:L`: per (i, l, s): `K0 = rng_u32(seed, PURPOSE_LANE_K0, 0, i, l, s) & ((1u<<22)-1)`; `for j in [l*L, min((l+1)*L, W))`.
    - `omp-restart:T`: virtual thread t owns rows `i ≡ t (mod T)`. For each pass it resets to `number(0,…)` and walks its rows in increasing order.
    - `pixel-major`: one chain from 0; `for i, for j, for s`.
    - `pixel-major-omp:T`: virtual thread t owns rows `i ≡ t (mod T)`. Its one chain starts at 0 and is never reset; it runs `for its rows i ascending, for j, for s` (SPEC §3).
    - `base2` is 3 when `--u2 base3`, otherwise 2.
11. **Threads** (`--threads N`, default = hardware concurrency).
    - Run independent chains concurrently with `std::thread`: rows for `row`, (row, lane) units for `lane`, and virtual threads for `omp-restart`.
    - `image` and `pixel-major` are single-threaded.
    - Each worker gets its **own copy** of `params`, because `unordered_map::operator[]` is not safe to share.
    - Within a chain, passes and pixels run strictly in the SPEC §3 order, so output is identical for every N.
12. **Instrumentation outputs** (`--out DIR`, created if missing):
    - `sum.npy`: float64, shape (H, W, 3), C order. The per-pixel sum over passes of the trace colour (`pix`).
    - `k_consumed.npy`: uint64, shape (H, W). The total diffuse draws (`hal.index` deltas) consumed by that pixel over all passes.
    - `object_id.npy`: int32, shape (H, W). The scene-list index (SPEC §9) hit by the **unjittered** primary ray of the pixel, or −1.
    - `image.ppm`: P6, `min((int)sum / passes, 255)` per channel (SPEC §7).
    - `meta.json`: every resolved option, `passes`, `width`, `height`, `wall_seconds`, `total_k_consumed`, and `oracle_version: "1"`.
    Write `.npy` with a small hand-written writer: magic `\x93NUMPY`, version 1.0, and a header dict padded with spaces to a
    multiple of 64 bytes ending in `\n`.
13. **CLI.** `--scene`, `--size`, `--passes`, `--refr`, `--seed`, `--chain`, `--halton`, `--ghost`, `--alpha`, `--u2`,
    `--continue-after-emitter`, `--jitter`, `--threads`, `--out`.
    - Defaults: `--chain image`, `--halton incremental`, `--ghost all`, `--u2 same`, `--alpha 0`,
      `--continue-after-emitter yes`, `--seed 0` (uint32), `--jitter 1/700`.
    - Scene defaults: `gui` → size 400, passes 50, refr 1.5 (SPEC §9). `standalone` → size 900, passes 8, refr 1.9 and
      `--chain pixel-major`, each unless given explicitly.
    - Unknown flags exit with status 2 and usage text.
14. **Camera `tan` in double** (SPEC §7). In `camcr`, replace `tan(fovx)` → `tan((double)fovx)` and `tan(fovy)` → `tan((double)fovy)`.
    Record this in CHANGES.md: the shipped GCC 5.4 binary evaluated tan in double, while current libstdc++ would pick the float overload.

## Acceptance
- `make build` succeeds and `make lint` passes. Add `src/app/smallpaint_oracle.cpp` to the clang-format exclusion only if it
  must keep the original formatting: put a `// clang-format off` / `// clang-format on` pair around the original code. Do not reformat it.
- Determinism: two runs of `--size 64 --passes 2 --seed 7` produce byte-identical `sum.npy` (`cmp`).
- Thread invariance: `--chain lane:16` and `--chain omp-restart:4` with `--threads 1` and `--threads 4` give byte-identical `sum.npy`.
- `--halton exact` vs `--halton incremental` with `--chain image --size 64 --passes 2` give byte-identical `sum.npy`.
- `object_id.npy` has value 4 (back plane) at (row 200, col 200) and 9 (light) at (row 73, col 200) at size 400 (SPEC §9 geometry).
- Timing: report `wall_seconds` for `--chain image --size 400 --passes 50`, and the image mean RGB of `image.ppm`. For comparison,
  the reference mean is about (97.0, 100.2, 71.0).
