# T3.2 — Vendor Cycles `util/` and build the `cycles_util` library in the `painterly` namespace
Milestone: M3 · Depends on: T3.1 · Parallel-safe: no

## Goal
After this card:
- Cycles' math/type/hash/transform utilities compile into a static library `cycles_util`.
- Its namespace is `painterly`: `CCL_NAMESPACE_BEGIN=namespace painterly {`.
- No OIIO, TBB, OCIO or glog is needed. Our shims replace the few headers that need them.

## Vendored files
Use `tools/vendor_sync.py add` to vendor them to `third_party/cycles/<same path without intern/cycles/>`:
- The closure of `util/hash.h util/math.h util/types.h util/transform.h util/projection.h util/color.h util/math_intersect.h`
  (about 45 headers; see `vendor_sync.py closure`).
- `util/transform.cpp`, and the closure of its includes (`util/boundbox.h`, …).
- `util/aligned_malloc.h/.cpp`, `util/guarded_allocator.h/.cpp`, `util/array.h`, `util/vector.h`, `util/map.h`, `util/unique_ptr.h`.
- `extern/sse2neon/sse2neon.h` → `third_party/sse2neon/sse2neon.h` (needed on arm64), with its licence file.

## Layout (docs/architecture.md, "Source layout and naming")
- `src/cycles/` builds the vendored Cycles code. Its `shim/` subdirectory holds headers and sources that **shadow an upstream
  Cycles path** (same relative path) so that vendored code compiles without OIIO, TBB, OCIO or glog.
- `src/painterly/` is our own engine. Nothing under it shadows an upstream path, because upstream has no `painterly/` directory.
- Never vendor an upstream file that is also shimmed: both copies would be on the include path, and MSVC searches the
  includer's directory first (research report R6).

## Create
- `src/cycles/CMakeLists.txt`: a static library `cycles_util` built from the vendored `util/*.cpp` and the shim sources.
  - `target_include_directories(cycles_util PUBLIC <src/cycles/shim> <third_party/cycles> <third_party> <third_party/sse2neon> <src>)`,
    in this order. Shims come first so they shadow upstream headers. `third_party` lets a shim wrap the real header as
    `#include "cycles/<path>"`. `src` lets our code include `painterly/...`.
  - Public compile definitions: `CCL_NAMESPACE_BEGIN=namespace painterly {` and `CCL_NAMESPACE_END=}`. Use quoting that works
    for Ninja, Makefiles and MSVC.
  - Every later painterly library links `cycles_util`, so it gets the same include order and definitions.
- Shims in `src/cycles/shim/util/`. Each starts with the comment `Shim: replaces Cycles util/<name> without <dependency>`.
  - `log.h`: `LOG_*` macros and the helpers that vendored code uses. The minimum is LOG_ERROR/LOG_WARNING/LOG_INFO
    streaming to `std::cerr`, plus any others the compiler demands.
  - Add others only when the compiler proves them necessary. List them in the report.
- `tests/core/test_shims.py`. Every file under `src/cycles/shim/` (a) starts with that `Shim: replaces Cycles` comment and
  (b) has no vendored counterpart: its relative path is not a `dest` in `third_party/cycles/VENDORED.toml`.
- `src/test/test_util.cpp` (doctest):
  - `hash_uint4` on fixed inputs equals the oracle header (`src/app/smallpaint_oracle_hash.h`, included in the same test under
    a different namespace) for 10^4 random inputs;
  - `transform_inverse` round-trips a known matrix exactly where expected;
  - `make_float3`/`dot`/`normalize` smoke checks.

## Modify
- `src/CMakeLists.txt`: `add_subdirectory(cycles)` first.
- `src/blender/selftest.h`: remove the local `CCL_NAMESPACE_BEGIN/END` fallback (from T2.1); the compile definitions now provide them.
- `src/blender/CMakeLists.txt` and `src/test/CMakeLists.txt`: link `cycles_util`.
- `.clang-format` handling: vendored files are never formatted. `make lint` formats `src/` only, which includes `src/cycles/shim`.
