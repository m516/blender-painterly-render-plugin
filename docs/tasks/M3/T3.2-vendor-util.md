# T3.2 — Vendor Cycles `util/` and build the `cycles_util` library in the `painterly` namespace
Milestone: M3 · Depends on: T3.1 · Parallel-safe: no

## Goal
After this card:
- Cycles' math/type/hash/transform utilities compile into a static library `cycles_util`.
- Its namespace is `painterly`: `CCL_NAMESPACE_BEGIN=namespace painterly {`.
- No OIIO, TBB, OCIO or glog is needed. Our shims replace the few headers and sources that need them.

## Vendored files
Use `tools/vendor_sync.py add` (T3.1). Paths are relative to `intern/cycles/` (T3.1 "Path convention"), so `closure` output
can be passed to `add` unchanged; each file lands at the same path under `third_party/cycles/`:
- The closure of `util/hash.h util/math.h util/types.h util/transform.h util/projection.h util/color.h util/math_intersect.h`
  (`vendor_sync.py closure` prints the list). It contains `util/system.h`, which `util/transform.h` includes.
- Do **not** vendor `util/transform.cpp` or `util/boundbox.h` in M3. `util/boundbox.h`, which only `transform.cpp` includes,
  qualifies calls as `ccl::min`/`ccl::max`/`ccl::clamp` (boundbox.h:39-88, 266-269; upstream builds with `namespace ccl`,
  intern/cycles/CMakeLists.txt:208). That does not compile in `namespace painterly`. M3 uses only the inline
  `transform_inverse()` and `euler_to_transform()` of `util/transform.h`, plus `transform_inverse_cpu_avx2()` from
  `util/transform_avx2.cpp`. When a later card needs `transform.cpp`, Opus decides how: a patch in `patches/`, or a
  `namespace ccl = painterly;` alias.
- `util/transform_avx2.cpp`. Upstream `transform_inverse()` (`util/transform.h:572-584`) calls `transform_inverse_cpu_avx2()`
  whenever `system_cpu_support_avx2()` is true, so this file is compiled on every platform. Only on x86-64 does it get
  upstream's AVX2 flags (`util/CMakeLists.txt:155-156`; `CYCLES_AVX2_FLAGS`, `intern/cycles/CMakeLists.txt:82,99`):
  GCC/Clang `-msse -msse2 -msse3 -mssse3 -msse4.1 -msse4.2 -mavx -mavx2 -mfma -mlzcnt -mbmi -mbmi2 -mf16c`, MSVC
  `/arch:AVX2`. The global `-ffp-contract=off` (docs/architecture.md) still applies.
- `util/aligned_malloc.h/.cpp`, `util/guarded_allocator.h/.cpp`, `util/array.h`, `util/vector.h`, `util/map.h`, `util/unique_ptr.h`.
- Do **not** vendor `util/system.cpp`. It includes `util/string.h`, which includes `<OpenImageIO/string_view.h>`.
  `system_cpu_support_avx2()` comes from the shim `util/system.cpp` (see Create).
- sse2neon (needed on arm64) and its licence, from the `sse2neon` upstream (DLTcollab/sse2neon at
  `227cc413fb2d50b2a10073087be96b59d5364aea`, the commit Blender v5.2.2 pins; T3.1 "Upstream pins"):
  `tools/vendor_sync.py add --upstream sse2neon sse2neon.h LICENSE --dest-prefix sse2neon`, which vendors
  `third_party/cycles/sse2neon/sse2neon.h` and `third_party/cycles/sse2neon/LICENSE` (MIT).

## Layout (docs/architecture.md, "Source layout and naming")
- `src/cycles/` builds the vendored Cycles code. Its `shim/` subdirectory holds headers and sources that **shadow an upstream
  Cycles path** (same relative path) so that vendored code compiles without OIIO, TBB, OCIO or glog.
- `src/painterly/` is our own engine. Nothing under it shadows an upstream path, because upstream has no `painterly/` directory.
- Never vendor an upstream file that is also shimmed: both copies would be on the include path, and MSVC searches the
  includer's directory first (research report R6).

## Create
- `src/cycles/CMakeLists.txt`: a static library `cycles_util` built from the vendored `util/*.cpp` and the shim sources
  `src/cycles/shim/util/*.cpp` (T3.3 adds more).
  - `target_include_directories(cycles_util PUBLIC <src/cycles/shim> <third_party/cycles> <third_party/cycles/sse2neon> <src>)`,
    in this order, the same four as docs/architecture.md. Shims come first so they shadow upstream headers. `src` lets our
    code include `painterly/...`.
  - Public compile definitions: `CCL_NAMESPACE_BEGIN=namespace painterly {` and `CCL_NAMESPACE_END=}`. Use quoting that works
    for Ninja, Makefiles and MSVC.
  - On arm64 (`CMAKE_SYSTEM_PROCESSOR` matches `^(arm64|ARM64|aarch64)$`): the public compile definition `WITH_SSE2NEON`,
    as Blender's root `CMakeLists.txt:1564-1566` adds it. Without it `util/optimization.h:36` never defines `__KERNEL_NEON__`,
    `util/simd.h:26-28` never includes `<sse2neon.h>`, and Cycles falls back to scalar code.
  - Public compile options on x86-64 with GCC/Clang (`CMAKE_SYSTEM_PROCESSOR` matches `^(x86_64|AMD64|amd64)$`, not MSVC):
    upstream's `CYCLES_SSE42_FLAGS` `-msse -msse2 -msse3 -mssse3 -msse4.1 -msse4.2` (`intern/cycles/CMakeLists.txt:97`,
    applied to all Cycles code at `:132-138`). `util/optimization.h` defines `__KERNEL_SSE42__` unconditionally on x86-64,
    so `dot`, `normalize` and `transform_inverse` on float3 call `_mm_dp_ps`/`_mm_round_ps`/`_mm_blendv_ps`, which GCC and
    Clang refuse to inline without these flags. MSVC x64 needs none (`:87`). They enable no FMA, so `-ffp-contract=off` and
    oracle parity are unaffected.
  - Every later painterly library links `cycles_util`, so it gets the same include order, definitions and compile options.
- Shims in `src/cycles/shim/util/`. Each starts with the comment `Shim: replaces Cycles util/<name> without <dependency>`.
  - `log.h`: `LOG_*` macros and the helpers that vendored code uses. The minimum is LOG_ERROR/LOG_WARNING/LOG_INFO
    streaming to `std::cerr`, plus any others the compiler demands.
  - `system.cpp`: defines the `util/system.h` functions that vendored code references, at least
    `system_cpu_support_avx2()` (called by `transform_inverse()`) and `system_cpu_support_sse42()`. Copy upstream's CPU
    capability code: the `__cpuid` helper (`util/system.cpp:53-71`, with `<intrin.h>` on MSVC as at `:12-16`) and
    `:145-244` (CPUID on x86 and x86-64, `false` elsewhere). It starts with the comment
    `Shim: replaces Cycles util/system.cpp without OIIO (upstream includes util/string.h)`, followed by upstream's SPDX lines.
    Define further `util/system.h` functions only if the linker demands them.
  - `stats.h`, starting with `Shim: replaces Cycles util/stats.h without Blender's intern/atomic`. Vendored
    `util/guarded_allocator.cpp` includes `util/stats.h`, whose `util/atomic.h` includes `atomic_ops.h` from Blender's
    `intern/atomic`, outside the pinned `intern/cycles` root. Mirror upstream's `class Stats` (`static_init_t`/`static_init`,
    `mem_alloc`, `mem_free`, public `std::atomic<size_t> mem_used, mem_peak`), and make the `static_init_t` constructor
    `constexpr`, so that `static Stats global_stats(Stats::static_init)` stays constant-initialized as upstream intends.
    Vendored `guarded_allocator.cpp` only reads the members by value (`return global_stats.mem_used;`), which converts
    implicitly. Raise `mem_peak` with a `compare_exchange_weak` loop. Do not use `std::atomic_ref`: libc++ has it only from
    LLVM 19, and the macos-14 wheel job (Xcode 15.4/16.x) lacks it. Do not vendor `util/stats.h` or `util/atomic.h`.
  - Add others only when the compiler or linker proves them necessary. List them in the report; T3.3 extends any of
    `param.h`, `string.h`, `thread.h` (and their `.cpp`) that you create.
- `LICENSES/MIT-sse2neon.txt`: a byte-identical copy of the vendored `third_party/cycles/sse2neon/LICENSE`. The wheel ships
  `LICENSES/*.txt` (T2.9 `license-files`), not `third_party/`, so the arm64 wheel, which compiles sse2neon in, needs this copy.
- `tests/core/test_shims.py`. Every file under `src/cycles/shim/` (a) starts with that `Shim: replaces Cycles` comment and
  (b) has no vendored counterpart: its relative path is not a `dest` in `third_party/cycles/VENDORED.toml`.
- `src/test/test_util.cpp` (doctest):
  - `hash_uint4` on fixed inputs equals the oracle header (`src/app/smallpaint_oracle_hash.h`, included in the same test under
    a different namespace) for 10^4 random inputs;
  - for an exactly invertible matrix (axis permutation, power-of-two scales of either sign, integer translation), every
    component of `transform_inverse(M)*M` equals the identity's under float `==`. Do not `memcmp`: a negative scale gives
    `-0.0` entries (e.g. M = diag(−1,1,1) with translation (−3,0,0)), and IEEE `-0.0 == +0.0`;
  - `make_float3`/`dot`/`normalize` smoke checks.
