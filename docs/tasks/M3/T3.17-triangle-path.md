# T3.17 — Triangle path: the reference box built from meshes matches the oracle statistically
Milestone: M3 · Depends on: T3.16 · Parallel-safe: no

## Goal
Blender scenes are triangle meshes, and triangles are not bit-identical to analytic planes (Embree uses float32). Show that replacing
smallpaint's six planes with quads leaves the look statistically indistinguishable from the oracle.

## Modify
- `tests/core/scenes.py` (T3.16): add `build_smallpaint_scene_triangles(scene, *, size, plane_extent, …)`.
  - Same as T3.16, but each plane becomes one quad mesh (2 triangles, no corner normals). The quad lies in the plane, is centred at the
    foot point `−d·n`, and spans ±`plane_extent` along two orthonormal in-plane axes.
  - `plane_extent` is a parameter. Use 50, documented as "any value large enough that the quads cover the box's visible faces; the box spans at most 6 units (z from −5.5 to 0.5, SPEC §9)".
  - Normal orientation: the winding gives normals equal to smallpaint's `n`, and `two_sided = False` keeps smallpaint's plane normal semantics exactly.

## Create
- `tests/core/test_triangle_path.py` (loads `scenes.py` by file path, as T3.16's parity test does):
  - **Fast:** at size 64, `object_id()` of the triangle scene equals the analytic scene's **exactly on interior pixels**, i.e.
    pixels whose 3×3 neighbourhood in the analytic `object_id()` holds a single id (T5.4's 3×3 criterion, applied here to every
    id because both scenes keep the analytic spheres). Report the number of differing pixels elsewhere, but do not assert it.
    Edge pixels legitimately differ: the unjittered rays of columns 16 and 48 pass within a relative 4.4e-8 of the back wall's
    vertical edges (`tan((double)float(π/4))` = 1 + 4.4e-8, SPEC §7), which is below float32 resolution, and the same holds
    along the floor-wall edges and where the spheres meet the floor.
  - **Slow:** an ensemble of 8 pairs, size 400, P = 32, chain `image` (`scene.set_integrator(chain="image")`, as in T3.16; oracle
    `--chain image`), triangle scene vs oracle (`painterly_analysis` ensembles, shared cache).
    `compare_ensembles(..., alpha=0.01)` must be indistinguishable on
    `metrics.realization_free_key_family(metrics.diffuse_key_family(keys))`. Print the table.
  - Embree's float32 hits can shift K consumption. The realization-dependent keys (`pattern_corr`, `block_rmse`) would then
    measure the changed sample sequence rather than the look, so the family leaves them out. Report whether `k_consumed` equals
    the oracle's; do not assert it.
