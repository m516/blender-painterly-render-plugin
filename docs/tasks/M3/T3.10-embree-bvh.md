- One `RTCDevice` per process (lazy, thread-safe, `"threads=1"` unless you find a reason otherwise). Embree INTERNAL tasking is used only for builds.
- One `RTCScene` per mesh (one triangle geometry) and a top-level scene of instance geometries. Build quality: `RTC_BUILD_QUALITY_HIGH`.
- Create every RTCScene (each mesh scene and the top-level instance scene) with `rtcSetSceneFlags(scene, RTC_SCENE_FLAG_ROBUST)`.
  This is Embree's watertight mode. A ray through an edge shared by two triangles must hit one of them: T3.17 and T5.4
  compare object ids exactly on interior pixels, and unjittered smallpaint rays at pixels (i, i) cross the back quad exactly
  on its diagonal.
- `Ng` is in object space for instance hits. Transform it to world with the inverse-transpose of `object_to_world`, computed in double.
- `PainterlyRay` → `RTCRayHit`: cast o and d to float. Do not normalize d.
- `painterly_embree_scene_create` copies vertices and indices into Embree-owned buffers (`rtcSetNewGeometryBuffer`, never
  `rtcSetSharedGeometryBuffer`) and sets instance transforms with `rtcSetGeometryTransform`. The returned scene keeps no pointer
  into the caller's arrays. T3.13 builds it from the host `PainterlyMesh` vectors, and T3.14's snapshot taken in `start()` must
  survive later `Scene` edits from Python.

## Determinism scope (record in the header comment)
- Embree's triangle hits are deterministic on one machine and ISA, but **not across ISAs**: its AVX2 kernels use explicit FMA, which
  `-ffp-contract=off` cannot affect. M2's selftest showed `t = 0.49999997` rather than 0.5.
- Bit-parity with the oracle is therefore defined on **analytic** scenes only (T3.16).
- Triangle scenes are checked statistically (T3.17); M3 does not test their thread/batch invariance.

## Create `src/test/test_bvh.cpp`
- One unit quad (2 triangles) instanced twice at different transforms. Rays with unnormalized directions (|d| = 0.5, 1, 2):
  - t equals distance / |d| within float32 round-off (justified tolerance);
  - the instance index is correct;
  - u, v reproduce the hit point: `(1−u−v)·v0 + u·v1 + v·v2` equals `o + t·d` within float32 round-off (bound derived in a comment);
  - world Ng is parallel to the expected normal: `|cross(Ng, n)| ≤ ε·|Ng|·|n|` with the same justified float32 bound (exact for axis-aligned instances with power-of-two scales).
- A ray that crosses the unit quad exactly on its shared diagonal (o = (0.25, 0.25, 1), d = (0, 0, −1), quad diagonal x = y) hits, with the instance index correct.
  o and d are in the object space of the instance they target; triangulate the quad so that its shared edge runs from
  (0, 0, 0) to (1, 1, 0), and give that instance an exactly representable transform (axis permutation, power-of-two scale,
  integer translation) so the world ray stays exactly on the edge.
- Miss case. The `tnear` exclusion: a ray starting on the surface with `tnear` = the reference `ray_epsilon` 1e-4 (smallpaint `eps`, smallpaint_painterly.cpp:39) does not re-hit.
