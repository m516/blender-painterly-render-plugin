# T3.1 — `tools/vendor_sync.py`: pinned, hash-checked vendoring of Cycles sources
Milestone: M3 · Depends on: M2 · Parallel-safe: no

## Goal
After this card:
- Vendored files under `third_party/cycles/` are reproducible from pinned upstream commits: Blender's `intern/cycles`, plus
  sse2neon (see "Upstream pins").
- Each file is verified by sha256. Changes are expressed only as patch files.
- `make vendor-check` proves the tree matches the manifest.

## Read first
- `CLAUDE.md` rules 1 and 5 and "Network notes"
- `docs/plan.md` "Architecture"

## Upstream pins
Two upstreams, each a table in VENDORED.toml and each pinned to one commit:
- `cycles`: https://github.com/blender/blender.git, tag `v5.2.2`, commit `d13f752e3b9c4f8c261cda552b1021f8bcc0382c`,
  root `intern/cycles`.
- `sse2neon` (MIT): https://github.com/DLTcollab/sse2neon.git, commit `227cc413fb2d50b2a10073087be96b59d5364aea`, root = the
  repository root. Blender v5.2.2 has no `extern/sse2neon`; it builds sse2neon as a precompiled library and pins this commit
  in `build_files/build_environment/cmake/versions.cmake:1028-1036`.

Path convention: every `upstream_path` (in VENDORED.toml, on the `add` command line, and in `closure` input and output) is
relative to its upstream's root. For `cycles`, `util/hash.h` means `intern/cycles/util/hash.h`. So `closure` output can be
passed to `add` unchanged.

## Create
- `tools/vendor_sync.py` (stdlib + git CLI), with subcommands:
  - `fetch`, one checkout per upstream:
    - `cycles`:
      1. `git clone --depth 1 --branch v5.2.2 --filter=blob:none --sparse https://github.com/blender/blender.git .cache/vendor/blender-v5.2.2`;
      2. `git sparse-checkout set intern/cycles`;
      3. verify that `git rev-parse HEAD` equals the pinned commit.
    - `sse2neon` (a bare commit, not a tag):
      1. `git init .cache/vendor/sse2neon-227cc413`;
      2. `git fetch --depth 1 https://github.com/DLTcollab/sse2neon.git 227cc413fb2d50b2a10073087be96b59d5364aea`, then
         `git checkout --detach FETCH_HEAD`;
      3. verify that `git rev-parse HEAD` equals the pinned commit.
    It is idempotent: a checkout already at its pinned commit is left alone.
  - `sync`: for every entry in `third_party/cycles/VENDORED.toml`, copy `<root>/<upstream_path>` from its upstream's checkout →
    `third_party/cycles/<dest>`, then apply `third_party/cycles/patches/*.patch` in lexical order with `git apply`.
  - `check`, in two steps:
    1. Without network: the sha256 of each vendored file equals the `sha256` in VENDORED.toml. That hash is of the *post-patch* file; record `upstream_sha256` too.
    2. With `--upstream` (needs fetch): re-derive every file from its upstream's checkout + patches and compare byte-for-byte.
  - `add [--upstream NAME] <upstream_path>... [--dest-prefix P]`: append entries to VENDORED.toml, then sync. `NAME` defaults
    to `cycles`; paths follow the path convention above.
    - `dest` is `upstream_path`, so a `cycles` file lands at its path without `intern/cycles/`.
    - With `--dest-prefix P`, `dest` is `P/<file name>`; e.g.
      `add --upstream sse2neon sse2neon.h LICENSE --dest-prefix sse2neon` vendors `third_party/cycles/sse2neon/sse2neon.h` and
      `third_party/cycles/sse2neon/LICENSE` (T3.2).
  - `remove <dest>...`: delete these entries from VENDORED.toml and their files under `third_party/cycles/`. T3.3 uses it when
    T3.2 vendored a header or source (`.cpp`) that T3.3 must shim.
  - `closure <seed headers...>`: print the transitive `#include "..."` closure inside the `cycles` root (`intern/cycles`), as
    root-relative paths. Missing headers are listed separately; they are shim candidates.
- `third_party/cycles/VENDORED.toml`:
  - `[upstream.cycles]` (`repo`, `tag`, `commit`, `root = "intern/cycles"`) and `[upstream.sse2neon]` (`repo`, `commit`,
    `root = ""`), with the values in "Upstream pins";
  - then `[[file]]` entries with `upstream` (`"cycles"` or `"sse2neon"`), `upstream_path`, `dest`, `upstream_sha256`, `sha256`,
    `patched` (bool). Start with the file list empty.
- `third_party/cycles/README.md`:
  - Licence and provenance: Apache-2.0 (Blender v5.2.2 `intern/cycles`) for the whole tree **except** `sse2neon/`, which is
    MIT (DLTcollab/sse2neon at `227cc413fb2d50b2a10073087be96b59d5364aea`; licence text in `sse2neon/LICENSE`).
  - "Never hand-edit. Change upstream pin or add a patch in patches/ and run `tools/vendor_sync.py sync`."
  - Patched files carry the comment `Modified by the Painterly project` inside the patch.
- `third_party/cycles/patches/.gitkeep`
- `tests/core/test_vendored.py`: runs `tools/vendor_sync.py check` (offline mode) and asserts exit code 0.
