## Questions to pre-register as hypotheses
Derive each from the cost model: a fixed 20 bounces per path, no Russian roulette, and brute-force ghost spheres.
- **H1.** Paths/second scales near-linearly with threads (1, 2, 4) for `chain=lane:16`, and `chain=image` is single-threaded.
  Report the speedups.
- **H2.** Cost per path is dominated by the bounce count, not by scene size.
  - Measure paths/s for the analytic reference scene and for the triangle reference scene.
  - Measure it again with a subdivided icosphere of 100k triangles added to the triangle scene (diffuse grey, inside the box, not occluding the light).
- **H3.** Projection: the time for 1920×1080 × 256 passes (lane:16, 4 threads) on this machine, from the measured paths/s. Report it in hours and minutes.

## Method
- Use `_painterly.Session` directly from `analyze.py`. No oracle cache is needed.
- Time each config 3× and report the median.
- Record CPU model (`lscpu`) and thread count.
