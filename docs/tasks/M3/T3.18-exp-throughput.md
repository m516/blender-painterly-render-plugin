## Questions to pre-register
Derive each from the cost model: a fixed 20 bounces per path, no Russian roulette, and brute-force ghost spheres.
H1 is the only hypothesis with a decision rule. H2 and H3 are pre-registered measurements, an explicit exception to protocol §2
and §7: the README states how each was derived and its observable, `## Results` reports the numbers, and `## Conclusion` gives
them without a supported/refuted verdict.
- **H1.** Paths/second grows with threads (1, 2, 4) for `chain=row` (the default); `chain=lane:16` is reported too, and
  `chain=image` is single-threaded.
  - Pre-registered rule: throughput at T threads is greater than at T/2 in all 3 repeats, for T = 2 and 4.
  - Report the speedups, with no threshold.
- **H2 (measurement, no decision rule).** How cost per path depends on scene size. The cost model expects the bounce count,
  not the scene size, to dominate; this is reported, not tested.
  - Measure paths/s for the analytic reference scene and for the triangle reference scene.
  - Measure it again with a subdivided icosphere at subdivision level 6 (20·4⁶ = 81,920 triangles, the level nearest the plan's 100k-triangle mesh) added to the triangle scene (diffuse grey, inside the box, not occluding the light). Report the exact triangle count.
  - All three use `chain=row` and 4 threads, as H3.
  - Report the three paths/s values and the ratios triangle / analytic and (triangle + 100k) / triangle, with no threshold.
- **H3 (projection, no decision rule).** The time for 1920×1080 × 1024 passes (the default `passes`; `chain=row`, 4 threads) on this machine, from the
  measured paths/s. Report it in hours and minutes.

## Method
- Protocol steps 3-4 do not apply: there is no `jobs.py` and no oracle render. `analyze.py` builds the scenes and times
  `_painterly.Session` directly. Wall-clock times vary from run to run, so §5's determinism covers the scene setup and the
  numbers derived from the recorded times, not the times themselves. Commit `README.md`, `analyze.py` and `results.json`
  (§9 without `jobs.py`).
- `analyze.py` runs as `.venv/bin/python experiments/NNN-…/analyze.py` after `make build`. Before `import _painterly`, it puts
  `$PAINTERLY_BUILD_DIR/src/blender` first on `sys.path` (default `build/dev`, resolved against the repository root as
  `tests/conftest.py` does). It loads `tests/core/scenes.py` by file path with `importlib.util.spec_from_file_location` to get
  `build_smallpaint_scene` and `build_smallpaint_scene_triangles`, because a script run puts neither directory on `sys.path`.
- Time each config 3× and report the median.
- Record CPU model (`lscpu`) and thread count.
