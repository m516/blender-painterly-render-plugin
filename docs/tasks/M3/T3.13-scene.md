  - `void device_update(KernelPainterlyIntegrator &kp) const` fills every kernel-consumed field. Floats become doubles with
    `double(float)`. `spiral_frame` in `KernelPainterlyIntegrator` is the 3×3 matrix F, which `PainterlyScene::device_update` computes (below),
    not this method.
  - `struct PainterlySocketUIInfo { const char *name; double min, max, soft_min, soft_max; const char *ui_name, *description, *group; };`
    and `const std::vector<PainterlySocketUIInfo> &painterly_integrator_ui_info();`.
    - One entry per socket, and a test asserts that the two name sets are equal.
    - Groups follow the table.
    - Ranges are UI limits, not behaviour.
- `camera.h/.cpp`: `class PainterlyCamera { PainterlyCameraType type; int width, height; PainterlyCameraFit fit; double raster_to_camera[16]; double camera_to_world[12]; void device_update(KernelPainterlyCamera &, double jitter) const; }`,
  with `enum class PainterlyCameraFit { HORIZONTAL, VERTICAL }`. The smallpaint camera has no fit; it uses image-plane units (below).
- `background.h/.cpp`: `class PainterlyBackground { double3 radiance; std::vector<KernelPainterlySun> suns; void device_update(KernelPainterlyBackground &, std::vector<KernelPainterlySun> &) const; }`. `add_sun` normalizes the direction and stores `cos(angle/2)`.
- `material.h`: `struct PainterlyMaterial { std::vector<KernelPainterlyLobe> lobes; double3 emission; }` (validation: ≥ 1 lobe, known kinds, non-negative weights, ior > 0 for glass).
- `analytic.h`: `struct PainterlyAnalyticPrimitive { PainterlyAnalyticType type; PainterlySphereIntersection intersection; int material; int object_id; double3 a; double b; KernelPainterlySpotProfile spot; }`.
- `mesh.h/.cpp`: `class PainterlyMesh { std::vector<float> vertices; std::vector<uint32_t> triangles; std::vector<int> tri_material; std::vector<float> corner_normals; }` with validation (index bounds, shapes) throwing `std::invalid_argument`.
- `object.h`: `struct PainterlyObject { int mesh; float object_to_world[12]; int object_id; }`.
- `scene.h/.cpp`:
  - `class PainterlyScene` owns vectors of materials, analytic primitives, meshes and objects, plus `PainterlyCamera`, `PainterlyBackground` and `PainterlyIntegrator integrator`.
  - It has `add_*`/`set_*` methods matching the `_painterly.pyi` Scene API, including `set_spiral_object`.
  - `object_id < 0` means auto: the running count of add_sphere/add_plane/add_object calls.
  - `clear()`.
- `device_scene.h/.cpp`:
  - `class PainterlyDeviceScene` owns `KernelPainterlyData` and the arrays referenced by `PainterlyGlobalsCPU`, plus `PainterlyEmbreeScene*` (freed in the destructor; non-copyable).
  - `PainterlyGlobalsCPU globals() const`.
  - `void PainterlyScene::device_update(PainterlyDeviceScene &ds) const`:
    - flatten material lobes into the `lobes` array (`lobe_offset`/`num_lobes`);
  - flatten meshes into the tri_* arrays (vertices expanded per triangle: 9 floats);
    - compute `itfm` with Cycles' `transform_inverse`;
    - compute the spiral frame F (SPEC §1) into `KernelPainterlyIntegrator::spiral_frame`. R(e) is the XYZ Euler rotation of
      `spiral_rotation` (Cycles' `euler_to_transform`); `M_s→cam` has columns (0,−1,0), (1,0,0), (0,0,1).
      - `smallpaint`: F = I.
      - `world`: F = R(e).
      - `camera`: F = R_cam→world · M_s→cam · R(e), where R_cam→world is the 3×3 part of the camera's `camera_to_world`.
      - `object`: F = R_obj · R(e), where R_obj is `PainterlyScene::spiral_object_rotation`, set by `set_spiral_object(rotation)`.
        The caller passes a rotation. The add-on uses Blender's own orthonormalization,
        `matrix_world.to_quaternion().to_matrix()` (M5), so the core never orthonormalizes. With no object set,
        `device_update` raises `std::invalid_argument`.
      - Test each case against a hand-computed matrix. For `camera` with an identity camera, F = M_s→cam.
    - fill `KernelPainterlyCamera.jitter` from the integrator's `jitter` j (SPEC §7) through `PainterlyCamera::device_update`:
      - smallpaint camera: image-plane units, `2.0 * double(j)`. This is exact, and `j = float32(1/1400)` gives
        `2·double(float32(1/1400))`, which the parity tests pass to the oracle;
      - perspective and orthographic: raster pixels, `double(j) * F` with `F = width` (HORIZONTAL) or `height` (VERTICAL).
      Test both, with hand-computed values;
    - build Embree only if there are triangles.
- `src/test/test_scene.cpp`: socket defaults, the set/get round trip, the UI-info name-set equality, object-id auto-assignment, `device_update` array sizes, and invalid-mesh rejection.
