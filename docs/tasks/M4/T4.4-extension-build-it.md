# T4.4 — Build, install and render the extension in real Blender 5.2.2 (integration test)
Milestone: M4 · Depends on: T4.3 · Parallel-safe: no

## Goal
`make blender-it` builds the extension zip (wheel included), installs it into an isolated Blender user directory, renders the
reference scene headless, and checks the image against the oracle **bit for bit**.

## Create
In this card, `<blender>` is the path that `tools/fetch_blender.py --version 5.2.2 --print-path-only` prints (offline; `make blender`
fetches the executable there). Blender is not on `PATH`.
- `tools/build_extension.py`:
  1. Run `make wheel`, or take `--wheel PATH`.
  2. Stage `src/blender/addon/` into `build/extension/painterly/`, plus `wheels/<wheel>`.
  3. Rewrite the staged `blender_manifest.toml` `wheels = ["./wheels/<file>"]` and `platforms = [<platform derived from the wheel tag>]`.
  4. Run `<blender> --command extension build --source-dir build/extension/painterly --output-dir dist/ --split-platforms`, with
     `<blender>` taken from `--blender PATH` (required; the Makefile passes `$(BLENDER)`).
  5. Print the zip path and write it, alone on one line, to `build/extension/zip_path.txt`.
- `tests/blender_it/run_reference.py`. It runs **inside** Blender (`<blender> -b --factory-startup --python-exit-code 1 --python … -- <out_dir>`):
  1. Call `addon_utils.enable("bl_ext.user_default.painterly", default_set=True)` and assert that `"PAINTERLY"` is the `bl_idname`
     of a registered `bpy.types.RenderEngine` subclass. `--factory-startup` does not load the user preferences in which
     `extension install-file -e` enabled the extension, so without this the engine is not registered.
  2. Set engine PAINTERLY, reference_scene, chain image, 64×64, passes 4, output scene_linear, exposure 1.
  3. Render and save an EXR (float32).
  4. Write the pixels (bottom-up float32) to `<out_dir>/blender.npy`, and the metadata to `<out_dir>/blender.json`, including
     `jitter = scene.painterly.jitter`, the value the render passed to the core (reference mode keeps the user's `jitter`, T4.3).
- `tests/blender_it/test_extension_it.py`. Mark it slow. Skip if no executable exists at the `<blender>` path or
  `build/extension/zip_path.txt` is missing (`make blender-it` creates both, so `make test-slow` alone skips). `<zip>` is the
  path that file names.
  It loads `tests/core/scenes.py` (`ORACLE_EXACT_KNOBS`) and `src/blender/addon/film.py` (`to_blender_rows`, `scene_linear`) by
  file path with `importlib.util.spec_from_file_location`, as `tests/core/test_film.py` does (T4.3).
  1. `BLENDER_USER_RESOURCES=<tmp>` for every Blender run below.
  2. `<blender> --command extension install-file -r user_default -e <zip>`.
  3. Run `run_reference.py`.
  4. Run the oracle with the same config, using the SPEC §2 parity rule (`--halton exact`), the T3.16 float32 knob values
     (`ORACLE_EXACT_KNOBS`, derived from `apply_reference_knobs()`; e.g. `--ray-epsilon`) and
     `--jitter repr(2 * float(np.float32(jitter)))`, the image-plane value the core derives (T3.13), with `jitter` read from
     `<out_dir>/blender.json`.
  5. Assert `blender.npy == to_blender_rows(scene_linear(oracle.sum, 4, 1))` exactly. This proves the extension, wheel, sync, film,
     orientation and core end to end.

## Modify
- `Makefile`: `extension: blender` → `.venv/bin/python tools/build_extension.py --blender $(BLENDER)`; `blender-it: extension build`
  → pytest on `tests/blender_it -m slow` (`build` provides the `build/dev/src/app/smallpaint_oracle` that step 4 runs).

## Acceptance
- `make blender-it` passes. Report the zip size and the render time.
- `"$(.venv/bin/python tools/fetch_blender.py --version 5.2.2 --print-path-only)" --command extension validate dist/*.zip` passes.
