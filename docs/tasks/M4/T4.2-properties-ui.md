## Create / fill
- `properties.py`:
  - `class PainterlyRenderSettings(bpy.types.PropertyGroup)`, attached as `bpy.types.Scene.painterly` in a `register()` classmethod.
  - Its annotations are **generated** from `_painterly.integrator_sockets()`, so no default is ever written twice. Every SPEC §8
    knob is a socket (T3.13), including those that only the add-on consumes (`passes`, `seed_per_frame`, `emission_scale`,
    `ghost_lights`, `output_mode`, `exposure`).
    - boolean → `BoolProperty`;
    - int/uint → `IntProperty` (min/max/soft from SocketInfo; uint min 0 and max 2**31−1, because Blender ints are int32: `seed`);
    - float → `FloatProperty`;
    - enum → `EnumProperty` with items `(id, id.replace("_", " ").title(), "")` in socket order;
    - vector → `FloatVectorProperty(size=3)`; `spiral_rotation` gets `subtype='EULER'` (a per-name subtype table, one entry).
    - `name = ui_name`, `description = description`. Store the socket group in a module dict `SOCKET_GROUPS` for the UI.
  - Blender-only properties, written by hand because they are not engine knobs, each with a one-line reason:
    - `batch` (int, default 1, min 1): passes per progress update; output is identical for any batch (SPEC §3);
    - `threads` (int, default 0 = automatic);
    - `spiral_object` (`PointerProperty(type=bpy.types.Object)`): the object of `spiral_frame = object` (SPEC §1);
    - `reference_scene` (bool, default False). Description: "Render smallpaint's built-in GUI scene instead of the Blender scene (reference check)".
  - A test asserts that no hand-written property name equals a socket name.
  - `data_version` (int, hidden) for version_update.
- `ui.py`:
  - A `PainterlyButtonsPanel` mixin (`bl_space_type="PROPERTIES"`, `bl_region_type="WINDOW"`, `bl_context="render"`, `COMPAT_ENGINES={"PAINTERLY"}`, `poll`).
  - Panels `RENDER_PT_painterly_sampling`, `_brush`, `_path`, `_lights`, `_film`. Each draws the generated socket properties of its group,
    in socket order, plus the hand-written properties that belong to it, with `use_property_split = True`.
  - `get_panels()` copied from Cycles with our own exclude set. The initial exclude set is empty except `RENDER_PT_simplify`;
    document why each name is excluded. Keep upstream's SPDX/copyright line in a comment above the copied function.
  - `register()` adds `"PAINTERLY"` to the `COMPAT_ENGINES` of those panels, and `unregister()` removes it.
- `presets.py`: `AddPresetBase` operator `PAINTERLY_OT_render_preset_add` and preset menu `PAINTERLY_PT_render_presets`.
  - Preset subdirectory `painterly/render`.
  - Ship `presets/painterly/render/smallpaint_reference.py`. It sets chain image and reference_scene True, and calls
    `property_unset("output_mode")` and `property_unset("passes")` (defaults generated from `integrator_sockets()`).
    The reference builder itself pins the smallpaint-unit knobs (gains, epsilon, frame); see T4.3.
  - The preset touches no lights: the built-in reference scene carries smallpaint's own emission (SPEC §6).
  - Register the preset path with `bpy.utils.register_preset_path(os.path.dirname(__file__))`.
- `operators.py`: `PAINTERLY_OT_apply_display_settings` ("Use smallpaint display settings"). It sets `view_transform='Standard'`,
  `look='None'`, `exposure=0`, `gamma=1` and `scene.render.dither_intensity=0` (SPEC §8) and reports what changed. It is never invoked automatically.
- `version_update.py`: a `@persistent` handler on `bpy.app.handlers.version_update` that upgrades `scene.painterly.data_version` to
  `CURRENT_DATA_VERSION = 1`. No upgrades exist yet; leave a documented hook.
- `tests/blender/test_properties.py`:
  - every `integrator_sockets()` name exists on `scene.painterly` with the matching default;
  - enum identifiers match;
  - all panels register, and a draw smoke test calls `panel.draw` with a fake layout or `bpy.ops` context override, if feasible in background;
  - the preset file executes without error and sets `chain == "image"`.
