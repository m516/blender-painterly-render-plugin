# T5.4 — The smallpaint scene authored in Blender, and the parity of the full Blender path
Milestone: M5 · Depends on: T5.3 · Parallel-safe: no

## Goal
Build the GUI reference scene as a real `.blend`, from meshes, Blender lights and Principled materials, and show that the full sync path
renders the look the oracle produces under `--ghost lights`. In Blender only lights are ghosts. This is the "honest Blender" parity target.

## Create
- `tools/make_reference_scene.py`, run inside Blender by `make reference-blend`
  (`<blender> -b --factory-startup --python-exit-code 1 --python tools/make_reference_scene.py -- <build_dir> <out.blend>`).
  - `reference_camera_rotation() -> np.ndarray`, module level and `bpy`-free: the (3, 3) float64 Blender camera rotation derived
    below. The module imports `bpy` only inside `main()`, which runs under `if __name__ == "__main__":`.
  - `main()` puts `<build_dir>/src/blender` at the front of `sys.path` (as `tests/conftest.py` does), then registers the add-on from
    `src/blender/addon` as module `painterly` (as `tests/blender/conftest.py` does). `--factory-startup` loads no add-ons, and
    without this the PAINTERLY engine, `scene.painterly`, `PAINTERLY_OT_apply_display_settings` and `_painterly` are missing.
    It creates the parent directory of `<out.blend>`, builds the scene below and saves it.
  - Camera at the origin looking along −Z with a 90° FOV (18 mm lens, 36 mm sensor, sensor fit AUTO) at 400×400.
    Its rotation is `reference_camera_rotation()` = `M_s→camᵀ` (SPEC §1; the rotation the core gives the smallpaint camera, T3.13),
    a +90° rotation about Z: camera +X (right) → +ŷ_s, camera +Y (up) → −x̂_s, camera −Z → −ẑ_s.
  - The 6 planes as large quads (`plane_extent` 50) with smallpaint `cl/10` as Principled Base Color (values >1 allowed, set via Python).
    Roughness 0 and specular irrelevant, because constant mapping ignores them.
  - Mirror and glass spheres as UV spheres (smooth, 64×32 segments, a knob) with Base Color (1, 1, 1), and Metallic 1 (mirror) or
    Transmission 1 with IOR 1.5 (glass). smallpaint ignores `cl` for types 2 and 3, and a unit tint is exact (SPEC §6, T3.16).
  - The blue diffuse sphere, Base Color `cl/10` = (0.4, 0.4, 1.2).
  - The light: a point light, radius 0.5, energy 120, colour white.
  - Scene settings: engine PAINTERLY and the display settings of `PAINTERLY_OT_apply_display_settings` (T4.2). `emission_scale`,
    `diffuse_gain` (1, because colours are cl/10) and the spiral frame mode stay at their socket defaults; at generation time, assert
    that `integrator_sockets()` gives 1.0, 1.0 and `"camera"`.
  - Blender world coordinates are smallpaint coordinates: every SPEC §9 centre, radius, plane normal and offset is used unchanged.
    Then `R_cam→world · M_s→cam = I`, so `spiral_frame = camera` gives F = I, as in the oracle.
- `tests/core/test_reference_scene_math.py` (no `bpy`; runs under `make test`). It loads `tools/make_reference_scene.py` by file path
  with `importlib.util.spec_from_file_location` and asserts that `reference_camera_rotation()` equals `M_s→camᵀ` exactly (entries 0/±1)
  and that `reference_camera_rotation() @ M_s→cam` is the identity.
- `tests/blender_it/run_reference_blend.py`, run inside Blender by `test_reference_blend.py`
  (`<blender> -b --factory-startup --python-exit-code 1 --python tests/blender_it/run_reference_blend.py -- <blend> <out_dir> …`,
  with `<blender>` and `BLENDER_USER_RESOURCES` as in T4.4):
  - It calls `addon_utils.enable("bl_ext.user_default.painterly", default_set=True)` and asserts that `"PAINTERLY"` is the
    `bl_idname` of a registered `bpy.types.RenderEngine` subclass: `--factory-startup` does not load the user preferences in which
    `extension install-file -e` enabled the extension (T4.4). Then it opens `<blend>` with `bpy.ops.wm.open_mainfile`.
  - Render mode: sets `scene.painterly.output_mode = "scene_linear"` and `scene.painterly.exposure = 1.0`, renders with the
    given chain, passes and `seed`, and writes the pixels (bottom-up float32, (H, W, 4)) and metadata to `<out_dir>`, as T4.4's
    `run_reference.py` does.
  - Object-id mode: runs the primary-hit check, step 1 below, with `sync` and `SyncStats` from the installed package
    (`bl_ext.user_default.painterly.sync`, `.sync.geometry`). It writes `object_id.npy` and `stats.object_ids` (as JSON; the
    reference scene has no instanced duplicates, so every key is an object name) to `<out_dir>`.
- `tests/data/scenes/README.md`. The scene is generated and not committed: `make reference-blend` writes `build/scenes/smallpaint_reference.blend`.
- `tests/blender_it/test_reference_blend.py` (slow):
  - Install the extension zip named by `build/extension/zip_path.txt` as T4.4 does, skipping under the same conditions, then
    render the generated `.blend` at 400×400, chain image, P = 32, 8 pairs (seeds via `seed`) through the installed
    extension, with `run_reference_blend.py`.
  - Compare with the oracle `--ghost lights` ensemble (same P, 8 pairs) using `compare_ensembles` on
    `metrics.realization_free_key_family(metrics.diffuse_key_family(keys))`. Use the oracle's object_id for masks: the Blender
    render's object-id pass is not exported yet, so the camera/object agreement test below checks it.
  - Convert each Blender render to a SPEC §7 sum before `metrics.measure`:
    `sum = np.flipud(pixels)[..., :3].astype(np.float64) * 255 * passes`, the inverse of
    `film.to_blender_rows(film.scene_linear(sum, passes, 1))` (T4.3). The only difference from the core's sums is the float32
    round-off of the pixels.
  - Why realization-free: experiment 002 shows that `pattern_corr` and `block_rmse` measure agreement with one specific
    *realization* of the texture. They collapse whenever K consumption differs from the oracle's (ghost_lights: 0.005, with
    K 19.21 vs 16.27 draws per pixel per pass), even when the texture amplitude is kept (structure 5.38 vs 5.74). A Blender
    scene with mesh spheres cannot reproduce the oracle's K consumption exactly, so those two keys are reported with
    effect summaries but never decide.
  - **Expected:** indistinguishable on the plane regions (`r3`-`r7`; SPEC §9, the front plane `r8` is behind the camera):
    their means and their `structure_std`. The diffuse sphere region `r2` may differ, because a UV sphere is not an
    analytic sphere. Record and report every per-key
    p-value and effect summary. Hard-assert only the `r3`-`r7` keys of the realization-free family.
  - Separately check primary-hit agreement:
    1. Inside Blender (`run_reference_blend.py`, object-id mode), on the `.blend`: `stats = SyncStats()`, then
       `core = sync.build_scene(depsgraph, scene.painterly, 64, 64, stats=stats)` (T5.2's out-parameter), and read
       `Session.object_id()` of `core` at size 64.
    2. Map Blender objects to SPEC §9 ids by object name; the generator names them `sp_00_middle_sphere` … `sp_09_light`, and
       `stats.object_ids` (T5.2, T5.3) gives each name's core object_id.
    3. Compare with the oracle's `object_id.npy` at size 64.
    4. Assert **exact equality** on *interior plane pixels*: pixels whose oracle id is a plane and whose 3×3 oracle neighbourhood has that
       same id. UV-sphere silhouettes legitimately differ from analytic spheres, so report the count of differing sphere-edge pixels as a number.

## Modify
- `Makefile`:
  - `reference-blend: blender build` → `$(BLENDER) -b --factory-startup --python-exit-code 1 --python tools/make_reference_scene.py -- $(BUILD_DIR) build/scenes/smallpaint_reference.blend`.
    `--python-exit-code 1` makes a raising script (including the generation-time socket assertion) fail the target, as in
    T2.3, T2.4 and T4.4.
  - T4.4's `blender-it: extension build` becomes `blender-it: extension build reference-blend`, so a fresh checkout has the `.blend`.
