## Create `src/blender/addon/sync/camera.py` (needs `bpy`; keep the pure-numpy math in `sync/camera_math.py`)
- `raster_to_camera(projection: np.ndarray(4,4), width, height) -> np.ndarray(4,4)`, pure:
  - Raster `(x, y)` with y down from the top row (SPEC §0) → NDC `(2x/w − 1, 1 − 2y/h, −1, 1)` → camera space through `inverse(projection)`.
  - Return the composed 4×4 matrix.
- `camera_fit(sensor_fit: str, width: int, height: int, pixel_aspect_x: float, pixel_aspect_y: float) -> str`, pure: `'AUTO'` →
  `'horizontal'` if `width * pixel_aspect_x >= height * pixel_aspect_y` else `'vertical'`; `'HORIZONTAL'` → `'horizontal'`;
  `'VERTICAL'` → `'vertical'`. This is the rule `calc_matrix_camera` applies (Blender v5.2.2
  `source/blender/blenkernel/intern/camera.cc:334-337, 483`), so F is the side that P fits.
- `sync_camera(scene_core, depsgraph, settings, width, height) -> None`:
  - `cam_obj = depsgraph.scene.camera` (evaluated).
  - `P = np.array(cam_obj.calc_matrix_camera(depsgraph, x=width, y=height, scale_x=render.pixel_aspect_x, scale_y=render.pixel_aspect_y), dtype=np.float64)`.
  - `camera_to_world = np.array(cam_obj.matrix_world.normalized(), dtype=np.float64)`, a C-contiguous (4, 4) array using
    translation and rotation only. `set_camera_*` accepts only float64 ndarrays (`_painterly.pyi`, T3.15).
  - Perspective → `set_camera_perspective(width, height, raster_to_camera(P, width, height), camera_to_world, fit=camera_fit(cam.data.sensor_fit, width, height, render.pixel_aspect_x, render.pixel_aspect_y))`,
    passing the float64 `raster_to_camera(P, width, height)` and that `camera_to_world`. Orthographic → `set_camera_orthographic` likewise.
    Panoramic → raise `NotImplementedError` with a clear message.
  - The core converts the integrator's `jitter` (a fraction of the fitted side, SPEC §7) itself. The add-on passes no jitter.
- The core computes the spiral frame F from the integrator sockets `spiral_frame`/`spiral_rotation` and the camera (T3.13).
  When `spiral_frame == "object"`, `sync_camera` calls `scene_core.set_spiral_object(rotation)` with
  `settings.spiral_object.matrix_world.to_quaternion().to_matrix()` as a (3, 3) float64 array. With no object, it raises
  a clear error before rendering.
- `tests/core/test_camera_math.py` (pure numpy, no `bpy`). It loads `sync/camera_math.py` by file path with
  `importlib.util.spec_from_file_location`, as T4.3's `tests/core/test_film.py` loads `film.py`: importing it through the package
  would run `addon/__init__.py` and `sync/__init__.py`, which import `bpy`. `camera_math.py` has no package-relative imports.
  - For a 90° FOV 400×400 perspective matrix built analytically, the centre raster point maps to direction (0,0,−1).
  - The corners map to (±1, ±1, −1) up to scale.
  - Shift moves the principal point by the expected number of pixels.
  - Tolerance: float64 round-off, justified.
- `tests/blender/test_sync_camera.py` (bpy):
  - For a scene camera with lens 18 mm on a 36 mm sensor, shift_x 0.1 and render 320×240, capture the `raster_to_camera` passed to
    `set_camera_perspective` with a recording fake `scene_core`. Evaluate T3.8's perspective steps 1–2 (`p = raster_to_camera · point`,
    `Pc = p.xyz / p.w`) at the four raster corners (0, 0), (w, 0), (0, h) and (w, h): the outer frame corners, so without T3.8's
    +0.5 pixel-centre offset, and unjittered. Each `Pc`, scaled to z = −1, equals the matching corner of
    `cam.data.view_frame(scene=scene)` scaled to z = −1, within float32 round-off of `view_frame`. Derive the bound in a comment.
    `view_frame` is in camera space, before the object transform, so the comparison is in camera space. Corners match by position:
    raster y runs down from the top row (SPEC §0), so raster (0, 0) matches the `view_frame` corner with minimum x and maximum y,
    and likewise for the other three.
  - Also: `camera_fit` for each sensor-fit mode. For a scaled, rotated object, the recording fake's `set_spiral_object`
    receives exactly `np.array(obj.matrix_world.to_quaternion().to_matrix(), dtype=np.float64)` (`np.array_equal`). That
    matrix satisfies `R @ R.T == I` within float32 round-off, because mathutils computes in float32; derive the bound in a
    comment.
